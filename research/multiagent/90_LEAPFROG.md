- **The field has consolidated hard in 2026.** Windsurf is now **Devin Desktop** (Cognition owns both brands — ✓TODAY windsurf.com/cascade FAQ); Google is folding Gemini CLI into Antigravity (community-reported, codemyspec.com ✓TODAY); OpenHands repositioned from autonomous agent to **Agent Canvas** — a control center that runs *other* agents via ACP (✓TODAY README). - **RapidTool sits in none of those boxes — that is the opening.** Every competitor sells one of two things: raw *autonomy* (Codex `approval_policy: never`, Antigravity "Always Proceed", Devin fleets) or raw *speed* (Cursor tab, Bolt instant preview). Nobody sells **governed production**: evidence-hashed gates that cannot be skipped, machine-typed honesty envelopes, append-only decision ledgers, deterministic keyless floors, bounded autonomy with hard caps. RapidTool already has all five, verified on disk this pass (§1.3). The leapfrog is not "add streaming chat" (parity) — it is to **productize the governance core** (10× on the five axes in §4) while closing the parity gaps that currently make the product feel broken (§3).
- **Biggest single structural wins available:** (1) executable verification lattice — machine checks that block advancement (G-10/G-28/G-29/G-30), (2) replay-deterministic trace + snapshots — a run that can be replayed to the same verdict (G-40/G-26/G-22), (3) the self-learning loop closed — critique → memory write-back → FusionRank → next packet (G-25/G-39), (4) plan-first Wild Mode + checkpoints so autonomy is safe to recommend (S3/S6), (5) MCP **through the phase machine** — a governed tool surface that literally no competitor has (S7).
- **Honest floor (§6):** RapidTool will keep losing at in-repo editing ergonomics, IDE depth, cloud-scale parallel fleets, visual design polish, and frontier-model raw IQ — forever, by design. Don't fight those. The winnable war is **"verifiable, auditable, budgeted software production"**, and the compounding weapon is the self-learning store (§5).

## 1. The field — full competitor sweep (loops, differentiators, what each beats RapidTool at)

> Format per competitor: **Loop** (prompt → software), **Differentiator** (what users pay for), **Beats RapidTool at** (with code/UI-level examples), **Source**. RapidTool's baseline is §1.3 of 42 (verified again this pass, anchors in §2 of this file).

### 1.1 OpenAI Codex (CLI + IDE + app)

- **Loop:** plan → implement → validate → repair, inside one live turn; human can steer mid-flight. Plan mode (`/plan` or `Shift+Tab`) is read-only research + clarifying questions → a proposed plan the human approves *before* implementation [C1][C4]; `/review` runs a read-only PR-style review vs base branch, uncommitted changes, or a commit [C1][C4].
- **Differentiator:** the deepest **approval + sandbox engine** in the CLI class. `approval_policy = untrusted | on-request | never | granular` with per-category auto-reject; `approvals_reviewer = auto_review` replaces the human with a reviewer subagent for eligible prompts; OS-enforced sandbox modes `read-only | workspace-write | danger-full-access`; network off by default with `network_proxy` allowlist-first domain rules, deny-wins, DNS-rebinding checks, local-binding blocks; destructive app/MCP tool calls always require approval when the tool advertises the annotation [C2][C5].
- **Beats RapidTool at:** live TUI steering — `Tab` queues a follow-up while Codex works, `Enter` injects mid-turn instructions, `Esc`×2 edits the previous user message and forks the chat from that point, `@` files into the prompt, `Ctrl+O` copies latest output, and a live **context meter** ("100% context left") in the header [C1][C3]; token streaming confirmed at the transport layer (`codex.sse_event` telemetry with token counts on `response.completed`) [C2]; session persistence (`resume / fork / archive`) [C1]; `AGENTS.md` hierarchy (global → repo → subdir, closer wins) [C4]; machine-scriptable `codex exec --json` emitting NDJSON per state change [C1]. RapidTool has **none** of these (no streaming `deepseek.server.ts:233`, no session persistence `console.tsx:4361`, no plan approval step, no permission language, no steering).
- **Sources:** README fetched ✓TODAY (github.com/openai/codex — installers, `npm i -g @openai/codex`, IDE installs, `codex app`, Codex Web); mechanics per 42's register [C1–C5] (learn.chatgpt.com docs, fetched 2026-09-06 by that pass).

### 1.2 Claude Code (Anthropic) — terminal / IDE / desktop / web

- **Loop:** explore → plan → code → **verify against a check it can run**. Plan mode entered with `Shift+Tab` or `claude --permission-mode plan`; the recommended workflow is explicit four-phase (explore/plan/code/verify) [✓TODAY best-practices]. The verification loop is the product: "Give Claude a check it can run: tests, a build, a screenshot to compare. It's the difference between a session you watch and one you walk away from."
- **Differentiator:** **verification mechanics** at four intensities — (a) in-prompt check, (b) `/goal` with a **separate evaluator** that re-checks after every turn until the goal resolves (run stalls and stops if it can't), (c) **Stop hooks**: deterministic script gates that block the turn from ending until they pass — Claude Code overrides after 8 consecutive blocks, (d) a **verification subagent** — "a fresh model tries to refute the result, so the agent doing the work isn't the one grading it" [✓TODAY best-practices]. Plus `CLAUDE.md` persistent memory, subagents, workflows/dynamic orchestration, hooks, MCP, `claude --cloud` for handoff to web/mobile, Routines, GitHub Actions.
- **Beats RapidTool at:** this is the **only competitor whose core pitch overlaps RapidTool's verification philosophy** — but Claude's "checks" are convention (prompts/hooks the user must write), while RapidTool's DoD gates are *built-in deterministic law* with evidence hashes (`dod.ts:4-9`). Claude still beats RapidTool on: streaming, surfaces (5), cloud handoff, ecosystem (agent SDK, workflows), and model quality. RapidTool's answer is not to copy hooks — it is to make the built-in gates *visibly* stronger than any hook (G-10 executable oracle + G-28 properties + G-29 metrics + G-30 arch rules).
- **Sources:** ✓TODAY code.claude.com/docs/en/overview + /best-practices.

## 4. THE LEAPFROG — five axis wins where RapidTool beats EVERY competitor, made 10×

> Principle (from 14 §1.2): RapidTool must never copy competitors on their axis (autonomy, visual polish, frontier IQ). It must push its own axes until they are the category. Each axis: **the win** (verified evidence), **why nobody can copy it fast**, **10× plan** (module-level).

### Axis 1 — Governed honesty as a *protocol*, not a policy

- **The win today:** machine-typed honesty envelopes (`chat.server.ts:277` `not-configured`; `wild-mode.server.ts:34,74` verdict contract); evidence-hashed DoD gates (`dod.ts:4-9`, FNV-1a); append-only decision ledger (`engine.ts:2033`); a classifier that **refuses** to fabricate a judgment (`wild-mode.server.ts:121`); autopilot barred from `forceHuman` gates (`engine.ts:2166`). 42 §3.2 verified none of Codex/DSH/Gemini/Antigravity has an equivalent: Codex's `auto_review` substitutes model judgment without evidence; Antigravity's "Always Proceed" is unbounded by design; Copilot's transparency is prose commits [✓TODAY].

RapidTool's is *law* — gates are engine code, errors are typed enums, the ledger can't be edited. A competitor would have to rewrite their runtime, not ship a settings page. And the Kiro anecdote (§1.15, community-flagged) is exactly the incident class governed gates prevent.
- **10× plan (modules):**
  1. **Executable oracle closes the loop** — thread `runCases` (`verify.server.ts:359`) evidence into the `p6-test` gate (`dod.ts:126`); a failing machine run opens HITL with hashed evidence (G-10 + M-09 closure). *Acceptance: a generated module cannot reach "complete" without machine-run evidence.*

## 5. The self-learning loop as the compounding advantage

> **Status (updated by the §9 pass):** `89_self_learning_research.md` **has landed** (2026-09-06, 26 cited sources). Its §0 anchor map and §6 design menu now supersede this section's from-scratch derivation; the loop diagram below remains accurate and **§9** rewires it with 89's anchors and re-verified line numbers.

**The loop (all pieces exist on disk except the two write-back edges in bold):**

```
run N (bounded, headless.ts:441)
  └─ trace.ts spans (G-40, NEW)                     ← append-only evidence of what happened
  └─ machine checks (verify.server.ts:359, dod.ts)  ← gates with hashes
  └─ critique on failure (G-25, NEW)                ← symptom/hypothesis/fix artifact
  └─ **[write-back] report-intake.ts applyReport → MemoryEntry (G-39, NEW)**
  └─ **[write-back] knowledge.ts savePattern → cross-project KnowledgeStore (NEW wiring)**
run N+1
  └─ FusionRank ranks memory into packet (algorithms.ts:221, packet.ts:292)
  └─ injectProven (knowledge.ts:265) injects domain patterns into research corpus
  └─ harvest.ts supplies real, provenance-stamped sources (never fabricated)
  └─ bench.ts predicts cost/risk before the run starts
eval harness (G-40) measures: gate-rejection rate ↓ over runs (14 §7)
```

**Why it compounds where competitors don't:** (1) the lessons are *structured + hashed*, not prose trajectories (Devin's "session trajectories" ✓TODAY are opaque); (2) ranking is *deterministic* (FusionRank / idf-lexical with honest labels — `knowledge.ts:16` admits it is not embeddings), so the loop is auditable end-to-end; (3) every layer keeps the keyless floor — an unconfigured backend produces template critiques and keyword harvests, never fabricated ones (`harvest.ts` header, `knowledge.ts:4` advisory-only). The compounding claim is *falsifiable* by design (14 §7): if run 6+ doesn't show fewer gate rejections, the loop is decorative and should be ripped out — write that into the eval harness.

**Ordering:** the write-back edges (G-25, G-39) are M-effort each and rank #4 in 13's value÷effort rollup; they must ship in P0/P1 (see §6), because every later axis (plan quality G-24, orchestration G-21/23) is *consumed through* memory — a manager that can't remember last run's lessons is just a more expensive crew.

## 7. What RapidTool will still lose at — honest, no overclaiming

1. **In-repo editing ergonomics.** Cursor's tab-complete + codebase index + instant multi-file edits inside a real IDE; Claude Code/Cline's surgical diff loops in *existing* repos. RapidTool generates governed artifacts; it does not (and per 14 §1.2.3 deliberately should not) become an editor. Do not roadmap an IDE plugin as a core bet.

4. **Frontier-model raw IQ.** One DeepSeek key vs frontier tiers at Codex/Claude/Gemini. Aggregation adds loops, not intelligence (14 §1.2.2). The honesty lint and tier labels (08 E-14) must keep this visible.
5. **Open-source harness gravity.** DSH has 214k stars, MIT, plugin ecosystem, and a community shipping its MCP/tooling surface daily (✓TODAY repo page). RapidTool cannot out-community an open platform; it should *interoperate* (ACP/MCP, P2-3/P2-4) rather than compete for the same contributors.
6. **Distribution.** Bolt/Lovable/v0 own consumer funnels; GitHub owns the issue→PR surface; Devin owns Slack/Linear. RapidTool's headless CLI + packet is the *developer-facing* wedge; it will convert fewer tire-kickers and must win on audits/trust stories instead.
7. **Stop/steer richness mid-run.** Even after P0-1, RapidTool's chat will lack Codex/Cursor-class queue/inject/fork affordances (Esc×2-style forking is a P2+ nicety). Accept partial parity; the differentiator is the ledger around the turn, not the turn.
8. **What we will *not* lose** — and should say loudly: governed honesty (Axis 1), deterministic replayable builds (Axis 2), bounded safe autonomy (Axis 3), the audit trail as product (Axis 4), and per-run compounding memory (Axis 5). Those five, made 10×, are a category nobody else currently occupies: **the governed, evidence-grade, self-improving software-production harness.**

### 9.1 The five learning loops, dissected

Convention: each loop is read as **Capture → Retrieve → Apply → Evict/correct**. "Lessons" below means *experience the agent can reuse in a later run/session* — not weights, not fine-tuning.

**9.1.1 OpenAI Codex (CLI/IDE) — three carriers: instruction chain, local memories, exec rules**
- **Capture.** (a) **AGENTS.md instruction chain** — human-written; Codex "reads AGENTS.md files before doing any work", building the chain once per run. Discovery: global scope first (`~/.codex/AGENTS.override.md` else `~/.codex/AGENTS.md`, only the first non-empty file), then project scope walking **root → cwd**, at most one file per directory (`AGENTS.override.md` → `AGENTS.md` → fallback names); files merge root-down, "files closer to your current directory override earlier guidance because they appear later"; empty files skipped; combined size cap `project_doc_max_bytes` = **32 KiB default** [✓TODAY agents-md]. (b) **Local memories** — auto, LLM-written, **off by default** (`[features] memories = true`); eligible prior chats become files under `~/.codex/memories/` containing "summaries, durable entries, recent inputs, and supporting evidence"; Codex "skips active or short-lived sessions, redacts secrets from generated memory fields, and updates memories in the background" — it "waits until a chat has been idle long enough to avoid summarizing work that's still in progress"; skips when rate-limit remaining < `memories.min_rate_limit_remaining_percent`; separate `memories.extract_model` (per-chat) and `memories.consolidation_model` (global rewrite) knobs; per-chat `/memories` opt-out [✓TODAY memories]. (c) **Exec rules auto-written from approval events** — Starlark `prefix_rule(pattern, decision=allow|prompt|forbidden, justification, match/not_match inline unit tests)`; "when you add a command to the allow list in the TUI, Codex writes to the user layer at `~/.codex/rules/default.rules` so future runs can skip the prompt"; with Smart approvals "Codex may propose a `prefix_rule` for you during escalation requests" — approve once ⇒ permanent guardrail [✓TODAY rules].
- **Retrieve.** Instruction chain assembled **once per run** at startup (no mid-run refresh); memories are injected into future sessions subject to `memories.use_memories` + per-chat `/memories` control; rules are scanned at startup under "every active config layer" (project-local `<repo>/.codex/rules/` only when the project `.codex/` layer is trusted) [✓TODAY agents-md, memories, rules].
- **Apply.** AGENTS.md content lands as prompt context before any work; memories add a recall layer; rules are enforced **at exec time by the runtime, not by the model** — argv compared as an argument list (execvp-style), compound `bash -lc` strings tree-sitter-split into individual commands when they are a safe linear chain, each evaluated separately, "the most restrictive result wins" (`forbidden` > `prompt` > `allow`) [✓TODAY rules].
- **Evict / correct.** Hard byte caps stop instruction growth (32 KiB); memories are declared "generated state… don't rely on editing them by hand" with a separate consolidation-model pass as the only global rewrite; vendor caution: "Keep required team guidance in AGENTS.md… Treat memories as a helpful recall layer, not as the only source for rules that must always apply" [✓TODAY agents-md, memories]. Rule corrections are human edits to `.rules` files, validated at load by `match`/`not_match` examples; `codex execpolicy check` tests a rule before it ships [✓TODAY rules].
- **Weaknesses.** Memories are **LLM-summarized prose without structured outcome rows or evidence links** — nothing records "phase X failed because Y, fix Z" as typed data; the summarizer itself is unmeasured. AGENTS.md captures only what humans write, so verify-failures never auto-learn into it. Rules govern **shell commands only** — nothing equivalent exists for product quality (a generated module can still be wrong while every command is allowed). No machine evaluation of whether a retrieved memory helped (no counter-evidence decay). Memory/instructions apply per session but Codex has no per-*project-phase* memory tiers.

**9.1.2 Claude Code (Anthropic) — CLAUDE.md scopes + auto memory + recorded recipes**
- **Capture.** (a) **CLAUDE.md** — human-written, four scopes in load order broadest→specific: managed policy (`/Library/Application Support/ClaudeCode/CLAUDE.md` etc.), user (`~/.claude/CLAUDE.md`), project (`./CLAUDE.md` or `./.claude/CLAUDE.md`, team-shared via source control), local (`./CLAUDE.local.md`, gitignored); path/file-type scoping via `.claude/rules/`; `@path` imports (max 4 hops); "Add to CLAUDE.md when: Claude makes the same mistake a second time; a code review catches something Claude should have known; you type the same correction you typed last session" [✓TODAY memory]. (b) **Auto memory** — "notes Claude writes itself based on your corrections and preferences", "learnings and patterns", per-repository scope **shared across worktrees**, loaded "first 200 lines or 25KB" every session; subagents can maintain their own [✓TODAY memory]. (c) **Recorded recipes = experience→skill automation** — `/run-skill-generator` "gets your app running from a clean environment, captures what worked (the install commands, the env vars, the launch script), and commits it as a per-project skill at `.claude/skills/run-<name>/`"; `/verify`, after successfully building and driving the app without a recorded recipe, "writes what worked to `.claude/skills/verify/SKILL.md`… so later runs and other agents follow the same steps"; **anti-churn rule: "Claude edits the recorded file only when it steered a run wrong"** — earlier behavior that folded in anything a run learned "caused frequent merge conflicts" [✓TODAY skills].
- **Retrieve.** CLAUDE.md + auto memory load **at the start of every conversation**; subdirectory CLAUDE.md/rules files "load on demand when Claude reads files in those directories"; project-root CLAUDE.md **survives `/compact`** (re-read from disk); skills keep a listing of name+description in context (budget = 1% of context window; least-used descriptions dropped first when overflowing) and **a skill's body loads only when it's used** — progressive disclosure [✓TODAY memory, skills].
- **Apply.** Both memory carriers are "loaded at the start of every conversation. Claude treats them as context, **not enforced configuration**" — behavioral enforcement is delegated to hooks ("To block an action regardless of what Claude decides, use a PreToolUse hook") [✓TODAY memory]. Recorded recipes replace rediscovery: after `/verify` records one, future runs "follow the recorded recipe" [✓TODAY skills].
- **Evict / correct.** `/doctor` "proposes trims for a checked-in CLAUDE.md: cuts content Claude can derive from the codebase… keeps pitfalls, rationale, and conventions"; >200-line files discouraged, >4 MiB skipped; auto memory capped (200 lines/25KB); conflicts resolved by user review of files; recorded-skill churn prevented by the edit-only-when-steered-wrong rule; `/memory` lets the user browse/edit/delete auto memory [✓TODAY memory, skills].
- **Weaknesses.** Everything is **prose context with no structured rows, no deterministic ranking, no evidence hashes** — retrieval is model-decided or load-everything-until-cap. Auto memory is correction-triggered, not verify-failure-triggered, so failed test runs don't themselves teach it. "Context, not enforced configuration" is an honest admission that adherence is probabilistic — RapidTool's gates are engine law instead (90 §1.2). Recipes capture *launch/build* procedures, not product-conformance lessons (a recipe for a wrong-product scaffold would still record cleanly).

**9.1.3 Devin / Cognition (cloud engineer; Knowledge + Playbooks)**
- **Capture.** Two artifacts + one auto-suggestion pipeline. **Knowledge** = "a collection of tips, advice, and instructions that Devin can reference in all sessions"; item = **Trigger Description (required** — "Devin will retrieve a Knowledge item when its current work is related to the specified triggers") + Content ("a handful of sentences"); examples: "common bugs and their associated solutions, code conformance practices, deployment workflows" [✓TODAY knowledge]. **Playbooks** = ".devin.md" reusable prompts with a fixed anatomy: Outcome / Procedure ("one step per line… imperative… setup, task, delivery… MECE") / Specifications (postconditions) / Advice ("tips to correct Devin's priors") / **Forbidden Actions** / Required from User; version history; iterate by "run 2+ Devins in parallel with the same playbook to quickly identify possible errors", then chat-fix and fold the fix into the playbook [✓TODAY playbooks]. **Knowledge Suggestions** (auto capture): "Devin will automatically suggest Knowledge to remember based on your feedback in chat. Edit the suggested Knowledge before saving, or dismiss"; it "can also suggest updates to existing knowledge items"; auto-organization into folders; org→enterprise "Promote to Enterprise" [✓TODAY knowledge]. Homepage claim: "Devin gets better over time by reading past session trajectories" (fetched 2026-09-06 by 90's own pass, §1.4).
- **Retrieve.** Trigger-description matching at work time — "Devin retrieves Knowledge when relevant, **not all at once or all at the beginning**"; **pinning**: no repo (recall when relevant) / a specific repo ("always used" when working there) / all repos (always); **macros** (`!deploy-checklist`) force-reference an item in a prompt; playbook macros attach a whole playbook by name. Per-item/per-folder enable/disable [✓TODAY knowledge, playbooks].
- **Apply.** Knowledge is read "in all sessions" as tips/advice (vendor warns "Devin will read the entire Knowledge contents, so keep it all relevant"); playbooks act as "a custom system prompt for a repeated task" with **Forbidden Actions** as hard negative constraints [✓TODAY knowledge, playbooks].
- **Evict / correct.** Enable/disable (never delete — org-shared) and folder toggles; suggestions are **HITL-gated before save** (edit/dismiss/regenerate); playbook version history + revert; "keep items small… split items… make triggers highly relevant" guidance [✓TODAY knowledge, playbooks].
- **Weaknesses.** The recall backend is **opaque**: "Devin's internal recall/scoring backend (embeddings? keyword? model-decided?) is not documented" in fetched pages (89 §1.4 honest limit, same [S1] doc). Items are read **in full** — no scored top-k truncation, so size caps value (vendor guidance admits it). Trajectory learning is informal prose with no audit trail of what a lesson is, when it was learned, or which evidence backs it. Knowledge is **org memory with human curation burden** — the machine proposes, a person must maintain. No counter-evidence/supersede mechanism documented (a wrong knowledge item stays until a human disables it).

**9.1.4 Cursor (IDE + Cloud Agents) — rules (.mdc) + skills, frontmatter-gated activation**
- **Capture.** (a) **Rules** — `.cursor/rules/*.mdc` version-controlled files with frontmatter `description`/`globs`/`alwaysApply`; four types: Project/User/Team/AGENTS.md (plain markdown, nested AGENTS.md auto-apply to their subtree, "more specific instructions taking precedence"); agent-authored rules supported ("Can I create a rule from chat? Yes"); remote rules importable from any GitHub repo; built-in `/create-rule` [✓TODAY rules]. (b) **Skills** — Agent Skills open standard folders; `SKILL.md` frontmatter `name` + `description` (required) + `paths` globs + `disable-model-invocation`; built-in `/create-skill`; compatibility loading from `.claude/skills/`, `.codex/skills/`, `~/.agents/skills/`; `/migrate-to-skills` converts "Apply Intelligently" rules and slash commands into skills (explicit commands get `disable-model-invocation: true`); built-ins include `/cursor-blame` ("investigates AI-authored changes and the prompts that produced them") and `/autopilot` (monitors a PR, addresses feedback/failing checks) [✓TODAY skills]. Note: no auto-capture of run outcomes into rules is documented — rules are written by humans or on explicit ask.
- **Retrieve / Apply.** "When applied, rule contents are **included at the start of the model context**." Activation is a deterministic function of the frontmatter triple: `alwaysApply:true` → every session; `globs` provided → "auto-attached when a matching file is in context"; neither + `description` → "Agent reads the description and pulls the rule in when relevant"; neither → only `@my-rule` manual mention. Skills: auto-discovered at startup (name+description only), "the agent is presented with available skills and decides when they are relevant based on context", **progressive resource loading** ("keeping context usage efficient"), nested skill dirs auto-scoped to their subtree [✓TODAY rules, skills].
- **Evict / correct.** No published context budget/truncation numbers for rules (89 §7 honest negative [S7]); best-practice guidance: "keep rules under 500 lines, split large rules… when you see Agent make a mistake, update the rule… tag `@cursor` on a GitHub issue or PR to have Agent update the rule"; skills listing shows only description until invoked, and `disable-model-invocation` stops auto-use [✓TODAY rules, skills].
- **Weaknesses.** Rules are **authored, never derived**: Cursor captures no post-run outcome rows (no equivalent of Claude's recorded recipes or Codex's approval→rule). "Apply Intelligently" is model-decided from a one-line description — probabilistic activation with no scoring, no evidence, no ledger. No cross-project outcome memory (skills are per-repo/user; Cloud Agent sync copies files, not learned lessons). Rule hygiene is a manual discipline.

**9.1.5 Google Gemini CLI — hierarchical GEMINI.md context + memory files + checkpointing**
- **Capture.** (a) **Context files** — `GEMINI.md` (name configurable via `context.fileName`, e.g. `["AGENTS.md","CONTEXT.md","GEMINI.md"]`): global `~/.gemini/GEMINI.md`, workspace files searched in workspace dirs and parents, and **JIT files** — "when a tool accesses a file or directory, the CLI automatically scans for `GEMINI.md` files in that directory and its ancestors up to a trusted root"; `@file.md` imports [✓TODAY gemini-md]. (b) **Memory files** (a real memory tool exists): "Gemini CLI persists durable facts, user preferences, and project details by editing Markdown memory files directly… routes memories to the appropriate Markdown file: shared project instructions go in repository `GEMINI.md` files, private project notes go in the per-project private memory folder, cross-project personal preferences go in global `~/.gemini/GEMINI.md`"; storage = agent `write_file`/`replace` edits [✓TODAY memory-tool]. (c) **Checkpointing** (rollback, not learning): before any approved file-modifying tool run the CLI snapshots a shadow Git repo at `~/.gemini/history/<project_hash>` (doesn't touch the project repo) + saves conversation history + the pending tool call [✓TODAY checkpointing].
- **Retrieve.** "The CLI loads various context files from several locations, **concatenates the contents of all found files**, and sends them to the model **with every prompt**"; loaded facts from memory files "are automatically included in the hierarchical context system for all future sessions"; `/memory show` displays the full concatenation, `/memory reload` forces re-scan [✓TODAY gemini-md, memory-tool]. No scoring or top-k retrieval is published — the model reads everything that matched the hierarchy.
- **Apply.** Context is always-on prompt prefix material; `/restore <checkpoint>` reverts files **and conversation** and "re-proposes the original tool call, allowing you to run it again, modify it, or simply ignore it" [✓TODAY checkpointing].
- **Evict / correct.** No auto-eviction/consolidation documented for context files; the correction surface is (a) human editing of the markdown (same files the agent edits), (b) **Trusted Folders**: trust dialog with a discovery phase listing Commands/MCP servers/Hooks/Skills/setting overrides + security warnings; an untrusted workspace runs "safe mode" — workspace settings ignored, `.env` not loaded, tool auto-acceptance disabled, **automatic memory loading disabled**, MCP servers don't connect; headless untrusted runs throw `FatalUntrustedWorkspaceError` (`--skip-trust`/env var to bypass) [✓TODAY trusted-folders]. Community-documented consolidation: CLI is being folded into Antigravity for unpaid tiers (docs banner + 90 §1.15) — treat CLI-specific memory mechanics as consolidating into the IDE.
- **Weaknesses.** The **least learning** of the five: capture is file-editing with no outcome-triggered lesson extraction, no dedupe, no structured rows, no ranking (load-everything ⇒ context bloat is the only limit), no evidence links. Checkpointing restores *state*, it doesn't teach. Trusted folders gate *project config* trust, not lesson quality.

**Head-to-head verdicts (evidence-coded):**
- **Capture: Devin and Claude Code lead, in different directions.** Devin's Knowledge Suggestions are the best **human-gated auto-suggestion** pipeline (machine proposes, human edits/dismisses — 89 §3 "machine proposes, human disposes" [S1]); Claude Code's recorded recipes are the only **verify-triggered capture of what actually worked**, with an explicit anti-churn policy ("edits the recorded file only when it steered a run wrong… before v2.1.205… fold in anything a run learned, which caused frequent merge conflicts" [✓TODAY skills]) — that churn lesson is directly reusable by RapidTool's lesson-writer. Codex alone converts **approval events into permanent guardrails** (allow-list → `prefix_rule` [✓TODAY rules]).
- **Retrieval quality: nobody scores.** Cursor's frontmatter triple (always/globs/description/manual) is the most *controllable* activation model [✓TODAY rules]; Devin's trigger-description contract is the most *structured retrieval interface* but its engine is undocumented [✓TODAY knowledge; 89 §1.4]; Codex/Claude/Gemini are load-at-start or load-everything with byte/line caps, no relevance ranking [✓TODAY agents-md, memory, gemini-md]. **None of the five publishes a scored retrieval of stored lessons** — the closest is Devin's promise to recall "when relevant", unverifiable from outside.
- **Safety: two different philosophies.** Codex makes policy **runtime-enforced and deterministic** (rules evaluated by the engine, most-restrictive wins — closest to RapidTool's own gate philosophy, but scoped to shell commands only) [✓TODAY rules]; Claude Code delegates hard blocking to user-written hooks because memory is "context, not enforced configuration" [✓TODAY memory]; Gemini gates *project config trust* via Trusted Folders safe mode [✓TODAY trusted-folders].
- **Eviction/correction is the weakest stage everywhere.** Every competitor's correction loop ultimately requires a human to notice staleness (Claude `/doctor` + user review; Cursor manual hygiene; Devin disable toggles; Codex hand-edited rules; Gemini hand-edited markdown). **No shipped competitor counter-evidence-decays a lesson** (a later verified run marking an earlier lesson obsolete) — that mechanism exists only in research systems (Graphiti validity windows, 89 §2.7 [S21]).
- **The collective gap RapidTool can own:** none of the five stores **structured, evidence-hashed outcome rows** bound to a deterministic phase machine; none has **deterministic scored retrieval** of lessons into generation prompts; none **machine-verifies its own memory** (a lesson's claim is never re-checked by the verify gate before it is trusted again); none can point at a lesson and say which gate verdict, hash, and phase produced it. That is precisely the compound of 90's Axis 1 + Axis 2 + Axis 5 — and the 86/87/88 verdicts prove RapidTool already *produces* the structured failure evidence (lattice `vague:true`, DoD unmet lists, verify evidence strings, ledger rows) that such a loop consumes; it only lacks the write-back edges (P0-5 = G-25/G-39) and the retrieval wiring.

- **Tier 2 — on-trigger (the 86/87/88 failure-mode brake):** when the P0 lattice is `vague` (`algorithms.ts:200`), inject top-2 `fix` rows tagged `[vague-brief]` into the reframe HITL prompt and the scorecard context (87 §4 H2; 88 §7.2 bootstrap injection) — so a second kanban/statkit/renamepro brief **meets its own class of failure before the fallback fires**, and the reframe HITL prompt carries the prior run's lesson ("last stats-library brief fell back to deliver-core-workflow and shipped 0 features — tighten the brief or route kind=library").
- **Tier 3 — model/manual:** the crew researcher turn and `expandBrief` (`prompt-engine.ts:171`) receive a name+description listing of candidate patterns (progressive disclosure — full body only on match, per Agent Skills 89 §4 [S26]); explicit `knowledgeFind` (`headless.ts:1483`) stays for manual/adversarial use.

**HOW EVALUATED / EVICTED (the stage no competitor ships):**
- **Verify-gate auto-evaluation:** a lesson is only *re-trusted* if its claim still holds against current evidence — (a) E-19 drift (`engine.ts:1893`) is the counter-evidence scanner: a `fix` row whose failure mode recurs in a later run (same LEX gap, same circular oracle, same template-emission pattern detected) gets a `counterEvidence` increment; (b) a `pattern`/`fix` row contradicted by a later verified run is **superseded by a new append-only row** (never delete — the append-only law at `knowledge.ts:8` is the store's constitution), i.e. Graphiti's validity-window idea scaled down (89 §6 menu item 7 [S21]); (c) the dod.ts probe table grows one deterministic probe, `p6-lessons` (advisory rank input, next to `p6-test` `:126` / `p6-verified` `:153`), which recomputes "is the injected lesson still load-bearing for this phase?" — memory that never fires is demoted in FusionRank (deterministic: score × decay factor), memory that prevents recurrence is promoted to Tier 1. **All decay is a scored, ledgered, replayable computation — not a model's mood.**
- **Caps:** 80-row FIFO with a **pressure promotion** (MemGPT memory-pressure idea, 89 §6 menu item 2 [S15]): at row 60/80, deterministic consolidation moves top-ranked rows into knowledge.ts *before* `slice(-80)` evicts them (`report-intake.ts:343`), mirroring Codex's separate consolidation pass but keyless-deterministic.
- **The falsification gate (90 §5 / 14 §7):** the G-40 eval harness asserts the only claim that matters — gate-rejection rate per failure mode decreases across runs once L1-L5 rows are live. If run 6+ shows no measurable drop, the loop is decorative and gets ripped out. This is the "measure, or don't ship" discipline that makes the whole axis honest.

**Human-in-the-loop correction path** (the machine-proposes/human-disposes gate 89 §3):
1. Engine events (L1-L3) auto-write **project-local** rows immediately (deterministic, in-ledger, low-risk by construction — they are the run's own evidence restated).
2. **Cross-project promotion is HITL-gated, Devin-style** (✓TODAY knowledge): a suggestion row (LLM-drafted from the {verify-fail, fix, user-note} triple — the ExpeL/Reflexion extraction 89 §2.2-2.3) appears in the vault + HITL panel as "Proposed knowledge — edit / dismiss / regenerate"; only an explicit human accept calls `savePattern` (`knowledge.ts:166`) for cross-project scope. The vault note is the edit surface (89 §0: vault is pure/deterministic, human-owned).
3. **Approval→guardrail, Codex-style** (✓TODAY rules): a human *rejection* of a gate failure with the ADR-002 ≥12-char note (`engine.ts` HITL; rejections already require notes) mints a proposed `fix` row with provenance = {phase, gate id, evidence hash, decision row} — one human rejection becomes a durable check, which is exactly the 86/87/88 anti-pattern ("approval over unmet DoD with `note:null`") turned into the correction mechanism. Symmetrically, approving an override over an unmet DoD now requires the note that the verdicts found missing (87 §4 H7, 88 §7.1 #9) and writes an L5 row.
4. Every lesson row, promotion, decay, and supersede is a **ledger event** (`wildLog`-style append, `engine.ts:2033` pattern) — the memory system is inside the governance system, not outside it. That sentence is the entire differentiator.

### 9.6 Honest risks + what competitors do that RapidTool should NOT copy

**Risks of the §9 loop (own them):**
1. **Lesson noise poisons prompts.** A wrong `fix` row injected into P6 is worse than none. Mitigations: advisory-only by default (rows ride the ranked slot but never gate — `knowledge.ts` header "Advisory only" stays law); deterministic scoring means a bad row's harm is bounded and measurable; HITL gate on cross-project promotion; the falsification harness is the exit criterion.
2. **Reflection text can hallucinate root cause.** The Reflexion "why did attempt 1 fail" sentence is model prose. Rule: store it as `hypothesis` (honest label like knowledge.ts:16's "NOT embeddings" concession), never as fact, until a verify pass or human note confirms it. L1/L2 rows are engine-detected (deterministic) and therefore factual; L3/L5 carry model/human prose and must be tagged as such.
3. **Staleness across model/version drift.** A fix that held for deepseek-v4-flash runs may not transfer. Decay counters + supersede rows handle it only if E-19 drift scanning actually runs; wire it before promotion exists.
4. **Cross-project leakage.** `injectProven` already excludes self-project rows and floors at minScore 0.12 (`knowledge.ts:265-289`) — keep those defaults; domain tags from `projectKindOf` must be conservative (86's kanban and 88's statkit runs both tripped to the same fallback domain — a lesson tagged `[deliver-core-workflow]` would otherwise "help" every wrong-domain run).
5. **The compounding claim is falsifiable by design** (90 §5/14 §7) — if rejection rates don't drop by run 6, rip the loop out. That honesty is the feature; don't let demo metrics soften it.

**What competitors do that RapidTool should NOT copy (each with the reason):**
1. **Devin's opaque recall backend** (unpublished scoring/embeddings — 89 §1.4 honest limit). RapidTool's retrieval must stay deterministic + auditable + test-pinned; that is Axis 2. Copy the *trigger-description contract* and the *suggestion HITL*, not the black box.
2. **Cascade's uncurated auto-memories as a primary store** — the vendor itself is retiring them for the Devin Local agent in favor of skills ("Migrate the ones you rely on to skills", 89 §1.3 [S3]). RapidTool's auto rows stay project-local + FIFO-capped; only HITL-gated rows reach the durable store.
3. **Claude Code's "context, not enforced configuration"** for anything safety-relevant — RapidTool's gates are engine law with evidence hashes (90 §1.2). Memory should *inform*; it must never *decide*. (Copy the anti-churn recipe rule instead: edit recorded artifacts only when a run was steered wrong.)
4. **Codex's model-decided Smart approvals / auto_review without evidence** — RapidTool's classifier verdict contract + `evidenceHash` (90 §1.1 comparison) is the whole point. Copy only the *approval→guardrail* direction (approve/reject ⇒ durable rule) — and even there, the rule is a ledgered knowledge row, not a silent policy change.
5. **Gemini's load-everything context hierarchy** with no scoring or caps — RapidTool's ranked top-k keeps prompt cost bounded and attribution exact. (Copy Trusted-Folders-style *config trust* if MCP tool loading ever lands — P2-3.)
6. **Cursor's model-decided "Apply Intelligently"** as the primary activation mode — probabilistic rule loading with no audit trail. RapidTool's Tier 1/2 injections are deterministic; Tier 3 model-decided loading is optional and always provenance-stamped.
7. **Any auto-memory that writes without a ledger** — every competitor's memory writes are outside their governance story. RapidTool's lesson writes are ledger events (`engine.ts:2033` pattern) or they don't happen.

### 10.3 Leapfrog theory — what the literature says about this specific plan

- **Incumbent rent-protection is the mechanism that makes leapfrogging possible.** Fudenberg-Gilbert-Stiglitz-Tirole (1983): an established monopolist earning rent from an old technology has reduced incentive to adopt radical replacements; Schumpeter's creative destruction; Brezis-Krugman: the new technology initially looks *inferior* to those experienced with the old one, which is exactly why leaders under-adopt and entrants leapfrog when it matures [F1]. **Applied:** the field's rent is frontier-model access + IDE distribution + cloud fleets. Governance-as-law (hashed gates, typed honesty, append-only decisions) is the radical axis that *initially looks inferior* — no streaming, no IDE, no frontier IQ. §4's "don't chase their axis, 10× your own" is the correct reading of the theory; P0-1/P0-2 remain parity (table stakes), not moat.
- **Disruption is accessibility, not "better for the best".** The Christensen Institute definition: disruptive innovations make products "simpler, more affordable… available to a larger population"; low-end vs new-market vs market-creating; incumbents fail to respond because their own business model is the stumbling block (Blockbuster/Netflix) [F2]. **Applied:** the pitch "10× governance" only disrupts if it opens buyers the cloud-agent vendors cannot serve — keyless/air-gapped/compliance/audit-heavy teams who are *excluded* from Codex/Devin (account + cloud + ungoverned runs required). Position §4's axes as **new-market access** ("governed production for people who can't use the others"), not "we are a better Codex".
- **The winnable slot is consolidation at the dominant design, not creation.** Markides & Geroski (Fast Second, 2005): radically new markets are *colonized* by creators, then *consolidated* by fast seconds who enter as the dominant design emerges; most large established firms lack the skills/attitude to create radical markets at all [F3]. **Applied:** no one — not Codex, not Devin, not RapidTool — has yet defined the *dominant design* for governed agentic production (evidence standards, audit formats, interop). That argues for **standards participation now** (ACP/MCP bets P2-3/P2-4; packet/vault formats as exportable artifacts) and for treating §4's axes as consolidation assets (trust, records, switching costs) rather than hoping to "invent" a category alone. 90 §7.5's "interoperate, don't out-community" is the same conclusion.
- **Defensibility lives in switching costs, not speed.** First-mover advantage mechanisms: technology leadership, resource control, buyer switching costs [F4 — flagged low-quality page, use as tertiary]. RapidTool cannot win speed or model leadership; its natural switching cost is the **portability of the record** — packet/vault/ledger formats another tool can't import. Axis 4 (paper trail as product) is therefore also a *retention* axis; format stability (freeze trace schema — already done in `tracing.ts`) is a strategic act, not an implementation detail.

### 10.4 Engineering practices the roadmap itself should adopt (agentic-codegen product development)

- **Eval harness before features — the roadmap's real P0.** The universal practice: set up evals to establish a performance baseline before iterating [F10]; give the agent "a check it can run" so the loop closes without you [F9]; task corpora with ground truth are the standard pattern (SWE-bench: 2,294 real GitHub issues across 12 repos — models resolve issue → test-verified PR) [F11]. **RapidTool's corpus already exists:** the three verdict runs' briefs (86 Team Kanban ≈2.2/10, 87 RenamePro ≈**1/10**, 88 StatKit ≈1.2/10) with evidence-traced ground truth. Ship `npm run eval`: brief → headless run → machine-scored brief-conformance (brief-named exports exist, no TODO(E-15) stubs in required paths, no wrong-domain fallback) → verdict. **Metric to beat: the 1/10 RenamePro verdict**; the gate is "conformance rises run-over-run AND wrong-product `complete` = 0". No P0/P1 feature ships without a corpus entry.
- **Regression discipline: every roadmap PR carries a runnable check.** "Without a check, 'looks done' is the only signal" [F9]. The repo's `node --test` + strip-types rig exists (`package.json` scripts); the missing layer is *behavioral* regression over engine phases — the eval corpus doubles as that suite.
- **Deterministic gates beat prompt conventions; keep the 8-block override lesson.** Claude Code's Stop hooks are script gates that block turn-end until passing, with an 8-consecutive-block override [F9]. RapidTool's `dod.ts` gates + `enforceDod` are the stronger, law-level version — but **advisory-by-default makes them convention**: the override should be a *recorded, noted* human act (ADR-002 symmetry), not silence. Fix the asymmetry before marketing the gates (86/88: 5/5 approvals `note:null`).
- **Separate evaluator / fresh-model refutation.** Anthropic's recommended verification: "a fresh model tries to refute the result, so the agent doing the work isn't the one grading it" [F9]. RapidTool's wild classifier (`wild-mode.server.ts`) reviews the same flash-tier model's output; the cheap upgrade is a **pro-tier refutation pass on P6 before `p6-verified` promotion** (no new surface — `llm.ts:16` tiers exist).
- **Risk-tier every tool; pause/escalate on high risk and failure thresholds.** OpenAI: rate tools low/med/high by read-only vs write, reversibility, permissions; pause for checks or escalate to a human before high-risk actions; intervene on exceeded retry/action thresholds [F10]. This is the exact spec P1-4's `wildPolicy` should encode (and it matches the wild pause semantics already in `store.ts`).
- **Route models by task difficulty, deliberately.** "Not every task requires the smartest model" [F10]. Flash/pro already exist (`llm.ts:16`); make routing an explicit, telemetry'd policy (deterministic floor → flash classifier/chat → pro verify-fix/critique) instead of an accident of call sites — this is also the model-routing claim competitors market (Bolt) made *measurable*.
- **Treat context as the budget it is.** Anthropic: context is the most important resource; performance degrades as it fills [F9]. S4's context meter isn't cosmetic polish — it's the UI of a real degradation curve (90 §3 rank #8 impact 5 is too low).
- **Invest in the ACI, not the prompt.** Anthropic spent more time optimizing agent tools than prompts on SWE-bench (absolute-filepath fix) [F8]. RapidTool's ACI is the verify oracle/expression interface (`verify.server.ts`); 86/87/88 show its failure mode — self-referential oracles that never see the brief. Grounding `generateCases` in brief + spec (87 H6) is ACI work, and it is the single highest-leverage *code* fix the verdicts name.
- **Simple patterns, no framework accretion.** Anthropic: successful implementations use simple composable patterns; frameworks obscure prompts and tempt complexity [F8]. RapidTool's hand-rolled zero-dep discipline (arch-tools/algo-tools headers: "no fast-check, no ts-morph") is correct and should stay a stated rule for the roadmap — every P2 item that implies a dependency needs a feasibility note first.

### 10.5 De-risked execution order (why the verdict fixes precede the leapfrog)

**Phase 0 — "truth wave" (engine-internal, ~3-5 days, no new user surface).** The verdicts prove the core loop can seal 13/13 phases on a 1/10 product; every P0/P1 feature below multiplies whatever the loop produces, so fix what it produces first:
1. **Brief-conformance DoD probe** (`p6-brief-fit` next to `dod.ts:126-165`): required brief-named exports/JSDoc/zero-dep parsed from brief → probe over generated source; `vague` lattice with a non-empty brief can no longer sail. (86 §6-A, 88 §7.1-7, 87 H7.)
2. **LEX consumer/dev-tool register** (`algorithms.ts:24-111`): job/object/constraint terms for cli/library/webapp/game briefs so `intentLattice` (`algorithms.ts:145`) stops falling back to `deliver-core-workflow` (86 §6-C, 87 H1, 88 §7.1-1/2).
3. **HITL note symmetry**: approvals of `forceHuman` gates need a ≥12-char note like rejections (ADR-002 mirror) — kills the 15-second null-note reframe approval (87 S2, 88 §4.11).
4. **Wire the orphaned trio** (`algo-tools.ts`, `arch-tools.ts`, `gate-stats.ts`) into `dod.ts` criteria + phase paths; decide the `enforceDod` default explicitly.
5. **`npm run eval`** over the 86/87/88 corpus (§10.4) — the metric to beat is RenamePro ≈1/10 → target: wrong-product `complete` = 0, conformance ≥ floor per kind.

**Then P0 as written, re-costed:** P0-1 + P0-2 (chat trust wave — unchanged, shallow anchors), P0-4 reusing `planning.ts` (S not M), P0-3 with delta snapshots, P0-5 re-scoped to G-25 critique persistence + knowledge wiring (M-08 done). *Why this order:* the conformance probe is ≈1 day and is what makes the §4 marketing claim ("governed production", "the 1/10 verdict is the metric to beat") actually true; chat streaming first would put lipstick on a pipeline that 86/87/88 proved can produce governed artifacts for the wrong product.

**P1/P2 unchanged in sequence** (lattice before breadth; G-22 last on replay-safe foundations) — with §10.2's re-specifications (replay/export DB-backed; ts-morph wording dropped; wire-before-build).

**Kill criteria per phase (stage-gate knock-out must-meets [F5]):** each phase advances only when (a) eval conformance floor holds and wrong-product `complete` = 0 on the corpus; (b) honesty invariants green (typed failures, no fabricated verdict — the property the classifiers already enforce at `wild-mode.server.ts:121`); (c) keyless determinism tests green (byte-stable fixtures, no new nondeterminism); (d) no new runtime dep without a feasibility note (the zero-dep rule). Any item failing its gate is killed or re-scoped — gates are go/kill decision points, "not merely project review points or status reports" [F5].

### 10.6 Validating each leapfrog axis — hypothesis, experiment, honest metric, kill criterion

**12.3.2 Constraints that bind RapidTool's design** (each is a fact above + a design consequence)

1. **JSON mode is not a grammar guarantee.** Docs require: `response_format={"type":"json_object"}` **and** the word "json" + an example in the prompt **and** a sane `max_tokens` — and warn the API **may occasionally return empty content** (actively being optimized; mitigation = change the prompt) [H3]. `finish_reason:"length"` = truncated JSON [D-API §4d]. → RapidTool must keep its schema-validation + retry + evidence-hash layer; `response_format` alone can never be the gate. Same posture as deepseek-api.md's "watch for length" note.
2. **Thinking is ON by default and disables temperature.** In thinking mode `temperature`/`top_p`/penalties are *accepted but have no effect* [H6]; reasoning tokens count against `max_tokens` [D-API §4]. → Any RapidTool "creativity/exploration" knob must either disable thinking (`{"thinking":{"type":"disabled"}}`, the deepseek-api.md fast-path) or be dropped; every call needs explicit `max_tokens` headroom.
3. **Tool-calling + thinking round-trip rule.** Tool calls are supported on all models including thinking mode (from V3.2) [H4]; **when the request carries `tools`, the `reasoning_content` of prior turns MUST be passed back or it is lost from context**; without `tools` it is ignored anyway [H6]. → RapidTool's persisted conversation/tool-loop (chat + deepseek server layer per §8 anchors) must store assistant `reasoning_content` alongside messages whenever tools are in the request. `strict` schema mode exists but is beta and requires the `/beta` base URL + `strict:true` on every function [H4].
4. **Concurrency ceiling shapes the crew fan-out.** 2500 flash / 500 pro per account [H2][H5] → run stage fan-out on flash, reserve pro for planning/verdict/architecture stages; the orchestrator needs 429 backoff (and can raise the cap for free via the expansion form [H5]).
5. **Cache-hit economics are extreme.** Flash cache-hit input is ~3% of cache-miss (off-peak $0.007 vs $0.22) [H2] → byte-stable system prompts and phase contracts (every packet repeats the same contract text) turn the governed factory into a cache-hit machine; a real cost lever for the "10× cheaper governed runs" pitch if RapidTool ever publishes economics.
6. **Alias trap.** `deepseek-chat` and `deepseek-reasoner` are still *accepted* but both resolve to `deepseek-v4-flash` (live-verified) [D-API §2] → pin the explicit V4 IDs everywhere; migrate any legacy config.
7. **No built-in web search on chat completions.** Search lives only in the product chat app / the Responses-API `web_search_call` tool event [D-API §1][H7] → keep the TAVILY path ([D-API §1]).
8. **Responses API = a second, Codex-shaped surface** with typed SSE events (`response.completed` / `response.incomplete` / `response.failed`, `function_call`, `custom_tool_call` = `apply_patch`, `web_search_call`, `reasoning_text`) and **no `data:[DONE]`** [H7] → if RapidTool ever serves Codex-format clients (P2 MCP/API surface), this is the wire format to target; its terminal events map cleanly onto RapidTool verdicts.
9. **Context is huge but evidence should stay small.** 1M context / up to 384K output [H2] makes whole-repo audits feasible in one run, but gate evidence should remain hashes + deltas (that is the product's honesty envelope, §4) — big context is a cost trap, not a feature, per run.

**12.3.3 Recommended routing (from [H2] arithmetic + [F10] difficulty routing):** flash = gate checks, parsers, JSON extraction, edit generation, subagent research fan-out (cheap + 2500 concurrency); pro = phase planning, verdicts, architecture/design, hard-debug reasoning (500 concurrency, ~3× flash price) — same split this thread already uses (L1/L2/A1 flash researchers under a pro architect, file header).

### 13.3 Testing depth (pyramid, mutation, property-based, snapshot, contract)

- **External.** The pyramid still governs portfolio shape: "you should have many more low-level Unit Tests than high level Broad Stack Tests" because end-to-end/UI tests are "brittle, expensive to write, and time consuming to run" and prone to nondeterminism [Q7]. Mutation testing attacks *test quality*: "Bugs, or *mutants*, are automatically inserted into your production code. Your tests are run for each mutant. If your tests *fail* then the mutant is *killed*. If your tests passed, the mutant *survived*" — coverage alone can't tell paste from chocolate paste [Q11]. Property-based testing is "the construction of tests such that, when these tests are fuzzed, failures in the test reveal problems with the system under test that could not have been revealed by direct fuzzing of that system" [Q8]. Snapshot tests lock output shape: render → compare to "a reference snapshot file stored alongside the test. The test will fail if the two snapshots do not match," and snapshots "should be committed alongside code changes, and reviewed" [Q13]. Contract testing replaces brittle integration tests: "assert that inter-application messages conform to a shared understanding that is documented in a contract" — consumer/provider, "contract by example" [Q12].

### 13.5 Runtime production observability (crash analytics, error tracking, structured logs, traces, SLOs/error budgets, canaries, flags, rollback)

### 13.6 Bug-fix discipline (root-cause postmortems → regression-to-guardrail)

- **External.** Two primary sources carry the whole discipline. Google SRE: "Unless we have some formalized process of learning from these incidents in place, they may recur ad infinitum. ### 15.1 Goals, mission, design philosophy

- **What it is** (AGENT_GUIDE.md:3-7): *"RapidTool is a deterministic, governed pre-flight compiler: it does not build software itself. It turns a client brief into a paste-ready Agent Packet plus a phase-by-phase audit trail, so that a real agent does the building under enforced, auditable constraints."*
- **The five philosophy pillars, with anchors:**
  1. **Determinism** — every phase has a keyless deterministic floor (`synthesizePhase` engine.ts:227-757 [V]); pure no-LLM modules everywhere (`bench.ts:4-8`, `swarm.ts:10-23`, `vault.ts:7-8`, `ast-mine.ts:10-21` [V]); same input ⇒ byte-identical output (`vault.ts:8`, `design.ts:8-9`, `diagram.ts:24-29`, `scaffold.ts:12-14` [V]).
  2. **Governed HITL gates** — machine-checkable DoD exit criteria per phase with FNV-1a evidence hashes (`dod.ts:2-11, 259-291` [V]); stock human gates P4/P5/P8/P9 (`phases.ts:150-151` [V]); `forceHuman` gates that autopilot can never self-approve (`engine.ts:916-920, 2166-2175` [V]).
  3. **Honesty lattice** — typed `{ok:false, reason:"not-configured"}` before any network I/O (`crew.ts:5-8`, `chat.ts:30-36`, `wild-mode.server.ts:34`, `verify.server.ts:15-17`, `prompt-engine.ts:10-12`, `harvest.ts:10-27` [V]); `source:"illustrative"` competitor rows never promoted to "cited" (`types.ts:71-78`, `engine.ts:75-76` [V]); the runner is "bounded, NOT a security sandbox" (`node-runner.server.ts:4-21` [V]); LLM narrative honesty footers (`engine.ts:1563-1568` [V]).
  4. **Paper trail** — append-only decision journal capped never edited (`engine.ts:940, 1026` [V]); `wild.*` ledger events (`engine.ts:2033-2038` [V]); `gate.verdict` logs + gate artifacts (`dod.ts:362-406` [V]); E-18 provenance on memory rows (`types.ts:103-110` [V]).
  5. **Headless-driveability** — a 27-verb file-based CLI (`scripts/rapidtool-cli.mjs`, README-cli.md:10-17 [V]) over `src/lib/headless.ts`, designed for AI-agent loops (README-cli.md:537-596 [V]).
- **What it is NOT** (AGENT_GUIDE.md:76-92): real LLM only when `DEEPSEEK_API_KEY` set; live web research only when `TAVILY_API_KEY` set (else keyless DDG/Wikipedia via `websearch.server.ts`); no server-side persistence (localStorage only); no working P2P/multiplayer (staged, no live coturn); evidence hashes are FNV-1a (integrity, not crypto).
