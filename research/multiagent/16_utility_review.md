## 2. Per-item utility verdicts (G-21…G-40)

### Area 1 — delegation & orchestration

**G-21 — Hierarchical crew orchestration (CrewAI + Swarm handoff) — VERDICT: ADOPT-AFTER (prereq: G-40a trace/E-28 persistence, then G-24 plan ledger).**
The crew today is a deliberate deterministic phase→role table — "never an LLM speaker selector" (`crew.server.ts:9-10`) — whose output is auto-ingested through the report seam (`console.tsx:726-755` → `applyReportResult`). Before hiring an LLM manager that "allocates tasks and reviews outputs" (CrewAI hierarchical process, cited in the register), RapidTool must first persist and meter what the current advisory crew does per turn: E-28 (crew transcripts) and cost metering are still open (08 §0 E-28; `console.tsx:726-755` keeps only the ingested summary+artifacts, discarding per-turn transcripts/prompts). A manager whose delegation decisions are unmeasurable multiplies exactly the un-auditable spend the honesty contract guards against (`crew.server.ts:18-21`). Once trace + a machine plan artifact exist, the genuinely useful 40% of this item is Swarm's typed handoff that changes the next dispatcher and a manager task-list JSON for the 3-role phases (0 and 6, `crew.server.ts:122-136`) — the org-tree UI and per-task budgets are then cheap. No superiority claim survives today: CrewAI's manager pays off on *executive* agents; RapidTool's crew never approves/advances (`crew.server.ts:15-16`).

**G-22 — Stateful graph runtime (LangGraph checkpoints/edges) — VERDICT: ADOPT-AFTER (prereq: G-26 snapshots), HARD-SCOPED to deterministic predicate edges + declared phase-skips; NO LLM-routed `next()`.**
The gap is real but narrower than the register's LangGraph framing. The true user-visible pain is that every project walks all 13 fixed phases (`phases.ts:3-109`), so a local CLI tool still crosses P9 deploy / P10 edge gates whose content is nonsense for it — the fixed-graph constraint 10 §3 already flagged ("phases are fixed 0–12"). That is solved by *conditional skip predicates on project state*, not by durable checkpoints: the project JSON is already a full serializable checkpoint (`headless.ts:50-63`), runs are seconds-to-minutes local, and LangGraph-style durable execution buys nothing at this scale. The full-graph version is the riskiest possible change to the engine's identity: advance is literally `phase + 1` (`engine.ts:915, 963`), `canEnter` allows only `from+1` (`phases.ts:118-120`), hydrate clamps linearly (`engine.ts:1226, 1246`), and consumers index `PHASES[currentPhase]` directly (packet, UI rail). The sealed linear graph is RapidTool's uncontested differentiator (06 §5.2) — conditional edges preserve it only if default-linear is the invariant and every non-linear transition lands in the ledger with a deterministic predicate as evidence. Build G-26 first so every edge experiment is rollback-safe; keep 27+ engine tests green as the contract.

**G-23 — Parallel role fan-out with merge (MetaGPT) — VERDICT: RECONSIDER.**
The claimed win is wall-clock latency on multi-role phases (0: researcher/planner/architect; 6: coder/tester/reviewer; `crew.server.ts:122-136`). But the crew is advisory and human-triggered (`console.tsx:713-726`), every role runs deepseek-v4-flash (`ROLE_SPECS`, `crew.server.ts:103-112`), and a parallel 3-branch turn saves seconds on a loop whose results are advisory text. The merge-synthesis turn adds a fourth LLM call, cross-branch context drift, and a new honesty surface (synthesis citing real branch ids) for no competitive gain — Devin/Cursor parallelism (06 §7.4) operates on *executive* agents doing real work. Reconsider only after G-21 makes delegation consequential; MetaGPT's shared-message-pool pattern is in tension with the deterministic per-turn transcript the honesty contract depends on.

### Area 2 — sequential thinking & backtracking

**G-24 — Plan-then-act ledger (sequential-thinking scaffold) — VERDICT: ADOPT.**
Verified gap: the planner role exists with a real mandate (`crew.server.ts:63-65`) but its output is a `plan`-type transcript message that **nothing consumes** — no machine state, no revision, no packet presence (register claim confirmed: no consumer of `CrewMessageType "plan"` beyond rendering). Competitors already give agents revisable plans (v0 to-dos, Cline Plan/Act, Magentic-One ledgers — register citations). The spec's design is right-sized: `src/lib/think.ts` ledger seeded by the deterministic topo()/spec-graph order (`algorithms.ts:337-384`) as the zero-key floor, LLM planner rows validated through the existing JSON envelope machinery (`crew.server.ts:78+`), deviations logged as `revised` rows, and emission into the packet (E-11 seam). A Hermes-style agent driving headlessly gets a machine-checkable plan to steer against instead of prose — that is the single clearest agent-facing upgrade in this register. S–M effort, low risk: ADOPT early.

**G-25 — Reflexion self-critique → revise → retry — VERDICT: ADOPT.**
`verifyAndFixServer` already loops fail→fix→retry up to 5 iterations (`verify.server.ts:152-223`), but the loop is amnesiac: failures feed only the next fix prompt, nothing is persisted as a lesson, and nothing re-enters memory or the packet. Reflexion's core claim — failures become *episodic lessons that shape the next run* — is exactly the half that's missing, and it is the L5 "Remember/Improve" layer of 14 §L5. The spec's integration is minimal and honest: a structured `{symptom, hypothesis, fix}` critique on failed `runCases`, threaded into the next `generateCases` prompt (seam at `verify.server.ts:122-150`), persisted via the memory-capable intake path that already landed (`report-intake.ts:325-344` — rows exist for complete reports; critique rows slot beside them) with `ArtifactKind` widened additively (`types.ts:23-39`, no "critique" member today). Deterministic-template fallback keeps the zero-key floor. M/med risk is LLM critique quality — acceptable since the fix loop already trusts the model for patches.

**G-26 — Snapshot/rollback backtracking (Cline checkpoints) — VERDICT: ADOPT.**
Highest utility-per-risk item in the register. Today the only "backtrack" is reject→retry on the same file (`headless.ts:518-523`), repair only clamps forward (`engine.ts:1226, 1246`), and project JSON saves overwrite (`headless.ts:58-63`) — an agent that wants to explore two trajectories has no primitive. The spec is zero-dep and reuses existing machinery: FNV-1a (`algorithms.ts:733`), `exportProjectJson` (`io.ts`), atomic save (`headless.ts:58-63`), and the append-only ledger (`engine.ts:923-933, 969-1016`) to carry snapshot-hash evidence. Fork-on-HITL-rejection gives the human a real alternative-exploration path and agents `cli rollback <hash>` / `cli fork` verbs. This extends the deterministic-replay culture that is RapidTool's genuine edge (06 §5.11) and is the mandatory safety net before any G-22 edge work. S–M/med (file-identity bookkeeping is the trap the spec already names). Rank top-3.

### Area 3 — algorithm tools

**G-27 — Algorithm template library + synthesis + benchmark — VERDICT: ADOPT (scoped).**
Verified gap: scaffold kinds are CRUD/game/console/service only (`projectKindOf`, `scaffold.ts:229-232`; Console emitter `scaffold.ts:566`), `buildTestOracle` emits static job-shaped cases (`algorithms.ts:449-467`), and the coder mandate never points at an algorithm source (`crew.server.ts:70-71`) — so a brief like "schedule jobs by deadline" produces template CRUD, and any algorithmic code the crew writes is hallucination-prone. A vendored ~20-port TS subset (MIT, notice header) with Big-O tags plus a `benchmark()` emitter for a new "algorithm" scaffold kind gives tool-kind projects real substance and gives the coder role a concrete reference. This is *not* a competitor differentiator (Bolt/v0 don't compete here either), it is content value at M/low with zero new deps — adopt for the tool-kind wedge, sized as the register says (~600 L), and pair with G-28's property runner as the natural oracle for emitted algorithm modules.

**G-28 — Property-based test generation (fast-check) — VERDICT: ADOPT.**
Verification depth is a named loss (06 §7.5: "machine-run loop covers the generated module only… hand-written examples"). `VerifyCase` is one boolean expression per case (`verify.server.ts:21-23`; harness `runCases :94-120`), so invariants like "sort output is a permutation and nondecreasing" are inexpressible, and there is no shrinking — the exact failure evidence a fix prompt needs. fast-check (MIT, server-only — the client bundle stays untouched) with a fixed seed preserves the deterministic-evidence philosophy (`dod.ts:7-11`: hash over sorted id:pass|fail). The risk the spec names — generator selection for arbitrary exports — is contained by capping attempts and falling back to expression cases when no typed exports parse. M/low-med: adopt alongside G-27 (property tests are the oracle that makes "algorithm module + benchmark" claims checkable) and wire through the existing `verifyAndFixServer` seam (`verify.server.ts:152-223`).

**G-29 — Complexity & code-metrics gate — VERDICT: ADOPT (small).**
Reviewer PASS/FAIL is currently opinion with no machine number behind it (P6 review gate evidence never consults code metrics — verified: `dod.ts` probes read project content only). A deterministic cyclomatic-complexity/LOC counter with file:line evidence appended to gate rows is keyless, ~80 lines, and exactly the machine-minted-verdict culture RapidTool sells. Note the register correctly rejected the heavyweight option: eslint is already a devDependency (`package.json` ^9.20), but pulling its programmatic API for one number is the wrong weight. S/low. Agent benefit: the coder self-checks "complexity ≤ 10" before claiming done — a concrete, testable standard. Adopt in the quick-wins batch.

### Area 4 — architecture tools

**G-30 — Dependency graph + architecture rules on real generated code — VERDICT: RECONSIDER (narrow to the honest core).**
The register's own framing concedes the problem: "architecture is enforced on the *actual* code" — but the actual code today is template scaffolds the pipeline wrote from its own planned graph (`planSpecGraph`, `algorithms.ts:337-384`), plus small agent-report files. Running dependency-cruiser's rules engine over that is parity tooling (Copilot/CI already lint real repos) on output that rarely violates layering. The assertion that would actually matter — and which nothing checks today — is **planned-vs-actual drift**: does the set of files in the ingested agent report match the spec-graph order (`specGraph.order`, surfaced at `console.tsx:1539-1552`)? That is a zero-dep diff, not a rules engine, and it belongs in gate evidence. Hold dep-cruiser until agent-written multi-module output is the norm (post G-27/G-35/E-15 volume), then re-open with the register's design.

**G-31 — Module-graph image auto-generation (madge) — VERDICT: REJECT (re-open gated).**
madge's product is "a *picture* of the codebase, generated deterministically" — but the codebase pictured is 5–15 template files, and RapidTool already owns a deterministic diagram module (diagram.ts landed this wave with tests; `DiagramPane`, `console.tsx:3293`) plus a spec-graph view. The marginal artifact is demo decoration with a new dependency, and its own spec rates it #13 and says "do together with G-30" — which is itself deferred. Re-open condition (state it in the register): real multi-file agent-written output volume plus a concrete reviewer/PR-style consumer. Until then: shelfware.

**G-32 — ADR automation — VERDICT: ADOPT (small).**
This one is a product-honesty fix as much as a feature: the architect MANDATE promises to "Lock schema, routes and ADRs" (`crew.server.ts:68-69`) and P12's content spec is ADR-flavored docs (`phases.ts:100-107`), yet no ADR file is ever produced — decisions live only as packet prose and ledger rows (`engine.ts:923-933`). Minting `adr/NNNN-<slug>.md` from approve/reject events (rejection note = consequences, `engine.ts:986+`), gate verdicts (evidence hashes, `dod.ts`), and architect JSON artifacts is deterministic, keyless, S-effort, and makes the exported project a governance artifact no app-builder ships (06 §4/§5: no competitor exposes a verdict ledger at all, let alone ADR files). The license flag on npryce/adr-tools (CC-BY-SA, pattern-only) is correctly handled; format is unencumbered. Adopt in the quick-wins batch.

**G-33 — AST codebase map + refactor planning (ts-morph) — VERDICT: RECONSIDER.**
ts-morph is a TypeScript-compiler-weight dependency justified when a codebase is rich enough to hide oversized modules, dead exports, and boundary violations. RapidTool's generated output today — deterministic templates plus occasionally ingested agent files — is neither large nor organic enough for symbol-level maps to pay, and the register's own acceptance criteria (match a hand-verified 3-file sample; boundary violations as gate evidence) describe QA that G-29's metrics and the G-30 drift probe already cover more cheaply. The "proposeRefactors (never auto-applied)" half is scope creep on a pipeline whose generated code is regenerated, not maintained. Revisit when module volume and agent-written code share justify it.

**G-35 — Component-generation catalog + HTML→React conversion — VERDICT: ADOPT-AFTER (prereq: G-34 tokens; scope: additive recipes + HTML-intake first, emitter refactor last).**
The gap is real — the scaffolded Console is hand-rolled stringly JSX (`scaffold.ts:566`) with no variant system — and the register is right that component-catalog UIs are the v0/shadcn standard. Sequence: brief tokens (G-34) → HTML intake + 3–5 additive variant recipes → full catalog refactor only if scaffold UI quality data demands it.

**G-36 — Open canvas (Figma-like) editor — VERDICT: REJECT.**
L effort, high risk (bundle weight, a11y, scope creep — the register itself says "build last, and only if the design tab earns usage"), **zero agent-facing surface** (its own spec: "none required (visual-only surface)"), and it drops RapidTool into Penpot/Figma territory where it has no product claim and no moat — the furthest point in this register from the mission bottom line (06 §5). ### Area 6 — vector / logo / icon generation on the DeepSeek key

This is a genuine differentiator in the governed-builder niche — Bolt/Lovable/v0 do not produce brand kits from the same subscription that builds the app — at M/med with the sanitizer as the single load-bearing risk (correctly identified; CSP + `<img>` data-URL preview keeps it out of the DOM). S/low and self-contained: `deriveRamp(baseHex, steps)` via culori LCH interpolation (MIT, tree-shaken ~2KB) or a zero-dep HSL fallback, WCAG contrast math for `accessiblePair`, deterministic `cli palette <hex>`.
