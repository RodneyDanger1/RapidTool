## 10. Lessons worth stealing (ranked by value × feasibility for a TypeScript/Node repo)

Each lesson states the competitor mechanism, the file that proves it exists, and the RapidTool seam it
maps to. Feasibility is for the existing RapidTool codebase (TanStack Start / TS / zustand / zod /
Node 22), not for a greenfield project.

### 1. Build the surgical edit primitive first — it is the single largest value gap
**Steal:** a `str_replace`-style edit whose preconditions are checked *before* the write (unique match,
line-ending/BOM preservation), with a **graded** fallback chain rather than one exact match, and a
machine-readable diff returned as the tool result.
**Proving files:** `codex-rs/apply-patch/src/seek_sequence.rs:1-25` ("Matches are attempted with
decreasing strictness: exact match, then ignoring trailing whitespace, then ignoring leading and
trailing whitespace"); `sdk/packages/core/src/extensions/tools/executors/editor.ts:162-191` ("multiple
occurrences of text found" → refuse); `aider/coders/editblock_coder.py:134-296` (whitespace →
leading-whitespace repair → closest-edit-distance → filename `get_close_matches(..., cutoff=0.8)`);
`packages/core/src/tool/edit.ts:84` (OpenCode names the exact four V1 strategies it will port later).
**Why for RapidTool:** this is the mechanism behind **103 A9** ("no apply-patch/continue primitive") and
**100 P0-04** (five job files that are byte-identical re-exports): with a real patch primitive, P6 can
emit *per-file* deltas instead of whole artifacts, and `repair --dir` can preserve user edits.
**Feasibility: M** (pure TS + difflib-equivalent; no new deps beyond a diff lib).

### 2. A provider registry with role tiers — and an explicit-model rule
**Steal:** (a) register providers by id via a factory (`registerHandler(providerId, factory)`), not by
branching; (b) declare *roles* — main / reasoning / weak — instead of one hard-coded model id; (c) never
inherit an SDK's default model — always send an explicit one, and treat whitespace-only as absent.
**Proving files:** `sdk/packages/llms/src/providers/factory-registry.ts:4-20,65-158`;
`pr_agent/algo/ai_handlers/base_ai_handler.py:1-26` (ABC) + `pr_agent/settings/configuration.toml:9-11`
(`model_reasoning` "dedicated reasoning model for self-reflection", `model_weak`);
`specs/llm-defaults.md` (LLD-001, quoted in §5).
**Why for RapidTool:** **103 A1** is the highest-value foundational gap; `LlmModel` in `src/lib/llm.ts:16`
is a two-variant union and every seam imports `deepseek.server.ts` directly. The role tiers also give a
principled fix for **P0-03** (judge/producer asymmetry) — make the judge's *role* explicit rather than
tuning tiers ad hoc.
**Feasibility: M** (interface + registry + env-driven config; the seams are already isolated).

### 3. Governance as a policy engine: `(action, resource) → effect` with an explicit fallback
**Steal:** approvals become data, not control flow. Every decision resolves through
`evaluate(action, resource, fallback)` where the caller must supply the default effect — so "the agent
may not mint this" is a *statement*, and an unmatched action cannot silently allow.
**Proving files:** `packages/core/src/policy.ts` (`Effect = "allow" | "deny"`, `Info { action, effect,
resource }`, `evaluate(action, resource, fallback: Effect)`); `codex-rs/core/src/exec_policy.rs:395-452`
(`Decision::{Allow, Prompt, Forbidden}` → `ExecApprovalRequirement::{Skip, Prompt, Forbidden}`) plus
`updated_policy.add_prefix_rule(&amendment.command, Decision::Allow)`.
**Why for RapidTool:** this is the *shape* of the **P0-01** fix (an approval actor check becomes a policy
statement evaluated at one seam) and of **P0-02** (a DoD criterion becomes a predicate over the recorded
actor/resource, not `status === "complete"`).
**Feasibility: S** — a `src/lib/policy.ts` with a frozen rule table + one `canSelfApprove(action,
resource, fallback)` seam; the repo already has the atomic-write and error-code machinery.

### 4. Verify the *effect*, not the *request* (this is the P0-02 root cause, stated by a competitor)
**Steal:** when an action is supposed to change state, observe the resulting state change and time out
with a *failure* if it does not land. OpenHands models it as three outcomes and refuses to conflate
"nothing needed doing" with "the thing did not happen".
**Proving files:** `src/hooks/use-await-context-compaction.ts:11-20,151-152` (`ContextCompactionOutcome
= "compacted" | "no_change" | "timeout"`; *"No Condensation event in time means the compaction never
landed — a failure, not a 'nothing to compact' no-op."*); `sdk/packages/core/src/extensions/context/
compaction.ts:552-583` (`tokensSaved: requestInputTokens - afterRequestTokens`).
**Why for RapidTool:** `dod.ts:47-48` (`phaseComplete`) is exactly the failure this prevents — a
criterion that reports on its own proxy. Reuse the pattern in the DoD probes *and* in any future
compaction.
**Feasibility: S** (no new infrastructure; a probe-shape change in `dod.ts`).

### 5. Freeze the grader outside the agent, then score across trials
**Steal:** the acceptance assertions are declared *before* the run, live outside the workspace the agent
can touch, and the score is reported as `pass@k` / `pass^k` / a flakiness measure across repeated trials
rather than a single green tick.
**Proving files:** `evals/smoke-tests/scenarios/02-edit-file/config.json` (`expectedFiles`,
`expectedContent[{file, contains}]`, `timeout`); `evals/analysis/src/metrics.ts:5-11,80-94`;
`sweagent/run/batch_instances.py:430` (FAIL_TO_PASS travels as metadata, never as task text).
**Why for RapidTool:** **100 P0-05** (4/9, `dod.blocked`) and **103 G5/A14** are credibility problems as
much as capability problems: an eval whose fixtures the pipeline author can write is not evidence. A
two-line change — move `acceptanceFixtures` out of the project JSON into a run-side file the engine
cannot write — converts the scorecard into evidence.
**Feasibility: S–M** (`scripts/run-eval.mjs` + `research/eval-corpus/` already exist; this is
re-pointing them).

### 6. Budgets that bind: per-phase $ and token caps, cache-aware prices, and honest output caps
**Steal:** (a) a cap that *stops* work rather than warns, with a defined salvage behaviour
(SWE-agent autosubmits the current diff instead of discarding it); (b) usage recorded with enough
attribution to bill a *phase* (Codex's `TokenUsageRecord`); (c) cost computed with cache read/write
prices, not just input/output; (d) output caps justified by the quadratic cost of re-sending text.
**Proving files:** `sweagent/agent/models.py:73-77,375-381` + `sweagent/agent/agents.py:330-346`;
`codex-rs/protocol/src/protocol.rs:2233-2261`; `sdk/packages/llms/src/providers/ai-sdk.ts:1138-1166`;
`pr_agent/algo/token_budget.py:17-40` (reserve output headroom per model);
`sdk/packages/core/src/extensions/tools/executors/output-limits.ts` (*"Every character returned by an
executor is re-sent to the model on each subsequent request, so oversized outputs cost quadratically
over the remaining run."*).
**Why for RapidTool:** **100 P1-05 / 103 A3/G7** — `RAPIDTOOL_TOKEN_CAP` meters only P6. The cheap part
(cache-aware prices + output caps) delivers most of the value without touching the engine.
**Feasibility: S–M**.

### 7. Snapshot / checkpoint / revert as a first-class subsystem, and state that lives in the artifact
**Steal:** (a) an explicit snapshot service with named operations (`capture | files | diff | preview |
restore`) and a session-level revert to a message boundary; (b) cross-run state persisted *inside the
artifact* under review — a versioned marker plus a content fingerprint and ACTIVE/RESOLVED states.
**Proving files:** `packages/core/src/snapshot.ts:14-30` + `packages/core/src/session/revert.ts:1-30`;
`sdk/packages/core/src/session/checkpoint-diff.ts`, `checkpoint-restore.ts`, `hooks/checkpoint-hooks.ts`;
`aider/repo.py:131` + `aider/commands.py:553-648` (git-as-checkpoint, `/undo`);
`pr_agent/algo/review_finding_state.py:1-25` (`<!-- pr-agent-review-state:v1 … -->`,
`key_issue_fingerprint`, `DEFAULT_MAX_RESOLVED_FINDINGS = 20`).
**Why for RapidTool:** **103 A5 / 100 P1-07** (no step-level checkpoint, no user-facing undo) — and the
PR-Agent marker pattern is a way to make the append-only ledger *queryable by fingerprint* without a
database.
**Feasibility: M** (git is already reachable from Node; the ledger format already exists).

### 8. Isolation must be an OS primitive or an explicit delegation — never "a bounded timeout"
**Steal:** the industry has exactly three answers, and all three are honest: OS primitives (Codex),
a container per unit of work (SWE-ReX), or delegation to a backend whose isolation you do not own
(OpenHands). What no competitor does is run generated code in-process and call it a sandbox.
**Proving files:** `codex-rs/protocol/src/protocol.rs:1072-1096` + `codex-rs/bwrap/src/main.rs`;
`sweagent/environment/swe_env.py:27-29`; `src/api/cloud/sandbox-service.api.ts`.
**Why for RapidTool:** **103 A2**. Note the repo's *honesty* here is already ahead of most (it advertises
`sandbox:false`); the fix is an executor swap behind `node-runner.server.ts`, which the census already
scoped.
**Feasibility: L** (host tooling policy decides docker/bwrap availability).
