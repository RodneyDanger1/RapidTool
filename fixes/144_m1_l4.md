## 1. WILD-RESUME REGRESSION (g3 finding: UI Resume was driverless)

### Existing behavior quoted first

The store's only resume entry re-enters the **driver**, it does not flip a flag —
`startWildRun` while `wildRun.pause === true` falls through the double-start guard and the
`started` block re-stamps an active, UNPAUSED run, preserving `startedAt` (epoch stability
for telemetry) and ledgering `wild.resume` (`src/lib/store.ts:900-945`):

```ts
        if (p.wildRun?.active) {
          // PA-01: a PAUSED active run is a run whose driver exited —
          // re-entering the loop here is exactly the resume path
          // (toggleWildPause cleared pause). An UNPAUSED active run is a
          // genuine double-start and stays refused.
          if (p.wildRun.pause !== true) {
            return { ok: false, ran: 0, stoppedReason: null,
                     error: "A wild run is already active.", code: "RT_E_PHASE_ILLEGAL" };
          }
          // fall through: resumed run — the started block below re-stamps the
          // active surface and keeps startedAt/lastAutoAt (PA-01).
        }
```
…`resuming` (store.ts:921) keeps `startedAt`, and the loop (store.ts:978-1001) steps up to
20 times via `wildStep`, returning on pause/complete. The prior test pinned only `ok ===
true` (`src/lib/store.test.ts:956-971` — "S2: startWildRun on a PAUSED active run resumes
it (PA-01 resume path)", asserts `resumed.ok, true` and nothing else), which is why the
g3 UI-resume defect (console Resume → `toggleWildPause` → `active:true, pause:false,
driverless`) could hide.

### New regression test — store.test.ts:1408 (suite test 63)

`144 L4: startWildRun on a paused run re-enters the DRIVER (active+unpaused stamp,
wild.resume log, >=1 more step)` — the real user flow: keyless wild run parks PAUSED at the
P4 gate (driver exited) → human approves the open gate (approve never unparks the run) →
Resume = `startWildRun` → mid-flight snapshot (start stamp commits synchronously before the
driver's first `await wildStep`) proves driver re-entry. Assertions:

- parked: `currentPhase 4`, `hitl.phase 4`, `wildRun {active:true, pause:true}`;
- after approve: cursor P5, wildRun **still** `{active:true, pause:true}` (approve ≠ resume);
- resume mid-flight: `wildRun.active === true`, `wildRun.pause === false` (the driver
  re-entered — a driverless `toggleWildPause` would also show this, which is why the next
  two assertions matter), `startedAt` preserved (same epoch), `wild.resume` log present;
- `res.ran >= 1` and `currentPhase > 4` after the resumed driver re-parks (it executed P5
  and parked at the P5 stock gate) — ≥1 REAL step, not a flag flip.

### New regression test — store.test.ts:1458 (suite test 64)

`144 L4: a paused run force-stopped by a simulated reload is honestly not-active —
startWildRun starts FRESH, never resumes the dead session`.

Existing behavior quoted first — a persisted ACTIVE run cannot survive reload: storage
rehydration and the CLI load path both repair through `engine.hydrateProject`, whose
`hydrateWildRun` force-stops it (`src/lib/engine.ts:1691-1696`):

```ts
  if (!run.active) return { wildRun: run, stopped: false };
  // Session-break honesty: a live run cannot outlive the driver that drove it.
  return {
    wildRun: { ...run, active: false, pause: false, stoppedAt: run.stoppedAt ?? Date.now() },
    stopped: true,
  };
```
…plus the loud `wild.stop` ledger row (`engine.ts:1966-1979`:
`"Session reloaded — active wild run stopped (no driver survives reload)."`). The CLI
resume surface then reports the run as **not-active** (`headless.ts:1837-1840`):
```ts
  if (!run || !run.active) {
    return { ok: false, reason: "not-active", error: "No active wild run to resume." };
  }
```
The test simulates the reload with `hydrateProject` on the parked run and asserts:
force-stop shape (`active:false, pause:false, stoppedAt:number` + `wild.stop` log), then —
because the store's only resume entry is startWildRun-while-paused-active (store.ts:900-916)
— a subsequent `startWildRun` is a **FRESH run**: `startedAt` mints a NEW epoch, ledgered
`wild.start`, **never** `wild.resume`. This is the store-side half of L3's honest
"start a new run from current phase" copy after any load.
