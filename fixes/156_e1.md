## 1. Mechanism — web-researched FIRST (7 live fetches, all read this pass, 2026-09-08)

| # | Source (fetched live) | What it establishes |
|---|---|---|
| [E1-1] | DeepSeek API reference — Chat Completions (`https://api-docs.deepseek.com/api/create-chat-completion`) | `thinking` param values `[enabled, disabled]`, default `enabled`; "If set to `disabled`, then use **non-thinking model**." `reasoning_effort` `[low, high, max]`, default `high`, "medium and xhigh are mapped to high". `reasoning_content` = "reasoning contents of the assistant message, **before the final answer**" (thinking mode only). `finish_reason` `length` = "the maximum number of tokens specified in the request was reached". `response_format` `json_object` "guarantees … valid JSON" and requires the word "json" in the prompt or the model "may generate an unending stream of whitespace until the generation reaches the token limit". `usage.completion_tokens_details.reasoning_tokens` exists. |
| [E1-2] | DeepSeek — Thinking Mode guide (`https://api-docs.deepseek.com/guides/thinking_mode`) | Thinking mode is ON by default with effort `high`; per-request toggle `{"thinking":{"type":"enabled/disabled"}}` (OpenAI format) with `none` disabling in the Anthropic format. Effort mapping identical for v4-flash and v4-pro: `low→low, medium→high, high→high, xhigh→high, max→max`. In thinking mode `temperature/top_p/presence_penalty/frequency_penalty` are NO-OPS ("will not trigger an error but will also have no effect"). Tool-call turns legitimately carry `content:''` with `reasoning_content` populated (worked example Turn 1.2/2.1). When the request does NOT carry `tools`, prior `reasoning_content` is NOT concatenated and need not be passed back (so a thinking-off retry of the same envelope needs no CoT replay). |
| [E1-3] | DeepSeek — JSON Output guide (`https://api-docs.deepseek.com/guides/json_mode`) | Vendor-acknowledged: "**When using the JSON Output feature, the API may occasionally return empty content.** We are actively working on optimizing this issue." Official checklist: `response_format:{type:'json_object'}` + the word "json" in the prompt with a format example + "**Set the `max_tokens` parameter reasonably to prevent the JSON string from being truncated midway**" (the sample itself uses `deepseek-v4-pro` + json_object). |
| [E1-4] | DeepSeek news — V4-Pro GA (`https://api-docs.deepseek.com/news/news260813`) | "Flexible reasoning effort for V4-Pro & V4-Flash: low for simple tasks, high for daily Agent workflows, max for complex tasks" — effort is a per-request dial, thinking is not mandatory. |
| [E1-5] | goose issue #11142 (`https://github.com/aaif-goose/goose/issues/11142`) | "The model's thinking tokens count against the same `max_tokens` budget as content tokens. When a reasoning model produces verbose thinking (common with DeepSeek…), the entire budget is consumed by `reasoning_content`, producing **0 content tokens** — … just `finish_reason: "length"` with empty content." Reference fix (pi coding agent): `maxTokens = baseMaxTokens + thinkingBudget` guaranteeing ≥ MIN_ANSWER_TOKENS. |
| [E1-6] | claude-code-router PR #1596 (`https://github.com/musistudio/claude-code-router/pull/1596`) | "Reasoning models … may return `content: ""` with all actual output in `reasoning_content`. This happens when `max_tokens` is consumed entirely by the thinking process." Field fix shipped there: `content || reasoning_content`. |
| [E1-7] | SkillClaw issue #70 (`https://github.com/AMAP-ML/SkillClaw/issues/70`) | DeepSeek v4-flash/v4-pro empty content through a PROXY relay (`content:""`, output in `reasoning_content`, `finish_reason:"length"`) while the DIRECT upstream call populates content. → excludes relay re-fielding here: RapidTool calls `https://api.deepseek.com` DIRECT (deepseek.server.ts `DEEPSEEK_BASE_URL`), so the observed empty content is the model/budget class, not a proxy defect. |

**Verified answers to the research questions:**
(a) **thinking + json_object is supported** on v4-pro — the API reference lists both independently, the
JSON guide's own sample runs `deepseek-v4-pro` + `json_object` (thinking on by default), and the
parent's small-prompt probe returned content + reasoning_content fine.
(b) **When reasoning consumes `max_tokens`:** `finish_reason:"length"` with empty/zero content — the
shared-budget mechanism [E1-1][E1-5]; DeepSeek's own JSON guide adds that json_object can return
empty content and that a too-small `max_tokens` truncates the JSON mid-string [E1-3].
(c) **Field fixes in the wild:** raise/separate the budget (pi, goose) [E1-5]; read
`content || reasoning_content` [E1-6]; **disable thinking per request** (`thinking:{type:"disabled"}` —
supported, "non-thinking model" [E1-1][E1-2]); or lower `reasoning_effort` (note `medium` silently
maps to `high`, so an effort dial must be `low` to actually cut budget [E1-1][E1-2]).

**Why this is the size/thinking case, not the small-prompt case:** at 32k max_tokens with effort
`high`, a LARGE chunk prompt ("write this whole module as one JSON string", brief ≤2000 chars + full
requirement list + ≤8 signatures + earlier exports) invites 10–30k+ tokens of chain-of-thought; the
shared pool [E1-5] then leaves zero tokens for content ⇒ `content:""` every call. A small prompt
thinks for 193 tokens and finishes normally — exactly the parent's probe split. Disabling thinking
hands the ENTIRE 32k budget to content.

## 2. Decision (fixes/154 R1 + D5 + 157 P1-3, smallest correct option)

**Option (1) chosen — an ADDITIVE `thinking?: boolean` opts flag on the synthesis call, sending
`thinking:{type:"disabled"}` for the json_envelope synthesis.** Rationale:
- Structured codegen needs OUTPUT budget, not chain-of-thought: the correctness loop is deterministic
  (envelope parse → export/binding/forbidden/signature validation → brief-fit → machine verify /
  tree-run) — CoT contributes nothing the harness can use, and on the large prompts it starves the
  answer. This is fixes/154 D5's prescribed branch ("refusals persist at 32k ⇒ disable thinking for
  json envelopes on the pro tier") now that the 32k/240s budget is live and empty content persists.
- Option (2) (`reasoning_effort: low`) was rejected as WEAKER: effort only shrinks (not removes) the
  reasoning draw; `medium`/`xhigh` silently map to `high` [E1-1][E1-2], and the vendor-acknowledged
  json_object-empty class [E1-3] plus the "answer lands in reasoning_content" class [E1-6] are only
  fully closed by the non-thinking shape (no reasoning_content exists on a non-thinking call).
- Option (3) (extract final JSON from reasoning_content in a follow-up call) was rejected: it
  assumes the JSON is IN reasoning_content, which the docs define as pre-answer CoT [E1-1] — the
  SkillClaw/hermes-agent misfile shape is a proxy artifact [E1-7] and RapidTool calls the provider
  DIRECT; the budget-starve shape has no JSON in reasoning_content to salvage (it is truncated CoT).
- No new retry rung added: with thinking off the starve class is structurally impossible on the
  first call, so a bounded "retry empty with thinking off" rung would be an unmeasured second remedy
  stacked on an untested fix (F3/D5 instrument-first discipline). The F3 empty-content diagnostics
  stay; if a post-fix keyed run's journal still shows refusals (the vendor's "occasionally empty"
  json_object flake [E1-3]), THAT measured evidence decides the next rung.

## 3. The fix (all additive, byte-identical defaults)

1. **`src/lib/deepseek.server.ts`** — new option `thinking?: boolean` on `DeepSeekCompleteOptions`
   (documented at the type). Body construction now:
   `...(opts.thinking === false || !isPro ? { thinking: { type: "disabled" } } : { thinking: { type: "enabled" }, reasoning_effort: "high" })`
   - Omitted flag ⇒ byte-identical legacy bodies: pro = `thinking enabled + reasoning_effort high`
     (the fixes/125 pro-reasoning contract, pinned by a new test), flash = `thinking disabled`.
   - `thinking:false` ⇒ the non-thinking shape on the PRO tier too; NO `reasoning_effort` key rides
     it (flash-shape parity — the exact body shape this codebase already runs json_object on for
     flash expand/oracle calls and sees real content from).
   - `thinking:true` on flash is a documented no-op (flash has no thinking-on shape in this module);
     the override's purpose is turning pro OFF for structured envelopes.
   - No export renames; existing callers untouched.
2. **`src/lib/codegen.server.ts`** — BOTH P6 synthesis call sites (single-module legacy path and the
   per-chunk tree path) now pass `thinking: false` alongside the existing `model: pro, json: true,
   maxTokens: 32_000, timeoutMs: 240_000, system:` — repair re-prompts reuse the same `opts` and are
   thinking-off too. Header/constant comments updated to say "thinking DISABLED instead of
   out-budgeted (fixes/156 E1)". NO prompt/byte strings touched.
3. `reasoning_effort: high` remains the DEFAULT for any other pro caller (chat/verify paths keep the
   fixes/125 reasoning contract unless they opt out).
