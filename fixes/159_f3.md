## The bug

155-SA §3: `dod.ts:714 oracleToCaseSeeds()` renders A7 rows as `# orc-<id> <name> — <given> ⇒ <expect>` seed lines and the E-08 comment block (dod.ts:706-711) documents that the verify loop "prepend[s] oracleToCaseSeeds() to the generation prompt, then reject[s]/retr[ies] whenever missingOracleCaseIds() is non-empty" — **but no production caller existed** (grep: defined in dod.ts, referenced only in gates.test.ts). `generateCases` (verify.server.ts:512-588 pre-fix) built its prompt from brief + source + grounding and never saw the A7 rows; `verifyAndFixServer` could mint a machine pass from a case list that silently dropped a pinned oracle row. The A7 oracle was decoration.

## The fix (A4 mode b — the transitional LLM-case path)

verify.server.ts deliberately never imports dod.ts (it also duplicates codegen helpers to stay import-free, e.g. `oracleSignatureFunctionNames`), so the seam is parameter-passed exactly as 158-s2 A4 prescribes: **caller renders the seed string + id list and passes both in**. Wiring is entirely additive:

1. **New pure export `buildOracleCasesPrompt({source, brief, signatureNames, seeds})`** — the E-08 prompt builder. `seeds` (the `oracleToCaseSeeds()` string) is PREPENDED as a `PINNED A7 ORACLE ROWS (E-08)` block above the legacy instructions; the legacy body is byte-identical to the pre-fix prompt. Empty/undefined/whitespace `seeds` ⇒ the exact pre-fix prompt (no seed block, no stray bytes) — the no-oracle project keeps full byte parity. Exported so tests inject the prompt-builder directly.
2. **New pure export `droppedPinnedOracleIds(returnedIds, pinnedOracleIds)`** — verify-side mirror of dod.ts `missingOracleCaseIds()` over the id list the caller passes (extra returned ids ignored; only pinned rows matter; seed order preserved). Same semantics as the dod helper it mirrors; dod.ts untouched.
3. **`generateCases(source, brief, signatureNames, seeds = "", pinnedOracleIds = [])`** — prompt now goes through the builder; after the model payload parses (incl. the existing audit-88 malformed-JSON repair retry), a NEW E-08 gate runs: any pinned id dropped from the returned case list ⇒ one bounded repair retry naming the missing ids, then an honest `{ok:false, reason:"error"}` refusal (`"…dropped pinned A7 rows: orc-2 — refused (E-08 pin: never a blind pass on a reduced oracle)"`). The repair reply is MERGED over the originals by id (a repair may return only the missing rows; self-authored steering cases are never lost).
4. **`verifyAndFixServer(…, opts {seeds?, pinnedOracleIds?})`** — forwards both to generateCases. Because generateCases refuses before returning, the loop can never run — let alone mint a pass on — a reduced oracle; the refusal surfaces through the existing honest error mapping as `status:"error"`, `iterations:0`, evidence naming the dropped ids, with its L3 lesson. A second in-loop re-check was deliberately NOT added: it would be unreachable by construction (any list verifyAndFixServer receives already passed the gate) — exactly the kind of dead seam this fix exists to kill.
