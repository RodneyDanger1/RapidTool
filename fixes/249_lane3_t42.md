## §2 What landed — module design (load-bearing decisions)

Exports: `checkGitLandSeat`, `gitLandInit`, `gitLandCommit`, `gitLandReadBack`, `gitLandingAvailable`,
`runBoundedChild` (bounds test-DI, exec.ts precedent: "dependency injection for tests only"),
`verifyGitPlan`, `isGitLandingSubcommandAllowed`, `GIT_LANDING_SUBCOMMANDS`,
`GIT_LANDING_MARKER_{REL,KIND,VERSION}`, `GIT_LANDING_TIMEOUT_MS`, `GIT_LANDING_OUTPUT_CAP`,
`DEFAULT_GIT_LAND_IDENTITY`.

- **Seat — human-only.** Every mutating call takes an explicit `seat` argument (no default). The claim
  is routed through `evaluatePolicy("repair.apply", "tree:<dir>", …)` (the seam the CLI `edit` arm
  uses), then tightened: only the recognized human seat (`decidedBy:"human"` /
  `human-cli-i-am-human`) presenting the out-of-band token passes (`isVerifiedHumanSeatToken`).
  Autopilot is allowed by the seam for `repair.apply`; this module refuses it — a machine never mints
  git history. Pure + total (`checkGitLandSeat`: malformed input refuses, never throws).
- **Host-repo guard — structural, not discretionary.** (a) `dir` REQUIRED, absolute, no cwd default;
  (b) init refuses any target inside an existing work tree (`rev-parse --show-toplevel`) or carrying a
  `.git`; (c) commit lands only repositories **this tail initialized** — proven by the
  `.rapidtool/landing.json` marker `gitLandInit` writes. A foreign repo root (host repo included) is
  uncommittable even with a valid seat; pinned, including a test that hands the host repo root in.
- **No network / no secrets.** Fixed allowlist `--version, rev-parse, init, add, commit, status, log`
  (mutators exactly `init, add, commit`); `verifyGitPlan` over every argv array; no URL argument
  exists; child env = `scrubbedEnv()` + neutral HOME + `GIT_CONFIG_NOSYSTEM=1` +
  `GIT_TERMINAL_PROMPT=0` + `LC_ALL=C`; identity rides `-c` flags only (no config file ever written).
- **argv arrays only.** `spawn(bin, argv)`; no shell string anywhere — pinned by a source-guard test
  (no shell flag; only `spawn` imported from node:child_process; no exec/execSync/execFile; no
  network-verb token in the source).
- **Bounded.** Wall-clock timeout (30 s default) with tree-kill (`taskkill /T /F` on win32) and
  close/kill grace settlement (node-runner H4 pattern); stdout/stderr capped + elided with a marker.
  Both bounds exercised by REAL tests: a genuinely hanging node child is killed at the deadline; a
  1.2 MB stdout bomb is clamped.
- **Coded failures.** `RT_E_GIT_UNAVAILABLE` (git absent ENOENT / binary that is not git),
  `RT_E_RUNNER_FAILED` (timeout / killed / spawn failure / exit≠0), `RT_E_VALIDATION` (seat refusals,
  guards, bad input, clean-tree no-op), `classifyError` (marker-write errno family).
- **Identity determinism (row trap).** The commit always carries an explicit identity via `-c`
  (default `RapidTool Landing (machine) <landing@rapidtool.invalid>` — a declared machine identity);
  ambient global config cannot leak (system config off, HOME = bare temp dir). Pinned by an
  author-assertion test.
- **The named probe, pinned.** `gitLandReadBack` (HEAD, commits, unborn branch read from git's own
  `.git/HEAD`) plus the raw `git log --oneline` read-back on the scratch tree — both asserted in the
  commit test (the playbook's "name one … pin it in the test").
