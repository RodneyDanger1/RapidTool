## BOTTOM LINE (read first)

- **What RapidTool already has that these two factories advertise as their safeguards — and
  has *stronger*:** a deterministic state machine that owns every transition (`canEnter` /
  `priorsSealed` deny phantom phases, `src/lib/phases.ts:126-148`); a machine-checkable DoD
  gate registry with per-gate probes + FNV-1a `evidenceHash` re-verification (`dod.ts`);
  HITL approval with **mandatory feedback** + rejection history + retry (`engine.ts:1515`
  `approveHitl`, `:1608` `rejectHitl`, `:1667` `unlockRetry`); an append-only decision ledger;
  item-level import sanitizing + hydrate repair (`io.ts:108`, `engine.ts:1967`); per-seat
  output budgets for every live-crew/swarm role (`crew.server.ts:124-135` `budgetTokens`);
  classified `RT_E_*` error codes + telemetry ring (`errors.ts`, `rt-events.ts`); a bounded
  runner on a fresh temp dir per execution (`node-runner.server.ts:10-23`). **Do not re-add
  what the state machine already serializes** (167B-5/6/7 are "present — don't build" findings
  with small deltas only).
- **Genuinely missing — four concrete safeguards the canonicals have and RapidTool does not:**
  1. **A journey-level budget/cost guard on the ENGINE path** (MetaGPT `invest()` →
     `max_budget` → `NoMoneyException`). The crew layer has one (`crew.server.ts:910-985`,
     honest `stopped: "cost-limit"` partial transcripts); the engine's keyed synthesis path
     has **zero** token/cost accumulation — LLM `usage` is surfaced by `deepseek.server.ts`
     and then dropped (167B-1).
  2. **A reviewer-must-pass gate at code-adoption time.** MetaGPT runs `WriteCodeReview`
     *before* `repo.srcs.save` (`engineer.py:129-142`); ChatDev loops review→modify until the
     reviewer is done (`composed_phase.py:203-217`). RapidTool's crew reviewer is explicitly
     advisory (`crew.server.ts:113` "You are advisory…") and its verdict artifact is ingested
     but **never consumed**; the engine's only LLM review (`resolveWildReview`,
     `engine.ts:3232`) gates phase *advance*, not artifact *merge* (167B-2).
  3. **Crew transcripts + per-turn usage are ephemeral — never serialized onto the
     Project.** ChatDev writes every phase result to disk (`chat_env.py:171-174`
     `rewrite_codes("Review #N Finished")`); MetaGPT serializes the whole Team incl. cost
     manager. RapidTool keeps the crew log only in component state (`console.tsx:1143`) and
     ingests a 400-char summary + artifacts; the run's messages and token spend vanish
     (167B-3). This is RapidTool's real "lost message" class — not bus loss, transcript loss.
  4. **Engine-layer failures are swallowed without attribution.** `runPhaseAsync`
     (`engine.ts:3051-3058`) catches *everything* and silently returns the deterministic
     floor — no `RT_E_*` code, no telemetry event, no role/step attribution. MetaGPT wraps
     every `Role.run` in `@role_raise_decorator` (typed role failure); ChatDev phases raise
     named-role `ValueError`s (167B-8).
- **Cross-cutting:** 167B-1 pairs with 162 §13.3-item-3 (no journey deadline — the budget and
  the deadline belong in the same guard). 167B-2 pairs with 162 §13.4's dual-representation
  fix (both are "adopt a wrong artifact" classes) and with A7's repair loop. 167B-3 pairs with
  Phase E's paper-trail honesty (an audit that cannot replay a crew run is not a full paper
  trail).

## Findings

### 167B-1 — No journey-level budget/cost guard on the ENGINE path (MetaGPT `max_budget`/`NoMoneyException`)

- **WHAT the canonical does**: MetaGPT treats the run as a funded company: `Team.investment`
  defaults to $10 (`team.py:41`), `invest()` sets `cost_manager.max_budget` and **raises
  `NoMoneyException` when `total_cost >= max_budget` before the run starts** (`team.py:92-100`);
  every LLM call books tokens through `CostManager.update_cost` with per-model pricing
  (`utils/cost_manager.py:30-56`); the cost manager rides inside `Context` and is serialized
  with the team (`context.py:66,102-110`); `Team.run_project` publishes the requirement as a
  message (`team.py:102-107`). ChatDev keeps a per-run cost ledger derived from the log
  (`statistics.py:6-36` per-model prompt/completion price maps).
- **WHY it matters**: without an aggregate guard, a keyed run's spend is bounded only
  per-call (`P6_SYNTH_MAX_TOKENS` 32 000, `codegen.server.ts:107`; 2 synthesis attempts,
  `:784`) — the journey can retry/repair/verify/wild-loop without any total-token or total-cost
  ceiling, which is exactly the unbounded-run failure 162 §13.3-item-3 flags for wall-clock.
  MetaGPT's `NoMoneyException` makes "out of money" a **first-class typed stop**, not a
  surprise.
- **RapidTool status**: PARTIAL — and the split is telling. The **crew** layer has the real
  thing: `maxTotalTokens` (60 000) + `maxPromptTokens` + a **pre-dispatch worst-case cost
  guard** (estimates the next turn's prompt-hi + role `budgetTokens` before dispatching,
  `crew.server.ts:973-985`), honest `stopped: "cost-limit"` partial transcripts
  (`crew.server.ts:926-934`, `crew.ts:93`), and per-run usage accumulation
  (`crew.server.ts:1023-1028`). The **engine** path has none: `engine.ts` contains **no
  usage/prompt/completion accounting at all** (grep empty), even though every LLM call site
  already receives `usage.prompt_tokens/completion_tokens` (`deepseek.server.ts:420-432`) —
  the numbers are read and thrown away.
- **WHERE to add**: engine-side, not crew-side. The keyed journey's entry points are
  `engine.ts` `runPhaseAsync` (:3051) → `liveLayer` (:2674) → `upgradeP6Keyed` (:2636) →
  `codegen.liveP6Synthesis`, plus the store wild-driver loop (`store.ts:1067-1090`). Budget
  state must live where the project lives: an additive `usage` accumulator on `Project` (or a
  per-phase record field), mirrored by `io.ts` sanitize + `hydrateProject` like every other
  project field.
- **HOW TO CODE** (RapidTool-idiomatic — mirror the crew contract, keep the honesty rules):
  1. Add `usage?: { promptTokens: number; completionTokens: number; maxTotalTokens?: number }`
     to `Project` (types.ts) + hydrate/io arms (drop-with-token on malformed, never half-apply —
     the `generatedTree` precedent).
  2. Add a pure `accountUsage(project, usage)` + `journeyBudgetExhausted(project)` pair in
     `engine.ts` (pure, unit-testable, colocated test like `phases.test.ts`).
  3. At the synthesis dispatch sites that receive `res.usage` (surfaced by
     `deepseek.server.ts:420-432`; the keyed path is `codegen.liveP6Synthesis`, reached from
     `upgradeP6Keyed`), accumulate before returning the upgraded project; pre-dispatch
     worst-case check identical in spirit to `crew.server.ts:976-985` (estimate next call hi +
     maxTokens vs remaining budget).
  4. On exhaustion return the honest state: a new code `RT_E_BUDGET_EXHAUSTED` in
     `errors.ts`'s registry (+ `ERROR_CODE_DOC` entry), a `wildLog`/telemetry event, and a
     project stamped `{…, lastSynthesis: {…, stoppedReason: "budget"}}`-style — never a throw
     into the run (the engine never throws on the floor path; cf. `runPhaseAsync`'s contract).
  5. Tie the wall-clock deadline from 162 §13.3-item-3 into the same guard object so budget
     and deadline share one "journey cap" concept.
- **HOW TO TEST**: pure unit tests for `accountUsage`/`journeyBudgetExhausted` (cap hit at
  exactly N tokens, malformed `usage` never throws); an engine test with an injected
  `LiveLayerDeps` whose fake `complete` returns usage: a project whose accumulator + next-call
  worst case exceeds `maxTotalTokens` must **not** dispatch another call and must land the
  `RT_E_BUDGET_EXHAUSTED` state; io round-trip: `usage` survives export/import byte-parity and
  a malformed `usage` field is dropped with the token. Regression: keyless floor unchanged
  (no usage field ever written).

### 167B-2 — Reviewer verdict does not gate code adoption (MetaGPT review-before-save; ChatDev review loop)

- **WHAT the canonical does**: MetaGPT's Engineer, when `use_code_review` is on, runs a
  dedicated `WriteCodeReview` action and **only then** saves to the repo
  (`engineer.py:94`, `_act_sp_with_cr`: review at :129-134 precedes `repo.srcs.save` at
  :142); the Engineer watches `[…, WriteCodeReview, FixBug, …]` (:106) so a failing review
  drives a fix cycle rather than a merge. ChatDev's `CodeReview` composed phase
  (`composed_phase.py:203-217`) runs `CodeReviewComment` → `CodeReviewModification` per cycle
  and only breaks when the modification concludes with the reviewer's `<INFO> Finished`
  marker (:213-217); a modification reply without a ``` fence is **not** written into the
  workspace (`phase.py:456-476` — code adoption is fence-gated).
- **WHY it matters**: an LLM-produced artifact that passes its own self-tests can still be
  dishonest/wrong against the brief (the 162 §0 overfitting corollary). Both factories close
  that with an LLM review *at merge time*. RapidTool's machine gates (p6-test, treeRun) can't
  judge brief-fidelity — only a reviewer can — yet nothing consumes a reviewer verdict.
- **RapidTool status**: ABSENT at adoption. The crew reviewer is **advisory by design**:
  `crew.server.ts:113` ("You are advisory. Your output is ingested as an [agent report]…"),
  and the console ingests the whole run via `ingestReport` regardless of any reviewer FAIL
  (`console.tsx:1394-1446`). The **only** LLM review that gates anything is the wild-driver
  classifier (`resolveWildReview`, `engine.ts:3232-3281`), and it gates *advance/approval
  decisions* — not whether synthesized code is merged. The codegen path adopts
  `liveP6Synthesis` output and repairs only on machine failure
  (`codegen.server.ts:738` synthesize-or-repair, `P6_SYNTH_MAX_ATTEMPTS = 2` :784).
- **WHERE to add**: (a) the codegen adoption site (`codegen.server.ts` `liveP6Synthesis` —
  coordinate with Phase A/A7 ownership); (b) a structured consumption seam in
  `report-intake.ts`/store so a `review` verdict artifact is parsed, not just stored.
- **HOW TO CODE** (keep the honesty contract — deterministic DoD stays the ruler; the LLM
  review is a *recorded, bounded* pre-adoption gate):
  1. Define a verdict envelope on the existing reviewer wire format (already JSON:
     `crew.server.ts` `JSON_ROLES` includes `reviewer`, :73): `{verdict: "PASS"|"FAIL",
     defects: [{artifact, why, fix}], evidence: string[]}`.
  2. In the codegen repair loop, before the final adoption of a synthesis that passes
     machine gates, **attempt** one reviewer pass (role `reviewer` spec, `budgetTokens`
     4096) with the diff-scoped context already built (`crew.server.ts:341-354` bounded
     change-summary for reviewer). FAIL with concrete defects → one bounded re-synthesis
     cycle seeded with the defects (mirror `P6_SYNTH_MAX_ATTEMPTS`), then re-review; a second
     FAIL is recorded honestly (project + ledger + `wildLog`) and the artifact is adopted
     **only** with a `review: "failed-after-N"` marker — never silently. Keyless → skip with
     the existing honest no-key envelope (never fabricate a review; follow
     `resolveWildReview`'s not-configured floor, `engine.ts:3260-3279`).
  3. The crew path stays advisory for the *phase narrative*, but a `review`-type message
     whose verdict is FAIL must now be readable by (b) so the engine/wild driver can treat it
     as repair seed.
- **HOW TO TEST**: unit: parse a reviewer JSON verdict (PASS/FAIL + defects) off the wire —
  malformed verdicts degrade to "unreviewed", never a crash; engine/codegen test with an
  injected reviewer dep returning FAIL-defects then PASS: assert exactly one bounded
  re-synthesis occurred seeded with the defect text and the final record carries the review
  trail; keyless run asserts the honest skip marker; regression: existing crew.test.ts
  (roles ↔ ACTIVE_BY_PHASE parity) and gates stay green — machine gates unchanged.

### 167B-3 — Crew transcripts + per-turn usage are ephemeral (never serialized onto the Project)

- **WHAT the canonical does**: ChatDev's `ChatEnv` is a workspace object every phase writes
  through; each code-producing phase persists its result to disk with a phase stamp
  (`chat_env.py:171-174` `update_codes`/`rewrite_codes("Review #N Finished")`; the
  WareHouse dir is named project_org_start_time, `chat_chain.py:188-230`). MetaGPT treats
  messages/artifacts as serializable models and ships whole-team serialization including the
  cost manager (`context.py:102-110`, `team.py:59-79` `serialize`/`deserialize`).
- **WHY it matters**: an audit trail that cannot replay the multi-agent run is not the full
  paper trail the honesty contract promises. RapidTool's packet cites artifacts, but the
  *chain* — who said what, to whom, at what token cost, in what order — disappears on reload;
  usage that would feed 167B-1's accumulator is dropped at ingest; re-runs can't be compared.
- **RapidTool status**: ABSENT. `CrewSession` lives only in orchestrator memory
  (`crew.server.ts:898-908`) and component state (`console.tsx:1143` `crewRun`); the only
  thing persisted is `ingestReport` with `artifacts` + a **400-char** summary
  (`console.tsx:1417-1429`) as `[agent report]` rows. Per-turn `usage` is accumulated in the
  session (`crew.server.ts:1023-1028`) and then discarded. Every message's `to` is mapped to
  `""` (`console.tsx:1408`) — the wire type declares addressing, the data never carries it.
  The `messages[].content` bodies (often the valuable reasoning) are dropped except inside
  the 400-char summary.
- **WHERE to add**: `report-intake.ts` (extend the validated report shape) + `store.ts`
  `ingestReport` + `io.ts` sanitize + `engine.ts` hydrate — the same four-file seam every
  other persisted field uses.
- **HOW TO CODE** (additive, byte-parity-safe): extend the report payload accepted by
  `validateReport` with an optional `transcript?: { seq: number; role: CrewRole; type:
  CrewMessageType; to: string; artifactTitles: string[]; promptTokens: number;
  completionTokens: number }[]`; `applyReportResult` stores it on the phase record (or a
  project-level `crewLog` array, mirroring how `rejectionHistory` is kept per phase); console
  `onSpawnCrew` maps the real per-turn usage (drop the `to:""` hardcode — see 167B-5) instead
  of a bare summary when a transcript is present (keep the 400-char summary for legacy
  payloads → byte-identical old exports); io/hydrate coerce-or-drop malformed rows with a
  `crewLog:dropped` token.
- **HOW TO TEST**: io round-trip — project with a populated crewLog survives export/import
  byte-parity, and a transcript row missing `seq` is dropped with the token; store test —
  `ingestReport` with a transcript persists all turns + usage and the phase record's gate is
  untouched (crew stays advisory); legacy payload (no transcript) serializes identically.

### 167B-4 — Per-seat budget discipline: PRESENT where roles run — do not re-add; extend only the accounting (see 167B-1)

- **WHAT the canonical does**: MetaGPT bounds a role's *reaction loop* (`max_react_loop`,
  `roles/role.py:113,273-280` "prevent the agent from reacting forever"; enforced in
  `_react`'s `while actions_taken < max_react_loop`, :454-461) and shares one cost manager
  across all roles. ChatDev bounds *turns per phase* (`max_turn_step`, `chat_chain.py:135-139`)
  and *cycles per composed phase* (`cycle_num` loop, `composed_phase.py:119+`).
- **RapidTool status**: PRESENT — genuinely good. Role decomposition is deterministic and
  tested: 13-phase × `CREW_ROLE_BY_PHASE` table (`crew.server.ts:146-160`) proven consistent
  with the packet seats (`crew.test.ts`, `toAgentRole` :201-212); **every** seat has a
  `budgetTokens` output cap (`crew.server.ts:124-135`, swarm seats too, `swarm.ts:94`);
  `maxSteps` clamps 1..24 default 12 (`crew.ts:139`, `crew.server.ts:909`); the wild driver
  is one-bounded-macro-action-per-call with a 20-step park cap (`store.ts:1067-1090`, cap at
  :1088). The engine has no unbounded role loop to guard.
- **Conclusion**: no new per-seat cap is needed. The only per-seat gap is that engine-side
  LLM sub-calls (liveLayer/codegen) have per-call `maxTokens` but no *seat-accounted*
  cumulative spend — that is 167B-1's job, not a new mechanism. If a reviewer-must-pass loop
  lands (167B-2), give it the same `cycle_num`-style bounded cycles ChatDev uses rather than
  an unbounded review loop.

### 167B-5 — Message bus / environment: RapidTool does NOT need pub-sub — but the addressing field and per-turn artifact ledger are vestigial

- **WHAT the canonical does**: MetaGPT's `Environment` is a real router: roles register
  addresses, `publish_message` delivers to matching `member_addrs` and **logs a
  "Message no recipients" warning when a message routes nowhere** (`base_env.py:175-192`);
  each role keeps a private `msg_buffer` and filters observations by `watch`
  (`role.py:284-290,399-448`). ChatDev's "bus" is the shared `ChatEnv.env_dict` every phase
  reads/writes.
- **WHY RapidTool should NOT copy it**: the sequential orchestrator (`crew.server.ts:930`
  `while (idx < roles.length && step < maxSteps)`) makes async lost-turn delivery
  structurally impossible, and the deterministic state machine already owns transitions —
  an async pub-sub layer would *reintroduce* the message-loss class it would claim to fix.
  This is a case where RapidTool's architecture is safer; say so in the dossier and don't
  build.
- **But two small deltas ARE worth porting** (both cheap, both honest-contract-adjacent):
  1. **The `to` field is dead.** Every console-mapped turn hardcodes `to: ""`
     (`console.tsx:1408`) while the wire type and MetaGPT's whole addressing model exist to
     answer "who is this for?". Fill it deterministically: next seat in the phase's role
     sequence (`CREW_ROLE_BY_PHASE[idx + 1]`, last turn → `"packet"`/`final`), or delete the
     field. MetaGPT's no-recipient *warning* has no RapidTool analog because there is no
     routing — but a transcript whose every `to` is empty is the same silence.
  2. **Cross-run artifact collisions are silent.** Crew artifacts dedupe "by exact title"
     within a session (`crew.ts:73`) but nothing prevents two runs from landing identical
     `[agent report]` titles as separate rows — ingested reports apply via
     `applyReportResult` and can diverge from a prior run's artifact without a
     title+hash conflict signal. Port the intent of MetaGPT's no-recipient log: a
     deterministic `report:dup-titles` token/warning on ingest when the same title with a
     different body is applied twice (mirrors the `[agent report]` honest-footer pattern).
- **WHERE**: `console.tsx:1404-1411` (fill `to` from the phase table — pure helper in
  `crew.server.ts` next to `rolesForPhase`), `report-intake.ts` (dup-title detection).
- **HOW TO TEST**: unit — `to` chain of a transcript equals the phase's role sequence for a
  representative phase; store/report-intake test — two ingests with the same title, different
  bodies produce the dup token and both rows are distinguishable; regression — crew.test.ts
  parity tests stay green.

### 167B-6 — Human-in-the-loop: PRESENT and stronger than both canonicals — do not re-add

- **WHAT the canonical does**: ChatDev's `CodeReviewHuman`/`HumanAgentInteraction` let a human
  inject bug reports/features into a bounded `cycle_num` of feedback rounds
  (`phase.py:478-530`, `composed_phase.py:220-235`; `--config "Human"` mode, README).
  MetaGPT relies on role prompts, not a hard HITL phase.
- **RapidTool status**: PRESENT — stronger. Four phases are hard HITL (`hitl: true` on P4/P5/
  P8/P9, `phases.ts:42,50,74,82`; `HITL_PHASES` :150); `approveHitl`/`rejectHitl`
  (`engine.ts:1515,1608`) require a feedback note on rejection; rejection evidence is fed
  back into the next attempt's prompt (`crew.server.ts:230-246` gateEvidenceBlock +
  rejectionHistory); `unlockRetry` (:1667) governs retries; the console has a forceHuman
  override gate with a reviewed-the-failure checkbox (165A-3). ChatDev's bounded human
  feedback rounds == RapidTool's reject→retry-with-rejection-evidence loop.
- **One tiny inconsistency to note (not a build)**: `CrewSession.status` declares
  `"blocked-hitl"` (`crew.ts:83`) but no crew path ever emits it (only engine gates block).
  Either wire a human pause between crew turns (Phase D nicety) or strike the dead status —
  declare-or-strike applies to type surfaces too.
- **HOW TO TEST** (if touched): a store test that a forceHuman P5 gate blocks the crew ingest
  path with `blocked-hitl`, or delete the union member + update `crew.test.ts`.

### 167B-7 — Workspace isolation + clean slate per run: PRESENT — the divergence bug class is the real gap (already 162 §13.4)

- **WHAT the canonical does**: ChatDev gives every run its own WareHouse dir named
  `project_org_starttime` and, when a dir already exists, **backs it up to a timestamped copy
  before wiping** (`chat_env.py:82-98`); `pre_processing` clears stale non-software files
  when `clear_structure` is set (`chat_chain.py:188-230`). MetaGPT gives each project a
  git-backed `repo` workspace with per-role docs.
- **RapidTool status**: PRESENT with better honesty. Every execution runs on a **fresh
  `mkdtemp` scratch dir** with best-effort cleanup and an explicit "courtesy, not a jail"
  contract (`node-runner.server.ts:10-23,99-111`); treeRun/spec runs copy the emitted tree to
  a temp cwd (`compile-check.server.ts:24-28,287,461`, 30 s `DEFAULT_RUN_TIMEOUT_MS`);
  phase artifacts are recorded per phase with gate artifacts swapped in by `recordGateInto`.
  RapidTool does not need ChatDev's backup-and-wipe because it never mutates a shared
  workspace — the project object *is* the state.
- **The actual gap is the one 162 §13.4 already names**: the
  `generatedSource`/`generatedTree` dual representation is the RapidTool analog of ChatDev's
  stale-workspace bug class (a prior run's artifact surviving into the next). 167-B
  corroborates §13.4-item-4 (single writer + `representation:reconciled` token) and adds
  nothing new — do not re-add workspace machinery, fix the representation invariant instead.

### 167B-8 — Error propagation: classified codes exist; role/step attribution does not reach the surface

- **WHAT the canonical does**: MetaGPT wraps every `Role.run` in `@role_raise_decorator`
  (`role.py:529`) so a failure is a *typed role* failure, and the team run is wrapped by
  `handle_exception` (`utils/exceptions.py:20`) which maps raw errors onto the typed set
  (NoMoneyException etc.). ChatDev phases raise named-role errors (`ValueError(f"{assistant_role_name}
  not recruited in ChatEnv.")`, `phase.py:93-95`; `ValueError("No Valid Codes.")`,
  `phase.py:362`), and runtime bugs are caught by *execution*: `exist_bugs()` runs the code,
  captures `error_output`, and feeds it back (`chat_env.py:107-148`).
- **RapidTool status**: PARTIAL — codes yes, attribution no. The `RT_E_*` registry +
  `classifyError` are excellent (codes `errors.ts:23-44`; classification mapping doc + fn
  `:61-132`, incl. LLM timeout/reject/runner classification) and runtime telemetry stamps
  machine-first event/code/scope fields (`rt-events.ts`). But two attribution holes:
  1. `runPhaseAsync` catches **everything** and silently returns the deterministic floor
     (`engine.ts:3051-3058`) — no code, no event, no phase/step in the telemetry. An LLM
     failure inside a keyed phase is indistinguishable from "the floor ran".
  2. A crew call failing mid-run returns `{ok:false, reason:"error", error}` without naming
     the failing **role or step** (`crew.server.ts:996-1001`); the console then reports "a
     crew call failed mid-run" (`console.tsx:1454`). Contrast MetaGPT: the failure names the
     role that threw.
- **WHERE**: `engine.ts:3051-3058` (the catch), `crew.server.ts:996-1001` +
  `completeCrewTurn` error path, console copy at `console.tsx:1454`.
- **HOW TO CODE**: (a) in `runPhaseAsync`'s catch, keep returning the floor but first stamp
  the failure: `classifyError(err, { fallback: "RT_E_INTERNAL" })` + `reportRt`-style
  telemetry (the `wildLog` pattern at `engine.ts:3284`) with phase + step context — telemetry
  must never throw into the observed code (purity rule); (b) in the crew loop, catch per-turn
  (already one turn per `completeCrewTurn`) and wrap: error message prefixed
  `role=<role> step=<idx>/<roles.length>` and, when classifiable, the `RT_E_*` code on the
  returned object; (c) surface that in `console.tsx:1454` copy ("…failed mid-run at role
  reviewer, step 3/4 (RT_E_LLM_TIMEOUT)…").
- **HOW TO TEST**: engine unit test with an injected throwing dep through `liveLayer` →
  `runPhaseAsync`: asserts the floor project is returned **and** a telemetry/ledger record
  carrying the code + phase exists (no throw, no silent pass); crew test with a
  `complete` mock that fails on the reviewer turn: the `ok:false` result's error names
  `role=reviewer` and the step index; existing errors.test.ts classification coverage
  unchanged.
