## Findings

### 169A-1 — No existing-codebase / "continue on this repo" ingestion path (create is fresh-brief-only; importTreeDir is a ledger re-import, not a repo reader)
- **WHAT**: RapidTool cannot accept an existing codebase — a directory, a zip, or a repo — to
  EXTEND or MODIFY. Its only project-input verbs are: `create` (a fresh brief, rapidtool-cli.mjs:381),
  `ingest` (a *phase report* JSON from a previous run's agent, :539 — not code), and the UI's
  JSON import (project-ledger round-trip). OpenHands' core premise is an existing workspace:
  every conversation carries a `workspace.working_dir`, the home screen has an
  open-workspace dialog + folder browser + workspace-mode selector + remote-workspace service
  (`open-workspace-dialog.tsx`, `folder-browser-modal.tsx`, `workspace-mode-selector.tsx`,
  `workspaces-service.api.ts`); files land in that worktree and the agent edits them in place.
  gpt-engineer has a dedicated improve mode (`handle_improve_mode`/`improve_fn`, steps.py) that
  diffs and edits the user's existing files. SSSF is *defined* by in-repo operation: every
  `kind="code"` phase owns a git branch/commit and `changes.capture(base="main")` diffs the
  working tree into `context_handoff/changes.diff` for the next agent (create_adw.md, Step 1).
- **WHY it matters**: the top factories' unit of work is "a repo I already have"; RapidTool's
  unit of work is "a brief". That caps every competitive comparison ("can it take my
  codebase and add X?") at *no*. The honest-bar framing of 162 §0 is untouched — this is
  about the *input* half of input→output.
- **HAS-IT (grep evidence, this session)**: the nearest seam, `importTreeDir`
  (headless.ts:1557), iterates `project.generatedTree` rows only — for each row it reads the
  file at that row's own path inside `dir` and rebuilds the row (fnv1a hash; changed = real
  edit, headless.ts:1548-1556). Rows outside `REPAIR_TREE_ALLOWED_ROOTS`
  (`src/api|domain|jobs|state|ui|generated`, `tests/`; headless.ts:1490-1498) or matching
  `REPAIR_TREE_RESERVED` (`tests/oracle.spec.ts`; :1503) are **refused** — a pre-existing repo's
  `package.json`, `README.md`, `public/`, `server/` files would all be refused. It is invoked
  only as advisory `tree-run --project` divergence context (rapidtool-cli.mjs:775-790) and in
  `repair` — it never creates a project, never walks an unknown dir, never seeds a brief. The
  seam's own comment says it: "fixes/149 P0-1 — the emit→edit→re-emit continuation seam"
  (headless.ts:1466-1485). It is a *ledger re-import*, exactly as suspected. `ingest` reads a
  report JSON (rapidtool-cli.mjs:546-560) and rejects anything that is not valid JSON with a
  phase payload (`RT_E_REPORT_INVALID`). UI import = single ledger JSON (console.tsx:1531).
- **WHERE**: new pure module `src/lib/codebase-source.ts` (or extend `io.ts`); new Project
  field (types.ts) e.g. `existingSource?: { rootLabel: string; files: { path: string; body: string; hash: string }[] }` —
  deliberately NOT reusing `generatedTree` (whose path discipline is emission-scoped); engine
  hydrate + io sanitizer arms (mirror the `generatedTree` normalization, io.ts sanitize
  import); new CLI case `create --from-dir <dir>` (rapidtool-cli.mjs, next to `create`) and/or
  `source add-dir`; UI picker next to the brief composer.
- **HOW-TO-CODE**: (1) walker must be a **pure function taking an injected fs-like reader**
  (client-bundle guard: no `node:fs` in client-safe modules — AGENTS.md) so it is unit-testable
  and reusable server-side; default denylist mirrors gpt-engineer's FileSelector
  `IGNORE_FOLDERS = {site-packages, node_modules, venv, __pycache__}` (file_selector.py) plus
  `.git`, `dist`, `.rapidtool`, `.vercel`; honor a `.gitignore`-lite allow-list; refuse
  symlink/traversal/absolute paths with the SAME refusal discipline as `repairTreePathRefusal`
  (headless.ts:1512-1530 — copy the shape, widen the allowed roots to "any repo-relative path
  not on the denylist"). (2) Cap: total chars ≤ `IMPORT_MAX_CHARS` (io.ts:31, 10_000_000) with
  an honest per-file overflow token (never silent truncation — AGENTS.md honesty contract);
  hash each file (fnv1a, parity with evidence hashing). (3) Honesty: the brief stays the
  user's; the source tree rides as *context* — phase prompts (prompt-engine.ts) and the
  packet's scope section reference `existingSource` files by path; the keyless floor must
  state "I validated file bookkeeping only; I never implemented the brief" and **must not**
  pretend it read the codebase. (4) `create --from-dir` = walk → build brief
  `"Extend/modify the codebase at <rootLabel> per the attached prompt"` → attach source → run
  phases as today; `repair`-style tree application of LLM edits to the source dir is a
  **later** phase (needs the P6 journey seams), keep this finding to *ingestion + context*.
- **HOW-TO-TEST**: unit — walker over a fixture dir (mixed ok/denied/oversized/traversal
  paths) returns exactly the expected rows + refusal tokens; round-trip: project with
  `existingSource` survives export→import→hydrate byte-identically (io parity test, mirroring
  the generatedTree pins 162 §8.4); CLI — `create --from-dir` on a small fixture repo exits 0,
  packet names the source files; keyless run emits the honest no-op floor text; a file over
  the cap is dropped with a token, never half-applied.
- **162 fold-in**: Phase A input side + Phase D UX; independent of the oracle keystone.

### 169A-2 — No archive output: `export` is JSON-only and no zip/tar code exists in the product (server or client)
- **WHAT**: every file-output surface RapidTool owns reduces to *one JSON string*, *one
  markdown string*, or *a directory written by the CLI*. `export` → `h.exportJson(project)`
  (rapidtool-cli.mjs:649-662; io.ts:34) — `--out` writes a single `.json`. `emit` writes a dir
  (rapidtool-cli.mjs:663; headless.ts:1018 emitProject). Nothing produces an archive a user can
  hand to someone ("here is the whole run + emitted tree as one file").
- **WHY**: zip/tar.gz is the cheapest "take it with you" deliverable; OpenHands treats it as a
  first-class browser primitive — `src/utils/tar-gzip.ts` writes POSIX ustar by hand
  (512-byte headers, octal fields, **fixed mtime 0 so re-uploads are byte-identical**), gzips
  with the platform `CompressionStream("gzip")`, and POSTs `application/gzip`; its
  conversation/transcript export is a modal (`transcript-export-modal.tsx`,
  `utils/transcript-export/`). gpt-engineer's FileStore is archive-shaped too: `push(FilesDict)`
  writes a whole tree, `pull()` globs a dir back to `{path: content}` with binary files read
  as `"binary file"` (file_store.py) — the exact round-trip shape an archive export needs.
- **HAS-IT (grep)**: `grep -rni 'zip|archiver|jszip|adm-zip|createZip|\.zip' src scripts` →
  **zero hits** in the whole product; no tar/gzip/CompressionStream usage; no archive verb in
  the 33-verb dispatch (rapidtool-cli.mjs `case "` list). The ONLY archive-like artifact in the
  repo is a root-level scratch doc (`attachments/RapidTool_Complete_Master.md`) — not app code.
- **WHERE**: (a) CLI `export --zip`/`emit --zip` writing `<slug>.zip` of the export JSON +
  packet md (+ the emitted tree when given an emitted dir) — server-side via `node:zlib`
  (no new dependency; zero-dep floor preserved); (b) client: single-file gzip download of the
  JSON/md via `CompressionStream` needs no dep, and a browser tar writer is a pure module that
  can be shared (see tar-gzip.ts's exact discipline: ustar 100-byte name cap, regular files
  only, deterministic mtime → byte-identical re-download).
- **HOW-TO-CODE**: new pure module `src/lib/archive.ts` exporting `tarHeader(name, bytes,
  mode)` + `packTar(files)` (port the ustar writer — it is ~120 lines, deterministic,
  no deps, and its "fixed mtime ⇒ byte-identical" property matches RapidTool's determinism
  ethos) and `packTarGzip` server variant using `node:zlib.gzipSync` (dynamic import seam —
  client-safe module must not import node:zlib statically, AGENTS.md H2 rule); CLI cases:
  `export --zip --out x.zip` (payload: project.json + packet.md + audit decision log) and
  `emit --zip` (payload: the whole scaffold result `{path, body}[]` from
  `scaffoldProject`/`emitProject`); UI: an "Export .zip" button next to Export JSON
  (console.tsx:1500-1520 downloadJson) using the shared pure packer + CompressionStream;
  name-safety: slug the zip stem via `slugName` (io.ts:374), refuse >100-char paths honestly
  (list them, don't silently drop — mirror scaffold refusal warnings).
- **HOW-TO-TEST**: unit — packTar over fixture files: byte-exact golden output (fixed mtime),
  >100-char name throws with the ustar message, round-trip unpack (node:zlib + a tar reader in
  the test) returns identical bytes; CLI — `export --zip` then unzip in the test and assert
  project.json parses and matches `exportJson`; determinism — two runs byte-identical; UI —
  manual: click Export .zip, unzip, files present.
- **162 fold-in**: Phase B production/deliverables. Note: zip content must NEVER include the
  .rapidtool decision ledger rows that are un-exportable by design — reuse `exportProjectJson`
  exactly so the zip carries the same honest payload the JSON export does.

### 169A-3 — No single self-contained HTML deliverable, and the UI has no one-click software export at all
- **WHAT**: the console's only "export software" affordance is a block of *instructions*
  (ExportSoftwareBlock, console.tsx:5237-5295): it explains that emit "runs in the CLI — the
  emit seam writes folders server-side, and this build lives in this browser, so there is no

  `rapidtool-cli.mjs emit --project … --check`, and `npm install && npm test` inside the

  not a report).
- **WHY**: a single self-contained HTML is the zero-install way to share a governed-run
  deliverable (packet + audit trail + artifact list in one file) — and the repo already
  contains precedent that it is cheap: `packet-e2e.md`, `design-e2e.html`, `phases-e2e.svg` at
  root show the team producing standalone review artifacts by hand. Competitors ship
  *interactive* run outputs: SSSF's visualizer is a whole Vue app over the session trace DB
  (`apps/visualizer/src/App.vue` + `public/logo.svg`); OpenHands exports transcripts via modal.
- **HAS-IT (grep)**: no `text/html` Blob, no `download … ".html"`, no self-contained HTML
  renderer in src/scripts; grep `favicon|icon|<title>` in scaffold.ts hits only the emitted
  app's own boot title (scaffold.ts:1389). Root `design-e2e.html` is a hand-authored fixture,
  not generated output.
- **WHERE**: pure renderer `src/lib/html-report.ts` — deterministic HTML string from a
  Project (name, phase table, decision ledger rows, packet body, artifact titles) with inline

  (htmlLine/collapse, single-line collapse + HTML-escape every dynamic insert — the hostile-
  brief escape discipline at scaffold.ts:15-21 must be copied verbatim: a brief containing

  v1 — honest, no client markdown engine needed); deterministic (no Date.now; derive
  timestamps from project fields like scaffold does). Keep it dependency-free and
  client-safe (no node imports).
- **HOW-TO-TEST**: unit — fixture project with hostile brief (`<script>` in name/artifact
  body) → rendered HTML contains the escaped text and no executable `<script` element; golden
  byte test for a fixed fixture (determinism); open-in-browser manual check that the file
  renders offline with zero network requests; CLI round-trip exits 0 and file parses.
- **162 fold-in**: Phase B (deliverables) + Phase D UX (button). This pairs naturally with

### 169A-4 — The emitted scaffold is not a shippable project skeleton: no LICENSE, no .gitignore, no git hygiene — and no in-repo/factory-git posture at all
- **WHAT**: the scaffold (scaffold.ts assembly, :1916-1937) pushes README.md (readmeBody,
  :1918), DEPLOY.md (deplyNotes, :1919), .env.example, package.json, tsconfig.json,
  `.rapidtool/project.json` (ledger export), browser boot files for webapp/game, tree files,
  spec modules, tests/oracle.spec.ts — and **stops**. No `LICENSE`, no `.gitignore`, no
  `.gitattributes`, no git init/commit step anywhere in the emit path (emit writes files only;
  headless.ts emitProject → writeFileSync per file).
- **WHY**: every studied competitor treats git as part of the deliverable, not an afterthought:
  SSSF's whole factory is git-lane based — `kind="code"` phases own a git branch/commit,
  `git_helper.py` in the template, `changes.capture(run, ChangeCapture(base="main"))` diffs the
  worktree into `context_handoff/changes.diff` and hands the diff to the next agent, gates
  include `tests_pass("cmd")` and `diff_matches_claims` (create_adw.md Step 1-2); its repo
  itself ships `.gitignore` + `LICENSE` at root. gpt-engineer calls
  `stage_uncommitted_to_git` (main.py imports from `gpt_engineer.core.git`) and its
  FileSelector is gitignore-aware (`filter_by_gitignore`, `is_git_repo`, file_selector.py).
  OpenHands edits a real worktree that the user can `git status` the moment the agent moves.
  A scaffold without LICENSE/.gitignore is not a repo a user can `git init && push` without
  homework — and an emitted `npm install` tree without `.gitignore` invites committing
  `node_modules/`.
- **HAS-IT (grep)**: `grep -n 'gitignore|LICENSE' src/lib/scaffold.ts src/lib/io.ts
  src/lib/headless.ts` → **zero hits** (the only LICENSE/.gitignore greps in src/scripts land
  in maker-score/run-eval *eval-fixture* code, not emission). No `git init`/commit/`stage`
  verb in the 33-verb dispatch.
- **WHERE**: scaffold.ts root-document block (:1916-1923) — append `LICENSE` + `.gitignore`
  pushes; a later, separate finding-worthy step (not this one): a `git` lane verb that
  inits/commits the emitted dir at phase boundaries (that is SSSF-shape and touches
  headless.ts emit + new CLI verb — flag for a Phase C/D item, do not bundle here).
- **HOW-TO-CODE**: deterministic content, no LLM: `.gitignore` = emitted-kind-aware defaults
  (`node_modules/`, `dist/`, `.env`, `.rapidtool/logs/`, `*.log` — never blanket-ignore
  `.env.example`); `LICENSE` = the MIT text with a deterministic holder line derived from
  project fields ONLY when present, else an honest
  `Copyright (c) <year> <project.name> contributors` + the standard MIT grant (machine-
  generated stamp like `MACHINE_STAMP` at scaffold.ts:103-104 — "regenerate, don't hand-edit"
  keeps the honesty contract). Both must be byte-stable (same Project ⇒ same files) and
  listed in README's emitted-files table (readmeBody rows, :1553-1574 precedent) so README
  never goes stale. Add a `.gitattributes` only if a consumer asks — keep this diff minimal.
- **HOW-TO-TEST**: unit — scaffold fixture: emitted file list now contains `LICENSE` +
  `.gitignore` with expected content; byte-parity pin: the PRE-EXISTING emitted files are
  byte-identical to before this change (the 162 §8.4 discipline — run the existing scaffold
  golden tests unchanged); README table lists the two new files; keyless run unaffected
  (pure emission). Manual — emit, `git init && git add -A`, `git status` shows no
  `node_modules/`.
- **162 fold-in**: Phase B emission. Do NOT touch existing emitted bodies — only add files.
