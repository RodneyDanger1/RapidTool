## 5. New defect this lane's tests exposed (routed) + the suite-side workaround

**Nested `node --test` under a `node:test` host silently fake-passes.** treeRun executes each
emitted spec through a nested `node --test` child. When the HOST process runs under the
node:test runner (any suite via `npm test`), its children inherit `NODE_TEST_CONTEXT=child-v8`
— and a process carrying that var that spawns a nested `node --test` gets **status 0 with no
TAP** (the nested runner reports into the runner's IPC instead of stdout). treeRun then parses
no summary, sees exit 0, and reports `run:"pass"` with `{pass:0,fail:0}` — a fabricated green
for specs whose assertions never ran. Minimal repro (Node v22.23.2, Windows):

- inside `node --test <file>`: `spawnSync(process.execPath, ["--test", failingSpec])` → status 0, empty stdout;
- same call from a plain `node` process → status 1, real TAP (`# fail 1`);
- deleting `NODE_TEST_CONTEXT` from the env of the spawned child restores honest behavior.

Production hosts (terminal CLI, server) never carry `NODE_TEST_CONTEXT`, so `emit --run` in a
real shell is unaffected (C1's live probes §2 ran exactly that way and were honest). The
defect bites only when a test-runner process spawns a consumer. This lane's tests therefore:

- call `treeRun` through a small `treeRunAsConsumer` helper that transiently scrubs
  `NODE_TEST_CONTEXT` (host env of every production caller) and restores it immediately
  (`compile-check.server.test.ts`, documented at the helper), and
- scrub it in the E-25 `runCli` child env so CLI children see a real-terminal environment
  (`headless.test.ts`).

**Routing note (owner: node-runner.server.ts / compile-check.server.ts, or parent):** the
robust fix is to delete `NODE_TEST_CONTEXT` in `runNodeBounded`'s scrubbed child env (and/or
in `specRunnerCode`'s inner `spawnSync` env) so no consumer can ever inherit a child-v8
context — one line, keeps the "never a fabricated pass" contract under every host. Not patched
here (outside this lane's file allowlist).
