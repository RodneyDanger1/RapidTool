## 2 · The design (as built)

- **Precedence, one line:** policy decides *who may decide*; the overlay only narrows *what this
  build permits*. `applyPolicyOverlay` receives a `PolicyVerdict` and returns either **the same
  object** (no match, or a deny input) or a `deny` it builds. It **never constructs
  `{decision:"allow"}`** — widening is unreachable by construction (221 §F4 constraint a), and the
  seat rule under it is never crossed (Rule B pin: an `allowActions` entry for `hitl.force` cannot
  soften the machine seat's `force-requires-human-seat` deny).
- **Codes (each names the action; never generic):**
  `policy.action-off-list:<action>` (not on a declared `allowActions` list) ·
  `policy.action-denied:<action>` (`denyActions`) · `policy.action-ask:<action>` (`alwaysAsk`,
  fallback `human-seat-token`) · `policy.action-list-unreadable:<action>` (malformed ⇒ fail closed) ·
  `policy.action-list-escape:<action>` (a rule naming an action outside the registry, or a queried
  pairing outside the action's namespace ⇒ fail closed).
- **Rule precedence:** unreadable → escape → allowActions → denyActions → alwaysAsk. A deny input
  passes through unchanged and **unlabelled** (a list must not re-label a seat refusal).
- **Reader honesty:** `readPolicyOverlay` reports unknown keys in `ignored` (e.g. the runner's
  `denyCommands`, 221 item 4 — **not** read by this leaf; nothing is silently dropped as if enforced).
- **Console mapping:** the dock asks about the action the click would take — `hitl.approve`
  (Approve), `hitl.force` (override ticked) — on `gate:P<currentPhase>`; `onApprove` (the ONE handler
  for the dock button, the action bar and the `a` shortcut) refuses with the coded line into
  `setError`, and the dock disables the button with an aria-label naming the code.

## 4 · Deviations, honest limits, follow-on seams

1. **`types.ts` / engine consult are NOT in this lane's box.** 221 §F4's full row also declares the
   `Project.wildPolicy` field (types.ts ~:393) and the `wildApproveGate` consult with a
   `wild.paused_policy` coded pause. This lane owns `policy.ts` (+test) and the console region only,
   so the console reads the 221-declared field name **defensively** (`(project as {wildPolicy?: unknown})`)
   — `undefined` = "no narrowing declared". When the engine lane lands the field + consult, this
   becomes typed and the same overlay API serves it unchanged (that is why the signature mirrors
   221's `applyPolicyOverlay(verdict, overlay, action, resource)`).
2. **Why the codes are `policy.*`, not `RT_E_*`:** the `RT_E_*` registry lives in `errors.ts` and is
   pinned by `errors.test.ts` (`ERROR_CODE_DOC` completeness); minting an unregistered `RT_E_*`
   string is the ledger's "unregistered RT_E" defect class, and registering one would be an
   out-of-box edit this lane must not make. A policy refusal is a **verdict**, not a thrown failure —
   it travels as `PolicyVerdict` (+ `code`/`action`) or `PolicyRefusal`, and the module documents in
   code why no generic fallback (`RT_E_UNKNOWN`/`RT_E_VALIDATION`) can stand in for it.
3. **`denyCommands` deliberately unread** by this leaf (runner-seam concern, 221 item 4) and reported
   in `readPolicyOverlay(...).ignored` so a build's rule is never silently dropped.
4. **Not run (forbidden at this boundary):** `npm run typecheck`, `npm test`, `npm run build`.
   Console has no test harness (217c: "console.js testing = UNKNOWN") — its proof here is the
   re-read render path + the probe's exact rendered strings; the new TS surface is exercised by the
   25-test suite plus the consumer suites above. All runs were FOREGROUND (the `stdin is not a tty`
   host artifact never applied).
5. **Observation (pre-existing, not mine):** `git diff` reports `LF will be replaced by CRLF` for
   the two edited files — a repo-wide autocrlf working-copy notice; the diffs are 299/-3 lines, i.e.
   no line-ending churn was introduced.
