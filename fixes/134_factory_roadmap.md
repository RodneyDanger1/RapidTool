## §1 What "autonomous software factory" means operationally

The factory capability loop, as observed in the make journeys and the competitor registers:

```
brief → PLAN (design the software, not the pipeline)
      → WRITE (real multi-file software into a real tree)
      → RUN (execute the produced thing)
      → TEST (brief-grounded checks, machine-run)
      → SELF-FIX (see the failure, repair the artifact, re-run)
      → ITERATE (repeat within a bounded budget)
      → LEARN (this failure permanently improves the NEXT task)
      → SHIP (a runnable, hand-over-able artifact + verdict)
```

A **10/10 maker verdict** (the bar used implicitly by every make dossier: product delivery N/10 + process honesty N/10) means: an independent, real-keyed journey on a **fresh brief** ends with a **runnable artifact that does what the brief says**, backed by **non-vacuous machine evidence**, produced through a loop that **demonstrably repaired its own failures** and **recalled prior lessons** — while process honesty stays 9–10/10. Every capability row in §2 is scored against that definition.

## §4 THE CORE GAP ANALYSIS — six structural changes (not feature lists)

The governed pre-flight workbench converts to a self-driving builder through six **structural** changes. Each is stated as the invariant it establishes, then what exists today, then the concrete shape of the change (sizing and module anchors in §5).

### S-01 — WRITE as a real multi-file tree with file-level edits (not one envelope, not regenerate-and-replace)
- **The structural claim:** a factory writes *files into a tree the model can see and re-edit*; an LLM writing one 60k-char envelope is the single root of the rotating failure class (121: expansion → brief-fit → runtime-binding → oracle). Decomposition to ≤8 functions per synthesis call is the MetaGPT-verified fix (97 §W [W-META]); file-level accountability (per-file hash, per-file repair) is what makes SELF-FIX convergent instead of "regenerate everything and hope".
- **What exists today:** one-shot pro-tier synthesis of a single module (codegen.server.ts:705), repair prompts that re-prompt the *whole* envelope, `generatedSource` string on Project (types.ts:300).
- **What must be built:** chunked sequential synthesis (typeSignatures → groups of ≤8 → N module sources); additive `Project.generatedTree?: {path, source, hash}[]` (content-addressed per file); deterministic assembly into the scaffold layout; an existing pure import scanner (`dependencyGraph`, arch-tools) run as a new `p6-arch` DoD probe (named cycle ⇒ recorded FAIL); attempt-versioned files (N vs N+1 diff) so repair edits one file. Maps: CG-01/CG-02, G-30/G-31/G-33, 121 queued (b).

### S-02 — PARITY: the generated thing IS the run thing (scaffold tree converges with generated core; the tree is what gets compiled and run)
- **The structural claim:** today there are two artifacts that never meet — the isolated machine-verified module and the emitted stub folder (123 CG-07). A factory's acceptance question is "does the produced app run?" — unanswerable while verify runs the module and emit ships un-compiled stubs. Parity = one artifact, verified where it will run.
- **What exists today:** scaffoldProject with kind-aware file flavors + node:test spec files + package.json/tsconfig (scaffold.ts), emitProject writing them + embedding the module (headless.ts:1002), the real bounded node runner (node-runner.server.ts:115).
- **What must be built:** a **compile/run pass over the emitted tree** (compile-check module — `node --check` on emitted CJS/ESM + `tsc --noEmit` on the emitted tsconfig; zero new runtime deps — typescript already a devDep; 129_z1's queued module); running the tree's own `node:test` specs through `runNodeBounded`; the emit report gains a tree-verify verdict; kind-correct core files replace `TODO(E-15)` throws for the slice the factory can honestly produce (library/cli/service kinds first — function modules, CLI entry, storage adapters — webapp UI shells stay declared-stub, honestly labeled, per 90 §7). Maps: CG-07/CG-11, G-20, DF-01/02/03 (wrong-product class), 127 F-X4.

### S-03 — ITERATE-UNTIL-PASS at the journey level, with a bounded budget and an honest stop (a refusal must never seal clean)
- **The structural claim:** "iterate until it works" is meaningless without a driver that owns the budget and an honest terminal state. Today the *loop* exists only inside verify (≤3) and the *journey* seals `complete` no matter what P6 did — so "autonomous" currently means "self-contained failure". The factory needs an outer loop over produce→run→test→repair with attempt/time caps, and when the budget dies it must stop **loudly** (recorded FAIL + HITL with machine evidence) — the honest stop IS part of the feature (mission language; Claude `/goal` "stalls and stops if it can't", 90 §1.2).
- **What exists today:** micro-loop primitives (verify.server.ts:590; synthWithBackoff; expandBriefWithBackoff), wild-mode bounded step driver (cap-20), honest refusal envelopes.
- **What must be built:** a keyed-P6 journey driver (N bounded produce attempts alternating the repair classes: signature → brief-fit → forbidden → runtime-binding → tree-compile); after budget exhaustion the phase records FAIL **and the completion path refuses "clean complete"** while a FAIL gate stands (completion gate; red-gate presentation, S-04). Maps: CG-03/CG-04, G-10, 95 G4/P0-C; 127 F-X1.

### S-04 — GATES THAT CLOSE: machine evidence threads into probes; the enforce-DoD default is decided; red-gate + clean-complete becomes impossible
- **The structural claim:** every competitor's trust feature is "checks the machine can run that block or visibly stall" (Claude Stop hooks; Copilot CI-before-PR). RapidTool's differentiator is *built-in deterministic DoD law with evidence hashes* — but the law is advisory by default (engine.ts:1425), `setEnforceDod` is a dead store action with no UI/CLI path (124 A3-02), verify outcomes never feed the `p6-verified` probe's recorded evidence, and the rail prints "sealed" from status counts, not gate truth (console.tsx:2426). A factory whose gate records FAIL and still prints "13/13 sealed" cannot claim to self-drive — the loop has no feedback that bites.
- **What exists today:** full enforcement machinery behind the flag (store.ts:396/461/579, engine.ts:2874 hard-block), `recordGateInto`/`runGate` (dod.ts), VerifyOutcome + convergence on apply (headless.ts:1169), DoD probe table with `p6-brief-fit` (dod.ts).
- **What must be built (all additive, decision-dated per 90 §13.5.4):** (1) thread `VerifyOutcome` (status/iterations/evidence hash) into the recorded evidence of `p6-verified`; (2) flip or re-decide `enforceDod` for **keyed runs** with a CLI `--advisory` escape (129_z2's queued item — keyless runs stay advisory because the deterministic floor cannot pass brief-fit, 97 P0-07 rationale); (3) completion gate: a run whose recorded gates contain FAIL may not report clean `complete` (surfaces in rail `{n} FAIL-gated`, packet `gate_summary`, seal strings — 97 P0-07 spec); (4) one UI/CLI affordance for `setEnforceDod`. Maps: CG-03, 124 A3-02, 97 P0-07, 95 G4.

### S-05 — MEMORY THAT REACHES THE NEXT TASK: retrieval completion + human-gated cross-project promotion + counter-evidence decay + a falsification metric
- **The structural claim:** capture without retrieval is journaling, not learning (124 A3-03: "self-learning is write-only"; the make journeys' lesson content is hollow — rows record THAT something failed, not WHAT was missing, 99). The factory compounds only when the *next* task's plan/codegen/reframe/verify prompts are demonstrably different because of the last task's failures — and when the claim is falsifiable (if gate rejections don't fall by run 6, rip the loop out — 90 §5/§9.3, 98 §6.4).
- **What exists today:** capture (engine.ts:436/1140, headless.ts:543/569/1169); read-back into P6 expansion only (codegen.server.ts:748–750); `selectLessons`/`lessonLinesForBrief`/`rankBriefLessons` pure and tested; KnowledgeStore + injectProven (knowledge.ts:378); prompt-engine proven-row rendering (:419); vault as human surface.
- **What must be built:** (1) Tier-2 injection — prior `[vague-brief]` rows into the P0 reframe HITL prompt (98 §5 Tier-2 site, engine.ts:436 region) and top lessons into the wild classifier context; (2) Tier-1 — cross-project proven rows into the packet's Ranked memory behind a configured store (packet.ts:292 slot; injectProven has zero prod consumers today); (3) the human-gated promotion path (`lesson propose/accept/supersede` verb family, 98 §7 — machine proposes, human disposes; the ONLY way a run's lesson reaches other projects); (4) counter-evidence decay + supersede on the store (98 §6, additive fields — no competitor ships this); (5) falsification counters in the eval harness (S-06). Maps: CG-09, 124 A3-03/A3-04, G-25/G-39, 117/129_z3 follow-through.

### S-06 — THE MAKER-LOOP AS A PERMANENT GATE: an objective eval harness that scores the shipped artifact against the brief
- **The structural claim:** "10/10 maker verdict" is only meaningful if a machine can re-score it. The make journeys each took a full agent-day to audit by hand; the factory must instead end every run with a **maker scorecard** (objective, deterministic-where-possible rubrics: brief-noun coverage of the tree, reqTrace completeness, oracle non-vacuity, emitted-tree compile + test pass, artifact presence) recorded as a DoD probe — advisory at first, the acceptance gate for the factory claim. This is what turns the 1/10 audits into a permanent, cheap, self-running gate.
- **What exists today:** the anti-vacuity oracle grounder (verify.server.ts:487), `p6-brief-fit` probe (dod.ts), brief-fit vocabulary checker `briefFitSatisfied` (codegen.server.ts:457), reqTrace contract in the synthesis prompt, six real briefs + audit dossiers that can become corpus fixtures.

## §6 THE 10/10 ACCEPTANCE BAR (per maker criteria)

A maker journey is: a **fresh brief** (not in the eval corpus), real key, driven through the CLI end-to-end, audited by an independent reviewer against this rubric. Score = product delivery N/10, process honesty N/10. **10/10 delivery is reached when all nine criteria below hold on the same run**, and the maker scorecard (T6) prints them:

| # | Maker criterion | 10/10 bar — observable evidence (what must exist) | Today (evidence) |
|---|---|---|---|
| M1 | **Product substance** | The emitted tree's core files implement the brief's domain: ≥1 real generated module per brief-required capability; brief nouns appear as identifiers **in the tree**, not only in the module; no engine-meta artifact, no lattice-relic contamination. reqTrace maps requirements → files. | ✗ — make journeys ship 0 brief modules (98_make_1..5, 99). Requires T2 + kind-correct cores (T3). |
| M2 | **Runs** | `emit`-dir: package.json present; bounded runner executes the tree's specs; tree compile passes (`node --check`/`tsc`); entry point runs with exit 0. Emit report records the tree verdict. | ◐ — emit writes the folder (headless.ts:1002); nothing compiles/runs it. Requires T1-check + T3. |
| M3 | **Tests are real** | Machine-run oracle cases reference brief nouns + contract signatures (anti-vacuity); ≥1 case fails when a requirement export is removed; pass is re-derived from the runner, never asserted. | ◐ — oracle grounding real (verify.server.ts:487); probe-level wiring + UI visibility pending. T1. |
| M4 | **Self-fix proven** | The run's own log shows a failure → repair → pass cycle on a *real* defect (syntax, unbound name, or tree compile error) with the failed attempt and the repair both recorded. | ◐ — module-level classes real (codegen.server.ts:184/210/245); no tree-level defect ever seen because the tree never runs. T3. |
| M5 | **Iterated to green, or stopped loudly** | Journey converges within the bounded budget to PASSED P6 gate + converged packet; OR budget dies and the run records FAIL + honest completion text + HITL evidence — never a red gate under a clean "13/13 sealed". | ✗ — red gate + clean complete is the current normal (99 #4, 129_z2). | M6 | **Gates closed** | `p6-brief-fit` + `p6-verified` + `p6-arch` + tree-compile all PASS on the shipped run; verify outcome is the recorded evidence; enforce-DoD decision documented and the keyed default behaving as decided; Settings/rail copy matches actual gate authority. | ◐ — probes exist; evidence threading + default decision + copy pending. T1. |
| M7 | **Learned** | ≥1 L1–L5 row from a prior run of the same domain appears inside this run's P6 expansion **and** reframe prompt (provenance + score visible); no lesson claims a fix that a later verified run contradicted (decay/supersede working). | ◐ — capture + P6 read-back live (129_z3); reframe injection, cross-project, decay pending. **The demonstration that would certify 10/10:** `npm run eval` on the corpus prints the maker scorecard; then one **fresh** brief (e.g., a domain RapidTool has never seen in a journey) run keyed end-to-end produces: multi-file tree (M1) → `emit --check` + tree-run green (M2/M3) → the run log shows ≥1 recorded repair cycle (M4) → gates converged, completion text truthful (M5/M6) → the packet's expansion cites a stored lesson from a same-domain corpus run (M7) → folder + report + DEPLOY.md handed over (M8) → independent audit confirms M9. That is the first honest 10/10.

**What 10/10 explicitly does NOT mean (honest floor, from 90 §6/§7 and reaffirmed by this pass):** Bolt/v0-grade visual polish and hosted infra (webapp UI shells stay honest stubs; P9 stays templates), in-repo editing ergonomics (RapidTool generates governed trees; it is not an editor), cloud-scale fleets (bounded local runs remain the feature), frontier-model IQ (the answer is decomposition + structure, not model envy), Manus-style unbounded computer autonomy. The factory claim is scoped to what a governed, evidence-hashed, keyless-floor builder can honestly produce: **library / CLI / service / data-module software that runs, plus honest webapp shells** — and 10/10 is scored within that scope.
