### 168-B-1 — RUN HISTORY / execution timeline: **ABSENT**

- **Evidence**: The only "past" a build shows is the *current snapshot* of each phase — click a rail phase → `PhaseRecordView`
  (console.tsx:5065, read-only replay of that phase's latest record/gate/artifacts/decisions). There is **no list of runs/executions**:
  nothing records "execution #3 of P5 at 14:02 → 2 artifacts → gate PASS → 41s", and no UI can answer "what did run #2 produce?".
  Re-running a phase **overwrites** rather than versions: artifact ids are deterministic (`id: \`${phase}-${kind}-${slug(title)}\``,
  src/lib/engine.ts:254) and store commits merge by id (`artifacts: [...committed.artifacts, ...unseen(live.artifacts, prevArtifactIds)]`,
  src/lib/store.ts:286; gate artifacts are filtered-then-replaced on re-record, store.ts:338). Logs are a single capped tail
  (`.slice(-200)`, store.ts:330), not per-run. The Runtime tab (`RuntimeLogPane`, console.tsx:3201) polls the **in-memory bounded
  telemetry ring** (`rtSnapshot()` every 2 s, console.tsx:3207) — volatile, current-session only, not a run ledger. Home lists builds,
  never runs (console.tsx:1075–1104).
- **WHY**: humans and agents land mid-project and must reconstruct what happened from a *diffable past*, not the last write.
  "I re-ran P6 and it got worse" is undetectable today — the previous P6 artifacts are gone (id-replaced). This is the single
  biggest auditability gap against the repo's own "paper trail" contract (AGENTS.md ¶6).
- **WHERE**: new store slice (versioned event log) + a "Runs" affordance in `RunScreen`.
- **HOW (wire)**: (1) store.ts: add a bounded `runLog: RunEntry[]` (`{seq, at, phase, action: "step"|"gate"|"wild"|"repair", ok, artifactsAdded, gateVerdict, elapsedMs, note}`),
  appended at every `executeAsync`/`runUntil`/wild-run resolution and at wild stop/pause (store.ts:1222/1304 commit points); cap ~100, persist with the project.
  (2) console.tsx: under the phase hero actions (console.tsx ~1800–1860 block), add a compact "Runs" popover/list — newest first,
  each row `P{phase} {action} · {ok?gate} · +{n} artifacts · {elapsed}s · {fmtClock}` — clicking a row opens a read-only
  `RunRecordView` reusing `PhaseRecordView`'s markdown rendering but scoped to the artifacts/logs that entry added (ids already on the entry).
  (3) Keep phase-rail click = phase record, add "Run N" only where entries exist for that phase.
- **TEST**: lib-level — pure `runLogAppend` reducer (cap, idempotent same-run re-commit) + store integration: execute twice on one
  phase, assert `runLog` has 2 entries while `artifacts` still holds one copy per id (regression-guards the overwrite semantics);
  UI — manual: run P3 twice with different outcomes, open Runs, confirm both entries and that selecting each shows its own artifacts.

### 168-B-2 — DIFF VIEW (between emits / emit↔repair): **ABSENT**

- **Evidence**: zero `diff` UI anywhere in console.tsx (grep: no diff component, no before/after pane; the only "diff" hits in
  src/lib are prose in crew/packet prompts, src/lib/crew.server.ts:95/335, src/lib/packet.ts:737). Because artifacts are
  id-replaced (168-B-1 evidence), two versions of the same artifact never coexist, so a textual diff has no inputs today.

  artifact body at a time (`ArtifactPane`, console.tsx:2819; `activeArt` = last match, console.tsx:1299).

  (`lastTestCaption`, console.tsx:147; gate PASS/FAIL) but never *content* deltas. A repair or re-synthesis that silently
  regressed a section is invisible.
- **WHERE**: Artifacts tab + (once 168-B-1 lands) RunRecordView.
- **HOW (wire)**: (1) when 168-B-1's runLog lands, keep the *previous* artifact body for same-id replacement in the entry
  (`prevBody`), or add `artifactVersions: {id, body}[]` capped at 2 per id. (2) A tiny pure `diffTexts(a, b)` (LCS/word-level —
  no new dep; ~60 ln in src/lib/diff.ts with colocated tests). (3) ArtifactPane: when a phase record/run entry has 2 bodies,
  render a "Changed" toggle that swaps the markdown body for a side-by-side `<pre>` diff (added=green/removed=danger tone classes
  already in the design system). (4) CLI parity later: `emit --diff prev.json` compares trees — out of scope here, list as follow-on.
- **TEST**: lib — `diffTexts` unit tests (add/remove/move, empty sides, 200KB guard); UI — manual: re-run a synthesis phase after
  editing the brief, open the artifact, toggle Changed, eyeball the delta; assert no diff UI appears for first-run artifacts.

### 168-B-3 — PROGRESS + ETA on long work: **ABSENT** (elapsed exists in exactly two narrow places)

- **Evidence**: During a keyed phase execution (`executeAsync` resolves only at the end — contract store.ts:109; commit at
  store.ts:1222/1304) the only feedback is a spinner button "Running…" (`Loader2` branch, console.tsx:1800) plus a bare `aria-busy`
  on the center column (console.tsx:1720). `PhaseProgressRail` (console.tsx:2460) is coarse *phase-graph* progress
  ("done/total sealed · pct%", console.tsx ~2473) — nothing for the *in-flight phase*. The two elapsed counters that DO exist are
  narrow: the wild-mode run clock ("since {n}s", console.tsx:778, ticking via console.tsx:637) and the chat LLM ticker
  ("thinking… {elapsedSec}s", console.tsx:4664–4673, 4873 — fixes/99 §2.4.1). Neither is visible during a normal single-phase
  "Execute"/"Run to gate", and **no ETA/"remaining" string exists anywhere** (grep: 0 hits). Telemetry *has* `elapsedMs`
  (src/lib/rt-client.ts:218, sys.heartbeat_lag) but it is diagnostic, not surfaced.
- **WHY**: the 240 s keyed synthesis path is indistinguishable from a hang (165-A-8 found one missing busy state; the UX gap is
  broader) — humans abandon, agents can't budget. "X of Y steps done, ~Ns elapsed, ~Ns left" is the minimum credible liveness.
- **WHERE**: center-column run surface (console.tsx ~1830–1860) + `WildConsole` (489) parity.
- **HOW (wire)**: (1) the engine already runs phases in bounded sub-steps server-side; expose a lightweight progress channel:
  extend the `executeAsync` flow to resolve `{progress}` via the existing store→server round-trip is invasive — cheaper honest
  v1: a client-side elapsed/ETA panel driven by the *known sandbox timeout + a server-reported phase weight table*:
  show `elapsed {s}s · phase budget ≈{b}s · ETA {mm:ss}` using `project.sandbox.timeoutS` (header chip already renders it,
  console.tsx ~1652) — label ETA "≈ · estimate" (matching the token chip's "estimate · ±15%" framing, console.tsx:1659), never
  fabricated precision (honesty contract). (2) Add a same-style ticker to the
  step button area as the wild/chat ones (console.tsx:637/4673 pattern). (3) If sub-step events exist later, upgrade to a real bar.
- **TEST**: UI — manual with keyed backend: Execute a P6 synthesis, assert elapsed ticks, ETA counts down, no spinner-only window
  >2 s; keyless mode: same panel shows deterministic budget text and completes. Typecheck/lint/build gates.

- **HOW (wire)**: (1) `src/components/toast.tsx` — `ToastHost` + `useToasts()` (zustand store, 3–4 visible, auto-dismiss 6 s,

  wild run stops-or-parks / gate parks at HITL / crew stops (`crewRun` already computed, console.tsx:1934) — subscribe to the
  store transition (prev `running`→false with a terminal status) so it fires regardless of active tab; (3) optional v2:

- **TEST**: lib — toast-store reducer (cap, dedupe same-event); UI — manual: start wild run, switch to another tab, wait for

### 168-B-9 — i18n + accessibility basics: **PARTIAL** — a11y is thoughtful but with concrete holes; i18n is ABSENT by design choice

- **a11y evidence (good)**: aria-labels on tabs list/triggers (console.tsx:2138–2200), search/filter inputs (2208/2218), icon
  buttons; `role="status"/"alert"` + `aria-live="polite"` on notices and the wild strip (console.tsx:472, 2060–2067, 2712, 2757);
  Radix AlertDialog for archive (console.tsx ~2026) gives focus management there; visible `focus-visible:ring` on most controls;
  `sr-only` labels (2757); min tap targets (min-h-9/10/11).
- **a11y holes (spec)**: (1) **custom `Modal` has no focus trap / initial focus / restore** — role=dialog+aria-modal (function
  `Modal`, console.tsx:5316) but focus stays on the trigger behind the overlay (Escape/scroll-lock only, console.tsx ~5319–5340);
  tab can walk behind the dialog. (2) **No skip link**
  and no `main` landmark ordering guarantee; center column announces `aria-busy` but completion is never announced — add
  `role="status" aria-live="polite"` text on run-complete transitions (feeds 168-B-6's toast host). (3) **No
  `prefers-reduced-motion`** handling for `animate-spin` (console.tsx ~1801) / pulse. (4) Contrast risk: `text-faint` at
  10–11 px mono (console.tsx:778, 2470) — audit against the light palette (styles.css) with a contrast check, don't guess.
  (5) The phase rail updates (rail-seg tones, console.tsx:2460–2520) are visual-only — give the `aria-label` per-segment
  (`console.tsx:2506` has labels; announce *state change* via live region when a run ends).
- **i18n evidence**: `<html lang="en">` hard-coded (`__root.tsx:57`); every string literal English in console.tsx; the only
  Intl usage is `localeCompare` (console.tsx:3314); dates via hand-rolled `fmtClock` HH:MM (console.tsx:223) and `agoLabel`
  (console.tsx:210) — no `Intl.DateTimeFormat`, no RTL, no string table.
- **WHY**: a11y holes above are cheap and are exactly what "usable by humans of all kinds" means (screen-reader users cannot
  operate Guide/Settings/Shortcuts dialogs today — focus never enters them). i18n is a *deliberate* deferral for a
  deterministic single-operator tool — spec only a minimal seam so it is not a rewrite later.
- **HOW (wire)**: a11y — (1) `Modal` (console.tsx ~5301): on open, focus the dialog title/panel (ref + `focus()`), trap Tab
  (keydown handler cycling focusables inside), restore focus to the opener on close (~20 ln, no dep; Radix Dialog would replace
  it but that is a bigger swap — a hand-rolled trap matches the file's no-dep modal precedent); (2) skip link as first element
  of `__root.tsx` layout + `id="main"` on both screens' `<main>`; (3) motion: `@media (prefers-reduced-motion)` guard for the
  spinner class in styles.css. i18n seam — keep it honest and small: central `src/lib/ui-strings.ts` table for the ~40
  user-facing labels + `Intl.DateTimeFormat` for the two clock helpers (console.tsx:210/223) with a `locale` field defaulting
  "en" (no runtime language switcher this wave); `lang` derived from the same field.
- **TEST**: a11y — manual keyboard: open each dialog, Tab cycles inside and cannot reach the overlay trigger, Escape closes,
  focus returns to the opener; axe/playwright spot-check on Run + Home + each dialog if the e2e lane has a browser harness;
  reduced-motion emulation shows no spinner animation. i18n — unit: `ui-strings` returns keys for locale "en" and falls back
  safely; `fmtClock` output identical under en-US/en-GB (regression against today's HH:MM).
