## 0. TL;DR

- RapidTool's governance core is **genuinely ahead of the OSS field on three axes**: a
  deterministic state machine owns every phase transition (LLM content only — engine.ts,
  store.ts), a machine-checkable DoD gate with FNV-1a evidence hash is recorded per completed
  phase (dod.ts), and an honesty contract (declare-or-strike capability ledger, E-14 modelRoute,
  forceHuman rights, ungrounded-footers) that MetaGPT/ChatDev/SSSF simply do not have.
- The **sharpest governance gap vs the field** is completion-vs-acceptance semantics: a phase
  flips to `complete` in `applyPhaseResult` (engine.ts:1311-1320) **before and without** its DoD
  gate being consulted; the gate is recorded afterwards and only enforced at LEAVE-time when
  `enforceDod` is on (store.ts:437-461, 498-539). SSSF's rule — "phases passing is not the same
  as the run being accepted… pass `accepted=` so the exit code, the session status, and the
  banner are decided together and cannot disagree" [L7] — has no RapidTool equivalent: there is
  no run-level `accepted` verdict that phase-gate evidence and final sign-off both feed.
- Secondary gaps, ranked: (2) HITL approval precedes the machine's own gate verdict for stock
  phases (their DoD includes "HITL approved", so the gate is only evaluable post-approval —
  dod.ts:284-288), so humans are asked to bless output that has not been machine-checked, and
  wild mode patches this with an awkward post-approval discard (engine.ts:3345-3363); (3) the
  sync store and wild loop are **two hand-maintained copies of the transition machine**
  (parity-bug history: audit-31, P0-08, SWEEP-2, ST-1); (4) human approve-with-note is a
  dead-end (only rejection notes feed re-synthesis — engine.ts:1279-1284); (5) no per-run
  append-only event journal (audit = capped in-project logs); (6) machine gate-approval is
  self-review by the same model that wrote the phase (no independent evaluator); (7) the graph
  is linear-only with no bounded worker fan-out (CAPABILITIES says so itself — dod.ts:678-683),
  while every surveyed factory (MetaGPT, OpenHands, SSSF, Anthropic's orchestrator-workers)
  rests on delegable subtasks.
- Recommendation: land S1-01 (run-acceptance verdict) and S1-02 (gate-first completion) as the
  governance keystone, then S1-03 (one transition kernel) — mirroring 157's own "P0-1 is the
  keystone" sequencing.

## 1. Code-grounded assessment vs the field

### 1.1 What is genuinely strong (do not rebuild)

1. **Code owns the loop; the LLM never moves the cursor.** Every transition runs through
   deterministic guards: `canEnter` is strictly `to === from + 1` with phantom-phase denial
   (phases.ts:126-132); `priorsSealed` indexes by record id, never array position
   (phases.ts:134-148); `advanceOnce`/`finishPhase` (store.ts:401-539) and the wild loop
   (`wildLeavePhase` engine.ts:3380-3444) both re-check priors-sealed + enterability before
   every edge. LLM output is bounded to *content*: `applyPhaseResult` (deterministic),
   `liveLayer`/`runPhaseAsync` (live research + LLM narrative layered on top, degrading to the
   deterministic floor on ANY error — engine.ts:2725-2727, 3051-3058), and wild-mode review
   verdicts. This is exactly the architecture SSSF markets — "Same models. Same prompts. The
   difference is who owns the loop" [L6] — and Anthropic's workflow/agent distinction:
   "Workflows are systems where LLMs and tools are orchestrated through predefined code paths"
   [L9]. ChatDev's chat-chain, by contrast, lets agents drive phase progression through
   dialogue [L3]; RapidTool's refusal to do that is a strength, not a gap.
2. **Machine-checkable DoD with reproducible evidence.** Probes read only project content —
   "never timestamps, ids or randomness" (dod.ts:216-220) — and `runGate` returns a stable
   FNV-1a hash over sorted `id:pass|fail` pairs (dod.ts:485-512); an unregistered phase fails
   loudly, never vacuously (dod.ts:490-504). Every completed phase gets a recorded gate
   (`recordGateInto`/store `recordGate`, dod.ts:600-644; store.ts:302-343) surfaced as a gate
   artifact + `gate.verdict` log, and `sealHonesty`/`failedGates` keep a census of red-gate
   completions (dod.ts:586-598; engine.ts:1183-1186) that the CLI turns into a non-zero exit.
   `verifyPriorPhases` (engine.ts:3015-3040) re-hashes earlier phases' gates when a later
   report touches overlapping files — a real regression-drift detector (E-19). MetaGPT's paper
   motivation ("agents with human-like domain expertise **verify intermediate results** and
   reduce errors", [L1]) is structurally present here as probes+hash, which is more than most
   OSS factories implement.
3. **HITL rights are real and enforced in code.** forceHuman gates (failed P6 sandbox
   engine.ts:1286-1294; P0 reframe) can never be machine-approved: sync autopilot refuses
   (engine.ts:1533-1535; store.ts:366-368 `canAutopilot`), the wild classifier refuses
   (engine.ts:3301-3310). Rejection requires ≥12 chars of qualitative feedback and lands in an
   append-only rejectionHistory (engine.ts:1608-1625); retry is only legal after a recorded
   reject (engine.ts:1667-1679); every approval/rejection writes a decision row with its actor
   (`decidedBy: human|autopilot`, engine.ts:1545-1555). Autopilot itself is DoD-gated and
   schedule-gated (store.ts:364-372: never stock HITL, never a failing gate, only tightness
   < 7.2 extra gates). This is stronger human-in-the-loop governance than ChatDev (no human
   surface in its chat chain [L3]) or MetaGPT's demo pipeline.
4. **Honesty contract as code.** The `CAPABILITIES` declare-or-strike ledger
   (dod.ts:654-689) with B-18 tails, E-14 modelRoute honesty on hydrate (engine.ts:1844-1859),
   `meta.liveUnavailable` dead-end waivers (engine.ts:2741-2761; dod.ts:401-408), explicit
   "ungrounded by construction" footers on LLM narrative (engine.ts:2517-2518, 2831-2834),
   session-honest wildRun hydration (an active run cannot outlive its driver —
   engine.ts:1940-1965), per-row hydrate repair (engine.ts:1870-1930), single-flight
   serialization (store.ts:180-232) and salvage-safe persistence (store.ts:674-802). No
   surveyed project ships this discipline; it is the repo's moat and 157's fixes must not
   erode it.
5. **Wild mode is a bounded, auditable primitive — one edge per call.** `wildStep` resolves
   exactly one edge (execute → gate/leave → pause-or-advance) with a full pause taxonomy
   (engine.ts:3468-3681): classifier-unconfigured gates pause (RT_E_LLM_NOT_CONFIGURED,
   engine.ts:3312-3321), forceHuman pauses, hard-DoD pauses with artifact + `dod.blocked` log,
   guard violations pause (engine.ts:3611-3624), errors pause with an honest ledger row
   (engine.ts:3650-3680) — and RT telemetry seeds ride along without changing behavior.

### 1.2 What is missing or misaligned vs the field (each maps to an S1-nn addition)

1. **Completion ≠ acceptance; no run-level `accepted` verdict (→ S1-01).** `applyPhaseResult`
   flips the record to `complete` purely on synthesis output + HITL resolution
   (engine.ts:1311-1320); the gate is consulted *after* (recordGate in finishPhase,
   store.ts:503) and an unmet gate mints an L2 "template-emission" lesson and continues
   (engine.ts:1357-1401). Enforcement exists only (a) at LEAVE when `enforceDod` (default ON
   for keyed runs — engine.ts:1766-1767), and (b) as an advisory census + CLI exit
   (`sealedWithFailures`, dod.ts:596-598). So "phase complete, gate failed" is a legal,
   recorded state, and nothing — UI or wild — has a single `accepted` boolean that phase-gate
   evidence and terminal sign-off both feed. `wildFinalize` marks a run complete without a
   final `failedGates` check (engine.ts:3447-3460), so an `enforceDod:false` wild run can
   banner "complete" over earlier red gates. SSSF's counter-rule is explicit: "Every ADW ends
   in `run.finish()` — **phases passing is not the same as the run being accepted**. A test
   phase that ran a red suite succeeded at its job. Pass `accepted=` so the exit code, the
   session status, and the banner are decided together and cannot disagree" [L7]. (157 §4 P0-2
   already flags the headless twin: `converged` returned without reading `gate.passed` — same
   disease, different organ; S1-01 fixes the shared verdict.)
2. **HITL approval precedes the machine verdict; pre/post gate split missing (→ S1-02).** For
   every stock HITL phase the DoD registry embeds "HITL approved — phase record complete" as a
   criterion (P4: dod.ts:284-288; P5: 296-299; P8: 417-420; P9: 429-432), so the phase's gate is
   **only evaluable after human approval**. The human is asked to bless an artifact set with no
   machine verdict on the criteria that *are* pre-evaluable (artifact presence, content
   probes); wild mode then has to discard a classifier self-approval when the post-approval gate
   fails (engine.ts:3345-3363 — "the candidate is discarded and the block is stamped on the
   pre-approval project"). That is the evaluator-optimizer loop [L9] running in the wrong order:
   evaluation should precede the approval decision, with clear criteria.
3. **Two hand-maintained transition machines (→ S1-03).** The sync store path
   (`advanceOnce`/`runReady`/`finishPhase`, store.ts:401-539) and the wild path
   (`wildLeavePhase`/`wildApproveGate`, engine.ts:3289-3444) re-implement the same edge logic
   (guards, autopilot-vs-classifier approval, hard-DoD leave check, recordGate+stampPacket
   ordering). The comments themselves are a changelog of parity bugs (audit-31 guard-skip,
   engine.ts:3423-3424; P0-08 Hole A/B packet re-stamp, engine.ts:3364-3367, 3640-3643;
   SWEEP-2 st-7 gate recording, store.ts:415-420; ST-1 gate-before-compile, engine.ts:1600-1604).
   Every future governance change (S1-01, S1-02, S1-06) must land twice or the machines drift
   again.
4. **Approve-with-note is a dead end; only reject feedback loops (→ S1-04).** A human
   rejection note is re-fed into synthesis (attempt/note ctx, engine.ts:1279-1284, and the T9
   visible answer block, engine.ts:1300-1308), but an *approval* note lands only in the decision
   ledger (engine.ts:1555) — it never reaches the next phase's synthesis context. OpenHands'
   architecture exists precisely so humans can inject into the stream ("user interfaces, agents,
   and environments interact through an event stream", [L5]); Anthropic's evaluator-optimizer
   fit-sign is "LLM responses can be demonstrably improved when a human articulates their
   feedback" [L9]. RapidTool already collects that articulation on approvals — it just throws
   it away.
5. **Audit = bounded in-project logs, not an append-only per-run journal (→ S1-05).** Logs are
   capped at 200 rows in-memory (engine.ts:1343), decisions at 100 (engine.ts:1555), memory at
   80; the CLI writes NDJSON under `<dir>/.rapidtool/logs/` (AGENTS.md) but the app's own run
   history is a mutable capped array re-stamped on every action. OpenHands' core is the
   opposite: an event stream "for tracking history of actions and observations" where state is
   derived [L5]. For an app whose pitch is "audit trail", the journal should be a first-class
   append-only artifact per run, with the capped arrays as views.
6. **Machine gate-approval is same-model self-review (→ S1-06).** In wild mode the reviewer
   classifier is the same DeepSeek route that authored the phase content, and it may
   self-approve any non-forceHuman gate including stock HITL phases (engine.ts:3571-3573 +
   3289-3374) — while the sync store's autopilot refuses stock phases entirely (store.ts:368).
   Two different machine-in-the-loop policies, neither with an independent evaluator. The
   pattern literature is unanimous that the critic should be separable: evaluator-optimizer
   ("one LLM call generates a response while another provides evaluation and feedback in a
   loop", [L9]); MetaGPT's QA-engineer role and "verify intermediate results" [L1][L2]; SSSF's
   reviewer is a *separate prompt template/role* in its roster (templates/
   prompt_engineering/reviewer, [L7 repo tree]).
7. **Linear-only graph; no bounded worker fan-out (→ S1-07).** `CAPABILITIES.concurrency` is
   honest: "Linear graph only (phases.ts canEnter). Parallel workflow + WebSocket progress
   frames do not exist" (dod.ts:678-683); `project.crew` is typed and initialized empty
   (engine.ts:1757) with no engine consumer. Research phases make one fetch pass per phase
   (`fetchResearch`, engine.ts:2530) — MetaGPT's assembly line assigns roles and parallelizes
   subtasks [L1][L2]; OpenHands has multi-agent delegation (§2.4, [L5]); Anthropic's
   orchestrator-workers exists for "complex tasks where you can't predict the subtasks needed…
   search tasks that involve gathering and analyzing information from multiple sources" [L9] —
   which is literally P7. Fan-out is the roadmap item the capability ledger already declares.

### S1-01 — Add a run-level acceptance verdict; phase-pass and gate evidence must not disagree (P0 governance keystone)

- **Change:** Add an immutable run verdict on the project — `accepted: null | { ok: boolean; at: number; evidenceHash: string; by: "human" | "machine" | "system" }` (type-level) — written exactly once at terminal seal by a new pure `sealRun(project)` that computes `failedGates` (dod.ts:586-598) + final P12 gate and stamps `accepted.ok = no red gates ∧ P12 gate passed`. All three terminal surfaces consume it: `wildFinalize` refuses to banner complete when the census is red (park `paused`, RT_E_GATES_FAILED, instead of `wild.complete` — engine.ts:3447-3460); the store's P12 leaf in `finishPhase`/`runUntilHitl` records it (store.ts:498-539, 1160-1217); headless/CLI `emit` already exits 1 on red seals and should read `accepted.ok` instead of re-deriving it (AGENTS.md exit taxonomy). Keep the advisory path honest: `enforceDod:false` runs may still seal, but the verdict says `ok:false` and the UI/CLI banner must show "not accepted" — never bare "complete".
- **Why:** Closes §1.2-1: today "complete-with-failed-gates" is a legal state with no single owner of the "so is the run OK?" answer; the UI, wild, and CLI each derive it differently (wildFinalize doesn't even check). SSSF: "phases passing is not the same as the run being accepted… the exit code, the session status, and the banner are decided together and cannot disagree" [L7]. This is the governance twin of 157's P0-2 "converged must require gate.passed" — one verdict, every surface reads it.
- **File/region:** `src/lib/types.ts` (Project verdict fields) · `src/lib/dod.ts` (new `sealRun` beside `sealedWithFailures`) · `src/lib/engine.ts` (`wildFinalize` :3447-3460; `sealHonesty` :1183-1186) · `src/lib/store.ts` (`finishPhase` :498-539; `runUntilHitl` :1160-1217) · `scripts/rapidtool-cli.mjs` emit/exit + headless consumers.
- **Test idea:** seed a project whose P6 gate recorded `passed:false`, run P0→P12 with `enforceDod:false`; assert `wildFinalize` outcome is `paused` (or `accepted.ok === false`), never `completed`; assert sync `runUntilHitl` returns `stoppedReason` reflecting the verdict; assert CLI exit ≠ 0 carries the same hash.
- **Source:** SSSF SKILL.md rule #10 [L7]; 157 §4 P0-2 (repo-internal).

### S1-02 — Gate-first completion: evaluate before you mark complete (and before you ask a human)

- **Change:** (a) In `applyPhaseResult` (engine.ts:1273-1414), after synthesis and before the status flip (:1311-1320), run `runGate` on the produced shape. When `enforceDod` and the gate fails, do NOT flip to `complete` — stamp a hard-DoD block (reuse `hardDodBlockInto`, dod.ts:745-792) and return the phase still `running`/parked with the honest error, so a red phase never reaches the "complete" census. When advisory, keep today's record-and-continue (complete + L2 lesson, engine.ts:1357-1401) but the recorded gate now rides the completion itself. (b) Split every stock-HITL phase's criteria into pre-approval-evaluable (artifact/content probes) and post-approval (the `pX-approved` rows, dod.ts:284-288 etc.): the HITL request payload carries the pre-approval machine verdict (a `gate` summary in `HitlRequest`), and `synthesizePhase`'s gate-opening path refuses to open a HITL request when pre-criteria fail unless `forceHuman` (so the human is never asked to bless output that already fails its own artifact criteria — they may still forceHuman-override, with the existing override log/memory, engine.ts:1543-1579).
- **Why:** Inverts the current default from "complete, gate recorded after" to "gate evaluated, then complete" — the field's default-fail stance (SSSF: deterministic code owns sequencing and acceptance; a phase that did not meet its bar did not pass [L6][L7]). It also fixes the wrong-order evaluator-optimizer loop of §1.2-2 — evaluation precedes the approval decision [L9], and MetaGPT's "verify intermediate results" happens between roles, not after sign-off [L1]. Removes wild mode's post-approval discard hack (engine.ts:3345-3363) as the *primary* defense (keep it as defense-in-depth).
- **File/region:** `src/lib/engine.ts` `applyPhaseResult` :1273-1414 + HITL-open sites; `src/lib/dod.ts` DOD rows (add `pre`/`post` classification on GateItem, :221-466); `src/lib/types.ts` `HitlRequest` + `GateItem`; store `finishPhase` :498-539 keeps its leave-guard (now redundant-but-harmless).
- **Test idea:** keyed-style project (enforceDod true) whose P4 synthesis produces no security artifact → assert no `awaiting_hitl` gate opens (or opens with pre-verdict FAIL and forceHuman required); assert phase never enters `complete`. Regression: advisory runs still mint the L2 lesson on unmet gates (existing lesson tests in store.test.ts / gates.test.ts stay green).
- **Source:** SSSF run.finish + code-owns-sequencing [L6][L7]; Anthropic evaluator-optimizer [L9]; MetaGPT intermediate verification [L1].

### S1-03 — One transition kernel: extract the edge resolver both loops call

- **Change:** Extract the duplicated edge logic — priors-sealed + canEnter guards, awaiting_hitl handling, hard-DoD leave check, recordGate + stampPacket ordering — into one pure module (e.g. `src/lib/run-edge.ts`, new file, type-level spec): `resolveEdge(project, { actor: "human" | "autopilot" | "classifier", verdict?: {approve: boolean; feedback: string}, force?: boolean })` returning `{project, outcome: "advanced"|"parked"|"blocked"|"completed", reason}`. `advanceOnce`/`finishPhase` (store.ts:401-539) and `wildStep`'s `wildApproveGate`/`wildLeavePhase` (engine.ts:3289-3444) become thin callers that add only their policy layer (autopilot eligibility store.ts:364-372; classifier resolution engine.ts:3232-3281). Wild keeps its one-edge-per-call and pause semantics; sync keeps its loop.
- **Why:** Every governance change S1-01/S1-02/S1-06 introduces must land once, not twice — the parity-bug changelog (audit-31, P0-08, SWEEP-2, ST-1) is the measured cost of the current duplication. The code-owns-the-loop principle [L6][L9] is stronger when the loop is one function, and cross-surface parity becomes a property, not a patch series.
- **File/region:** new `src/lib/run-edge.ts`; call sites store.ts:401-539 (sync), :590-647 (async) and engine.ts:3289-3444, :3634-3649; delete/absorb `recordGateInline` (engine.ts:1492-1513) and store `recordGate` (:302-343) behind one recorder.
- **Test idea:** a differential suite: for a corpus of ~20 synthetic projects (each status × autopilot × enforceDod × classifier-verdict), assert sync `advanceOnce` and wild `wildStep` produce the identical phase graph, gate records, and log event tails (the parity tests that were written ad-hoc per bug become a standing property test).
- **Source:** SSSF "who owns the loop" [L6]; Anthropic workflows = "orchestrated through predefined code paths" [L9].

### S1-04 — Approve-with-note becomes next-phase context (human feedback is input, not just ledger)

- **Change:** When `approveHitl` is called with a `note` (engine.ts:1515-1606), in addition to the decision row, append the note to the phase-handoff surface the next synthesis consumes: a bounded `handoffNotes` field on the project (or an event in the S1-05 journal) that `applyPhaseResult`'s prompt assembly reads for the *next* phase (mirror the rejection-note path at engine.ts:1279-1284, but for approvals; cap ≤3 most-recent notes, tag with `source:"human"`). Surface it in the packet's handoff section like rejection history is surfaced today.
- **Why:** Today the human's only forward feedback channel is rejection; approval guidance ("looks right, but keep the CLI surface minimal") is recorded and discarded. OpenHands made human-stream injection a first-class architectural primitive [L5]; Anthropic's evaluator-optimizer fit-condition is exactly that human-articulated feedback improves output [L9]. Cheap, additive, no state-machine change.
- **File/region:** `src/lib/engine.ts` `approveHitl` :1515-1606 + `synthesizePhase` context assembly :428-450 (prompt builder reads handoffNotes); `src/lib/types.ts` Project field; packet compile site `sealPacketArtifact`/`compileAgentPacket` (engine.ts:306-325).
- **Test idea:** approve P3 with note; run P4 synthesis with a stubbed deterministic synthesizer that echoes its context; assert the note text appears in the P4 context and in the packet handoff, and that a second approval replaces rather than accumulates (cap).
- **Source:** OpenHands event-stream interaction [L5]; Anthropic evaluator-optimizer [L9].

### S1-05 — Per-run append-only event journal (audit as a first-class artifact)

- **Change:** Add a per-run journal: a pure `appendRunEvent(project, event)` that pushes typed rows — `{seq, ts, actor, phase, event, detail, evidenceHash?}` — into a new append-only `runJournal` array (kept on the project like `logs`, but never mutated in place: every reducer copies, hydrate validates append-only order by `seq`). Write the same canonical events the engine already logs (`hitl.approved`, `hitl.rejected`, `gate.verdict`, `dod.blocked`, `wild.*`, `algo.run`, `lesson.capture`, S1-01's `run.accepted`) plus their pre-state evidenceHash. The existing capped arrays (`logs` 200, `decisions` 100, engine.ts:1343/1555) become derived views over the journal. CLI/headless already NDJSON to `.rapidtool/logs` (AGENTS.md) — emit the journal rows there too.
- **Why:** The product's pitch is "governed run + audit trail"; today the trail is a capped, re-stamped in-project array with no replay story. OpenHands' architecture is built on the event stream ("tracking history of actions and observations", state derived from it) [L5]. A journal makes S1-01's verdict replayable, gives E-19 drift checks a history to compare, and enables cross-run lesson retrieval (94/96 roadmap). Determinism note: keep `seq` monotonic and make the *content* of each event independent of wall-clock (evidence hashes already are; timestamps stay display fields).
- **File/region:** `src/lib/types.ts` (RunJournal row + Project.runJournal); `src/lib/engine.ts` log/decision write sites (:1333-1343, :1555-1598, :1641-1663, wildLog :3168-3173); `src/lib/store.ts` persist slice (PersistedSlice :657); hydrate (:1967+) repair pass.
- **Test idea:** run P0→P2 under the store; assert journal `seq` is gapless and append-only (no row overwritten), replay of `gate.verdict`+`hitl.*` rows reconstructs `failedGates` and the S1-01 verdict; corrupt a mid-journal row on hydrate → loud repair log + truncation, never a silent pass (mirror repairPhases engine.ts:1796-1834).
- **Source:** OpenHands event stream [L5]; repo's own audit-trail claim (AGENTS.md paper-trail rule).

### S1-06 — Independent evaluator for machine gate-approval (no same-model self-approval)

- **Change:** Define a `WildReviewer` policy split: a *generator* (the phase's own synthesis call) may never be the *reviewer* of its own gate. Two options, pick per gate class: (a) reviewer = a distinct role prompt (same route, critic persona + the phase's criteria verbatim — SSSF-style separate reviewer template [L7]); or (b) when a second route/model is configured, reviewer = that route. Enforce in `resolveWildReview` (engine.ts:3232-3281): the review context must include the runGate criteria list + evidence hash (it already carries `wildGateInfo`, :3204-3214), and the reviewer prompt must be criterion-addressed, not free-form. Align the two machine policies: either sync autopilot may also approve stock gates through the same evaluator (removing store.ts:368's blanket stock exclusion) or wild classifier inherits the stock exclusion — decide one, state it, and mirror it in S1-03's kernel.
- **Why:** §1.2-6: the same model that wrote P8 currently writes the review that approves P8. The pattern literature is unanimous on separable critics [L9][L1][L2], and SSSF ships the reviewer as a distinct template in its agent roster [L7]. Also removes the policy asymmetry where the UI autopilot and wild mode apply different machine-in-the-loop rules to the same gates.
- **File/region:** `src/lib/engine.ts` `resolveWildReview`/`wildApproveGate` :3232-3374; `src/lib/store.ts` `canAutopilot` :364-372; wild-mode server reviewer (`src/lib/wild-mode.server.ts`, referenced engine.ts:3556-3558); prompt templates.
- **Test idea:** inject a fake reviewer that records the context it saw; assert the context contains the DoD criteria + evidence hash and that a reviewer "approve" for a gate whose criteria text the generator could not have seen still requires ≥12-char feedback; assert autopilot and wild policies agree on a stock-gate fixture (single source of truth).
