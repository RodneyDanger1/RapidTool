## H-05 — `compileAgentPacket` baked `new Date().toISOString()` into `compiled_at` → non-idempotent packet

**Spec:** fixes/115_pro_hunter.md H-05 (P2) — probe-det.ts proved two compiles of the SAME project differed at the `compiled_at` line; every refresh/approve/execute re-stamp rewrote the packet artifact body (and persisted export) with a spurious diff.

**Fix — `src/lib/packet.ts`:**
- New `compiledAtFor(project)` helper: the stamp is a **pure function of the project** — the newest of `createdAt`, the newest `logs[].ts`, and the newest `decisions[].decidedAt`. Chose the latest-state stamp over createdAt-only so the human "as of" meaning survives (a post-approval stamp reflects the approval) while an unchanged graph is byte-stable. Defensive: non-finite/absent timestamps ignored (floor 0), ms clamped to `8.64e15` (Date max) so a hostile far-future `createdAt` can never make `toISOString()` throw RangeError mid-compile.
- `const compiledAt = new Date().toISOString()` (old line ~235) → `const compiledAt = compiledAtFor(project)`. Renders into BOTH the prose line and the System JSON envelope, unchanged.
- Traces (`attachAlgorithms` A2/A4 `ranAt: Date.now()`) are deliberately NOT in the derivation — stampPacket rewrites them on every stamp, so including them would re-drift the stamp.

**Regression tests — `src/lib/packet.test.ts` (H-05/D1–D3):**
- D1: `compileAgentPacket(p)` twice on the same project → byte-identical strings.
- D2: `engine.stampPacket(p)` twice → identical `p.packet` (no compiled_at drift on re-stamp).
- D3 (pin): after appending a decision with `decidedAt = createdAt + 5000`, prose + System JSON `compiled_at` equal `new Date(stateStamp).toISOString()` exactly, and an immediate recompile is byte-identical.

## H-03 (io half) — `importProject` never defended corrupt post-whitelist fields → hydration throw / store-crash vector

**Spec:** fixes/115_pro_hunter.md H-03 (P1) — probe-io.ts/probe-debug.ts proved `research=5` throws `(project.research ?? []).slice is not a function` inside hydrateProject's compile pass (misleading "Import failed during hydration"), and on early-return payloads (packet+lattice+specGraph present) a corrupt value rode into the store and crashed the NEXT `stampPacket`/`approve`/`execute`, which are NOT try/caught. The engine `hydrateProject` half of H-03 is owned by a later pass — this lane defends the import boundary in io.ts.

**Fix — `src/lib/io.ts`:** `sanitizeImportPayload(raw)` runs in `importProject` AFTER the whitelist checks (id/name/brief/13 phases/currentPhase/artifacts/logs still fail fast) and BEFORE `hydrateProject`. It coerces-or-drops every defensible post-whitelist field, **never throws**:
- `research` — non-array container → `[]`; entries must be `{query, items[]}`; items must be plain objects (researchHash/researchSources read `item.url`/`item.title` — a null item threw).
- `chatLog` / `oracle` / `crew` — container junk → `[]`; junk rows (null/primitives; oracle rows without a string `name`) dropped. (Engine hydrates these containers but NOT their rows; a null row crashed the packet crew/oracle render.)
- `scorecard` — not regenerated by attachAlgorithms and not normalized by hydrate: structurally-broken objects (missing/non-array `axes`/`bottlenecks`/`attackVectors`) → `null` (honest "Not written" floor); junk axes rows filtered.
- `specGraph` / `contracts` — plain-object guards alone passed junk like `{order:5}`/`{entities:5}` which `compileAgentPacket` then `.map()`s into a throw → dropped to `null`/rebuilt; node/entity/order rows row-filtered.
- **Repair trail:** one `import.repaired` warn log row per repaired import (event mirrors `hydrateProject`'s `hydrate.repaired` convention), detail = space-joined tokens (`research:dropped`, `oracle:rows:-3`, `scorecard:axes:-2`, …), row capped via `slice(-200)`.
- **Byte no-op invariant:** a well-formed payload is untouched (no field rewritten, no row appended) → the export→import→export byte-identical round-trip holds.

**Regression tests — `src/lib/io.test.ts`** (describe "importProject — corrupt post-whitelist fields (fixes/115 H-03 io half)", 9 cases): research container junk `[5, {}, "str", null, true]` all import ok → `[]` + `research:dropped`; junk research entries/items dropped with counts; chatLog container + rows; oracle container + nameless/null rows; scorecard missing arrays → null; scorecard junk axes rows; specGraph `{order:5}` (rebuilt by re-attach) and contracts `{entities:5}` (→ null); crew junk rows; and the probe-io regression vector (`research=5` + corrupt oracle/chatLog) → clean import, one trail row naming every field, `stampPacket` never throws.
