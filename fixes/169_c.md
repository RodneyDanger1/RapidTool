### 169-C-1 — The emitted webapp ships ZERO CSS: no stylesheet file, no link/import, no base styles — the "UI" is unstyled browser-default text on a white page

- **WHAT (the missing layer):** Every anchor generator emits a stylesheet as a matter of course — create-vite's

  and no CSS import** for any kind. Evidence (whole-file grep of scaffold.ts this session): the ONLY occurrences of
  styling vocabulary in the entire emitter are the two Tailwind devDep strings at 452-453 — there is no
  `stylesheet`, no `style`, no `<link`, no `.css` push, no `import "./…css"` anywhere. `emitIndexHtml`
  (1382-1398) writes a 12-line head with charset/viewport/title only; `emitUi`'s webapp branch (765-793) returns

  same. Result: `npm run dev` on any emitted webapp paints Times-Roman headings on a white canvas — visually
  indistinguishable from a 1995 page and from EVERY other RapidTool project (no brand, no differentiation, no hint
  of the product quality the user demands).
- **WHY it matters:** the UI is the user-visible deliverable of the whole 13-phase pipeline; P18 of the 155 audit
  ("UI shell renders the project title only") is the *content* emptiness, but even a styled title would be the
  difference between "empty shell" and "empty shell that looks like a real product's first screen". No CSS also
  means axes 4/5/6 (below) are structurally impossible until this lands.
- **WHERE:** `src/lib/scaffold.ts` — new `emitStylesCss()` + a push in the webapp boot block (currently the
  `kind === "webapp" || kind === "game"` branch pushes index.html/vite.config/main at ~1929-1933; a webapp-only

  paths (1445-1461) so the intake-only Shell is styled too.
- **HOW-TO-CODE:** `emitStylesCss` must stay pure/deterministic/escaped like every other emitter (no Date.now, no
  project text inside CSS values — project-derived text never reaches the style block; the design.ts precedent at

### 169-C-2 — Tailwind v4 is DECLARED in the emitted package.json but never wired: no `@tailwindcss/vite` plugin in vite.config, no `@import "tailwindcss"`, so the deps are dead weight and the design-system path is pre-broken

- **WHAT:** the webapp devDeps already promise the modern design-system stack — `tailwindcss: ^4.0.0` and
  `@tailwindcss/vite: ^4.0.0` (scaffold.ts:452-453) — but nothing consumes them. The emitted `vite.config.ts`
  (`emitViteConfig`, 1401-1416) registers exactly one plugin: `react()`. No emitted file contains
  `@import "tailwindcss"` (Tailwind v4 is CSS-first: the plugin compiles the CSS entry; without the import there is
  nothing to compile, and without the plugin the import would fail at build). So every emitted webapp `npm install`s
  Tailwind for nothing and any future hand-written `@import "tailwindcss"` would break `npm run build` — the wiring
  gap is a latent build-breaker, not just cosmetics.
- **WHY:** "Tailwind or a design-system integration" is hunt-axis 3; the user's bar (Codex/Hermes-quality) is
  unreachable with bare CSS in 2026, and RapidTool's OWN console proves the intended stack (src/styles.css:1
  `@import "tailwindcss";` + `@theme`, audited in audit/02 §381). The scaffold declaring-but-not-wiring is also an
  honesty smell: the emitted README claims `npm run build` really runs (fixes/135 bootability), which is true, but
  the declared deps silently do nothing.
- **WHERE:** `src/lib/scaffold.ts` `emitViteConfig` (1401-1416) — add the plugin import + `tailwindcss()` entry.
  Only the webapp config needs it (game/cli-tool/library/service devDeps carry no Tailwind — 457-460).
- **HOW-TO-CODE:** change the emitted config to `import tailwindcss from "@tailwindcss/vite";` and
  `plugins: [react(), tailwindcss()]`, keeping the deterministic comment header (1403-1406) honest by noting the
  plugin now matches the declared devDeps. Order is irrelevant to Tailwind v4. No other file changes: the CSS
  import in main.tsx (C-1) is what makes the plugin do work.
- **HOW-TO-TEST:** scaffold.test.ts app-kind test — assert bodyOf(result, "vite.config.ts") includes
  `@tailwindcss/vite` and `tailwindcss()`; the existing test at 93-106 already parses package.json and asserts
  vite/react — add `pkg.devDependencies["@tailwindcss/vite"]` truthiness so dep↔config can never drift again. The
  strongest end-to-end proof is the existing `emit --verify-kind` scratch path (PKG_SCRIPTS honesty note, 463-467:
  scratch npm install + declared build, bounded) — after C-1+C-2, that scratch `vite build` compiles real Tailwind;
  assert it still exits 0.

- **WHAT:** `src/lib/design.ts` is a complete, pure, WCAG-AA-verified design-token engine — 20-key palette per

  deterministically from the SAME project that generated the code (family from domain, cast from name hash) — is
  thrown away. Every emitted app is identically blank, while the engine could give each its own brand identity with
  zero LLM involvement.
- **WHY:** hunt-axis 1 (design tokens) and axis 6's token half. The user loves the Codex/Hermes dark aesthetic AND
  expects "excellent quality websites/apps": a token system is the floor of that. RapidTool is in the unusual
  position of already having the engine — the gap is one import away from being closed — and the console's own
  styles.css comment states the lineage: *"Palette source: src/lib/design.ts — the project's own deterministic

- **WHERE:** `src/lib/scaffold.ts` — `emitStylesCss(proj)` calls `designTokens(proj)` (import from "./design.ts";

- **HOW-TO-CODE:** `const d = designTokens(project)`; emit `@theme { --color-brand: d.palette.base; … }` mapping

  header: same hue families, lightness raised so every pairing clears AA ≥4.5:1, verified with the same luminance
  math design.test.ts uses) — a small deterministic `darken/lift` table keyed by family keeps this pure and lets a
  future design.test.ts-style contrast check cover the emitted sheet. All values from design.ts are fixed hex
  strings (never project text) so the no-injection rule holds trivially.
- **HOW-TO-TEST:** unit-level in scaffold.test.ts: bodyOf(result, "src/styles.css") contains

### 169-C-6 — Responsive + a11y basics: nothing emitted handles viewports, focus, motion, contrast guarantee, or landmarks — and the one a11y-ish attribute (lang="en") is hard-coded

- **WHAT:** hunt-axis 4. Today's emitted UI has: viewport meta (1388 — the only responsive nod), `lang="en"`
  hard-coded (1385 — fine only because Project has no locale field; document that choice), and semantic-ish
  `<main>/<h1>/<p>`. Everything else is absent by construction (no CSS, C-1): no fluid layout or breakpoints, no

  console's base layer does `cursor:pointer` + antialiasing etc. — audit/02 §381), no `color-scheme`/theme-color
  meta (so even the dark theme we add in C-7 will flash white and render native form controls light until told
  otherwise), no `prefers-reduced-motion`, no skip-link, no labeled nav (C-5 fixes landmarks), and no contrast
  guarantee for the emitted UI (the engine's AA guarantee lives in design.ts's tables — C-3 maps it into the
  emitted sheet, and the dark adaptation must keep every text pairing ≥4.5:1 per the console's documented rule).
- **WHY:** "great design/easy to use" fails real users without responsive + keyboard + contrast basics; the WCAG
  floor is also the company's own standard (design.ts "contrast-safety rule … every text-bearing pairing meets
  WCAG AA ≥ 4.5:1", re-verified in CI by design.test.ts — the emitted app should inherit that guarantee, not
  forfeit it).
- **WHERE:** `emitStylesCss` (new, C-1) for all CSS answers; `emitIndexHtml` (1382-1398) for the two meta tags;
  `emitUi`/fallback Shell (C-4/C-5) for the landmark attributes.
- **HOW-TO-CODE:** in the emitted CSS base layer: `color-scheme: dark` (matching the C-7 dark default) on `:root`;
  a `.app-frame { max-width: …; margin-inline: auto; padding-inline: clamp(…); }` fluid container; content grid via
  `grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr))` so cards reflow with NO media queries
  needed for v1; `:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px; }` on all
  interactive elements (console token precedent); `@media (prefers-reduced-motion: reduce) { *,*::before,*::after {
  transition: none !important; animation: none !important; } }`; `html { scroll-behavior: smooth }` guarded by the
  same media query. In index.html: `<meta name="color-scheme" content="dark light">` + `<meta name="theme-color"
  content="{dark bg hex}">` (hex from the same constant table as C-3/C-7 — never raw project text). In the JSX
  frame: `<a class="skip-link" href="#main">Skip to content</a>` + `id="main"` on `<main>` + `aria-label` on nav +
  `type="button"` on any emitted button.
- **HOW-TO-TEST:** scaffold.test.ts string asserts on styles.css (`:focus-visible`, `prefers-reduced-motion`,
  `color-scheme`, `auto-fit` or `repeat(`) and index.html (`theme-color`, `color-scheme`); console.tsx asserts

  tables already get.
