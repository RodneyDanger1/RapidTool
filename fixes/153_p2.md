# 153 — P2 (LOOP-LANE): the refusal→next-cycle loop

Lane scope (disjoint ownership): `src/lib/headless.ts` (driveP6Journey cycle context +
how a refused cycle feeds the next), `src/lib/headless.test.ts` (cycle-2-knows-cycle-1
tests), this log. Patch-only, no export renames, zero new deps. The keyed eval running in
the background is module-cache isolated — these edits affect the NEXT run only.

## The gap (read → confirmed)

`driveP6Journey` already threaded a refused cycle's evidence into the NEXT cycle's
*context* (`ctx.refusal`, headless.ts:1304), but the single ctx→deps mapping
`p6CycleLiveDeps` dropped it at the boundary: it mapped only `ctx.treeFailureTail` onto
`deps.treeFailure` (codegen's tree-failure reader). So when cycle N ended in a **synthesis
refusal**, cycle N+1's synthesis deps never carried the refusal class/reason — codegen's
next attempt could not see WHY the prior synthesis was refused and could re-request
byte-identical work (worst case: a refusal on a cycle whose project still carried a
stale red tree — the refusal was shadowed by the tree-run tail).

## What landed

1. **Refusal channel into the next cycle's deps (headless.ts).** `p6CycleLiveDeps` now
   maps `ctx.refusal` → `deps.synthesisRefusal` — a bounded excerpt (refusal class, the
   `RT_E_*` code already in the `p6.synthesis.refused` detail, + first ~200 chars of the
   model's reason; new `P6_JOURNEY_REFUSAL_MAX = 200`, mirroring the 1500-char
   treeFailure tail cap `P6_JOURNEY_TAIL_MAX`). The widened return type is exported as
   `P6CycleLiveDepsShape` (no rename of `p6CycleLiveDeps` itself). It rides liveLayer's
   additive deps param verbatim into codegen `liveP6Synthesis` exactly like
   `deps.treeFailure` (engine forwards the deps object reference untouched; codegen-side
   reading of the new key is the codegen lane's contract).
   - **Byte-identity preserved:** cycle 1 (no prior) ⇒ `undefined` ⇒ legacy
     `liveLayer(p, 6)`; tree-failure-only ctx ⇒ exactly `{ treeFailure }`, no
     `synthesisRefusal` key; refusal-only ⇒ `{ synthesisRefusal }`; both ⇒ both keys.
2. **Exhausted verdict names the LAST refusal.** The `p6.journey.exhausted` log already
   carried `— last refusal: …` (headless.ts:1408); the caller/eval-visible `events`
   trail entry did NOT — it now names the last refusal text too (headless.ts:1410-1413).
   `P6JourneyResult.refusal` already holds the full last detail; run-eval's journey
   envelope reads it (run-eval.mjs:373 — out of lane, unchanged).
3. **Driver behavior unchanged otherwise:** the no-tree branch still folds a refusal into
   `treeTail` (ctx doc: tree-run tail "(or refusal)") so the outstanding-evidence
   semantics and every pre-existing test stay intact.

## Tests (headless.test.ts — new fixes/153 P2 describe, fake-deps style, 4 tests)

- Refused cycle 1 → cycle 2's ctx carries the refusal class + reason, and
  `p6CycleLiveDeps` maps it onto a bounded (≤200) `deps.synthesisRefusal`; cycle 2
  recovers and converges.
- `p6CycleLiveDeps` unit: no prior ⇒ `undefined`; tree-failure-only ⇒ deep-equal
  `{ treeFailure }` with exactly one key (byte-identical); refusal-only ⇒
  `{ synthesisRefusal }` capped at 200; both ride together.
- Driver byte-identity: a tree-failure-only journey feeds NO refusal context to any
  cycle, records `refusal: null`, mints no `p6.synthesis.refused` log.
- Budget exhaustion after refusals: `result.refusal`, the `p6.journey.exhausted` log and
  the events trail all name the LAST refusal text (cycle 3's reason, never cycle 1's);
  the no-tree refusal also rides the tail channel as the outstanding evidence.
