## Design decisions (chosen before edits; rationale here, code cites this log)

1. **402 → `RT_E_LLM_NO_BALANCE` (own class).**
   - `errors.ts`: new registry code + `ERROR_CODE_DOC` entry + the `RT_E_LLM_REJECTED` doc line drops the "402 billing" clause (402 is no longer REJECTED's).
   - `deepseek.ts`: the `!res.ok` branch classifies `res.status === 402` **or** an "Insufficient Balance" vendor body as `RT_E_LLM_NO_BALANCE`; everything else keeps `RT_E_LLM_REJECTED` byte-identically. The refusal text is unchanged (`describeError` already said "account balance exhausted (HTTP 402)"). Never conflated with REJECTED (a 429/auth class) or with `RT_E_BUDGET_EXHAUSTED` (a SESSION cap we control — 226 A3's coded stop). A broke wallet is not a budget stop and not a generic refusal.
2. **Fundedness probe = a separate 1-token call.** The OV-27 reachability probe (`probeP6Reachability`, maxTokens:8) stays untouched (it answers "is the wire reachable"); a NEW `probeFundedness()` makes the cheapest possible call (maxTokens: **1**) through the SAME P6 concatenated-specifier provider and classifies via the SAME `classifyLlmPreflight` (relabelled: HTTP 402 → `class: "no-balance"`, `code: "RT_E_LLM_NO_BALANCE"`). `funded` is `false` only on a 402; `true` on `wire-ok`/`empty-completion` (an HTTP 200 means the account paid for the call); `null` otherwise (401/network/timeout cannot answer the funding question).
   - **A broke account does NOT proceed to a scored trial**: when the fundedness probe reports `class=no-balance`, `main()` ends the keyed run with a distinct recorded ending (results.json `ending:{class:"no-balance",code:"RT_E_LLM_NO_BALANCE",capability:"cannot-run-keyed (account unfunded)"}`, zero entries) and exits 0 — results are data.
3. **Mid-run wallet death → a distinct trial ending.** Per-trial the driver taps the provider's own call records (additive seam, §4) and, when any of the trial's synthesis calls refused with `RT_E_LLM_NO_BALANCE` (or a `p6.synthesis.*` log / journey refusal carries the code), the trial ends `status:"no-balance"` with `notes.capability:"cannot-run-keyed (account unfunded)"`, `notes.stopCode:"RT_E_LLM_NO_BALANCE"`, `notes.noBalance:true`, `acceptance.pass:null` — and it is **excluded from pass@k / pass^n / flakiness accounting** (never averaged, never a scored `dod`).
4. **Model ids + usage + cost reach the row via the smallest seam: an opt-in call tap in the provider.** The only place EVERY keyed call passes through is `completeDeepSeek` (`providers/deepseek.ts`); codegen/registry/engine all route to it (engine's P6 idiom imports `./deepseek.server.ts`, a re-export of the same module instance). A bounded, opt-in tap (`setLlmCallTap`/`clearLlmCallTap`) records `{requestedModel, servedModel, promptTokens, completionTokens, ok, code}` per call; the driver installs it once per keyed run and resets it per trial. Tap failures are swallowed (telemetry may never throw into the call it observes — AGENTS.md honesty contract 7). No tap installed ⇒ no behavior change at all.
   - Row keys: `servedModels: string[]` (ids the provider **read back** — never the requested constant, per the modelProvenance rule), `usage: {promptTokens, completionTokens, totalTokens}`, `estimatedCostUsd`, `costBasis`. `usage:null` when nothing was measured (keyless / tap unavailable) — never invented zeros.
   - **Cost is an estimate, never a claim** (101 §4.5): computed via token-ledger's `estimateCostUsd` (consume, never recompute) from caller-supplied prices — `RAPIDTOOL_PRICE_INPUT_PER_M`/`RAPIDTOOL_PRICE_OUTPUT_PER_M` env (operator prices win) else the repo's own documented list-price row (`research/multiagent/90_LEAPFROG.md:682` §12.3.1 [H2], OFF-PEAK cache-miss rates) with the basis stamped on the row; unknown model ⇒ `estimatedCostUsd:null` + reason (never a guessed price).
5. **Per-trial clean emit target.** Run #3's `foreign files in emit dir: src/generated/get-property.ts` was a stale tree from a previous run at the same path — the refusal (or, with `--force`, a mixed tree treeRun would then judge) is dishonest evidence either way. Chosen design: **pre-clean the driver-owned per-trial target** (`prepareCleanEmitDir`, guarded to paths inside `EVAL_OUT_DIR`) immediately before `emitProject`, so every emit starts from an empty workspace — no `--force` (force KEEPS foreign files → the tree-run verdict would weight a mixed tree), no foreign-file refusal, no inherited files. The removal is recorded per trial (`notes.emitDirClean`) and announced on stdout.
