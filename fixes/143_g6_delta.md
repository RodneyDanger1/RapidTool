## §1 HOW RapidTool works end-to-end — the complete mental model (one page)

### 1.1 Positioning and the two surfaces
RapidTool is **not a starter template and not a builder**: "It turns a client brief into a paste-ready Agent Packet plus a 13-phase (P0–P12) audit trail… It does not build software itself — a real agent does the building under enforced, auditable constraints" (console copy, console.tsx:856; AGENT_GUIDE.md:5–7 still the on-disk position). Two surfaces share **one pure engine** (`src/lib/`): the **browser app** (TanStack Start + React 19, `http://localhost:8080`, zustand store, per-browser `localStorage`, single-tenant, no login UI) and the **headless CLI** (`scripts/rapidtool-cli.mjs`, thin argv wrapper over `src/lib/headless.ts`, JSON files on disk, no browser/server). Everything the UI does, the CLI does; server-only seams (`deepseek.server.ts`, `verify.server.ts`, `node-runner.server.ts`, `compile-check.server.ts`, `crew.server.ts`, `chat.server.ts`, `wild-mode.server.ts`) are dynamically imported so the CLI works on bare Node.

### 1.2 The one object: a Project
A project is a single JSON document: `brief`, `name`, `kind`, 13 `phases[]` records (status, gate record, rejectionHistory), `artifacts[]` (id/phase/kind/title/body/bytes), `memory[]` rows, an append-only `decisions` ledger (actor + ISO timestamp), `logs[]`, `lattice` (domain jobs/entities), `implementationSpec` (stored since P0-01), `generatedSource` (the P6 module string), `lastTest` (verdict record), `scorecard`, `packet`, `modelRoute`, `wildRun`, `meta`. UI persists it to localStorage; CLI to `--project <file.json>` (atomic write-then-rename). Export/import round-trips it with shape validation + repair.

### 1.3 The 13-phase governed graph
`PHASES` in `src/lib/phases.ts`; titles/summaries carry honesty labels inline. **P0** Deep Research & Feasibility (scorecard ≥5 axes — dod.ts probe) · **P1** Core Orchestration & State Graph (spec graph + contract artifacts) · **P2** Memory & Context Consolidation · **P3** Tool Integration & Interoperability · **P4** Security, Isolation & Authorization — **stock HITL** · **P5** Validation, HITL & Self-Learning — **stock HITL** · **P6** Code Generation, Testing & Deployment · **P7** Domain & Market Research · **P8** Dynamic UI/UX Prototyping — **stock HITL** · **P9** CI/CD & Cloud Deployment Routing — **stock HITL** · **P10** Local Agent & Edge Inference · **P11** Real-Time Web & Tool Augmentation · **P12** Documentation & Technical Specs. `STOCK_HITL = [4,5,8,9]` (phases.ts:151). The graph is strictly linear: `canEnter` allows only `to === from + 1` (phases.ts:126–132), `priorsSealed` requires every prior record `complete` (phases.ts:134–148); phantom phases (id 13) are impossible by construction.

### 1.4 The deterministic advance
`create` mints the project; each **advance** executes exactly the current phase's deterministic synthesis (`applyPhaseResult`, engine.ts:1102): per-phase artifacts derived from brief/lattice/spec (research rows + scorecard at P0, spec graph + contracts at P1, memory rows at P2, tool surface at P3, security/validation policy artifacts at P4/P5, the typed synthesis module at P6, research at P7, UI/UX contract at P8 — screens now derived from product surfaces, engine.ts:877–886, never one-per-verb — CI/CD runbook at P9, edge/realtime specs at P10/P11, OpenAPI/ADR docs at P12). The phase then **records its DoD gate**: machine probes over plain project fields (dod.ts:26), each criterion + pass/fail, FNV-1a evidence hash, appended to the ledger with actor+ISO timestamp. `run` = exactly one advance; `gate` = advance until parked (`awaiting_hitl` / `complete` / `blocked`); UI "Run to next gate" = same loop.

### 1.5 Gates, HITL, enforcement — the governance edge
- **Advisory by default (keyless):** gates *record* exit criteria and never block; a FAIL-gated phase can still advance and the run seals `complete` — but since fixes/125/133#8 the census is surfaced honestly (`failedGates`/`sealedWithFailures`, dod.ts:402–413; headless seal logs `sealed-with-N-failed-gates`; console shows "Sealed with N failed gates" instead of green, console.tsx:1744–1758).
- **Enforced when keyed:** `enforceDod` defaults to `keyedDeepSeekConfigured()` (engine.ts:1498–1499); CLI `--advisory` sends false; under enforcement a failing `runGate`/auto-decision **parks** the run (wild step semantics: "reject or (enforceDod) a failing runGate = paused + a 'Hard DoD block' artifact", engine.ts:2713–2721). Keyless stays advisory because the deterministic floor cannot pass `p6-brief-fit` by construction (dod.ts:192–208).
- **HITL is real:** stock gates P4/P5/P8/P9 — and any `forceHuman` gate — **never auto-approve**, even under `--autopilot` or wild mode. They park for a human `approve`/`reject`; a rejection requires a 12+ char note that steers the next attempt and is preserved verbatim in `rejectionHistory`; a rejected project parks `blocked` until `retry` re-opens the phase (note stays applied). Wild mode parks honestly at the first human gate (classifier cannot self-approve) and pauses with an `RT_E` code when it cannot proceed (engine.ts:2725–2728).

### 1.6 The keyed live layer (what a key actually buys)
With `DEEPSEEK_API_KEY` in the server/CLI process env (deepseek.server.ts reads `process.env` only):
- **Live research:** P0/P7/P11 run real keyless web search (DuckDuckGo → Wikipedia; Tavily when `TAVILY_API_KEY`) and attach a **"Phase narrative (LLM)"** artifact + real findings (engine.ts:2362–2431, live overlay); failures degrade to the deterministic corpus with `liveUnavailable: true` — never fabricated findings.
- **Prompt expansion:** `expandBrief` (deepseek-v4-flash, JSON mode) turns the brief into an `ExpandedSpec` (requirements/edgeCases/typeSignatures/dataFlow/negativeConstraints) — the plan the later stages build on (prompt-engine.ts).
- **P6 code synthesis:** `liveP6Synthesis` (codegen.server.ts, pro-tier `deepseek-v4-pro`, `P6_SYNTH_MODEL`) upgrades the deterministic P6 module into a **brief-faithful module**: multi-class repair (signature-missing / brief-fit / forbidden-token re-prompts, mechanical export injection), bounded backoff, deterministic pre-verify validation (the "mechanical brief-fit floor"), honest refusal envelopes (`p6.synthesis.refused` log) — and on every failure **the deterministic floor stands**; no fabricated pass (codegen.server.ts header + 700–701).
- **Machine verify-fix:** `verifyAndFixServer` (verify.server.ts) has DeepSeek write executable boolean **oracle cases grounded in brief nouns + contract signatures** (anti-vacuity, verify.server.ts:487), runs them in the **bounded local Node runner** (`runNodeBounded`, node-runner.server.ts:115 — hard timeout, no-network env, temp dir, output caps; a bounded runner, *not* an OS sandbox), and on failure has DeepSeek patch the module and re-run, ≤3 iterations. **Only a real machine-run pass mints `lastTest.label === "tested"` + evidenceHash**, which is what the `p6-verified` DoD probe requires (dod.ts:172–190). `verify --apply` converges the P6 gate + packet on pass (headless.ts applyVerifyOutcome).
- **Advisory intelligence verbs:** `crew` (multi-agent review, never approves/advances), `chat` (grounded copilot turn over the project record, same server fn as the UI), `prompt`, `harvest` LLM query-building (falls back to keyword honestly), wild-mode auto-review classifier.
- **Lesson read-back:** prior-run lessons from `project.memory` are selected (`selectLessons`) and rendered into the keyed P6 expansion prompt (`lessonLinesForBrief`, codegen.server.ts:743–750) — the ONE production read-back seam.

### 1.7 The learning store
Capture is live at real seams: **L1 vague-brief** at P0 reframe when the lattice is vague (engine.ts:468–562), **L2 template-emission** when a phase seals with unmet DoD or keyed P6 synthesis is refused (engine.ts:1179–1203; headless.ts:524–561), **L5 run-summary** at terminal completion (headless.ts:567+), **L3/L4** from verify outcomes (headless.ts:1110–1112 region). Rows land in `knowledge.ts`: content-addressed ids, dedupe/idempotence, class-short taxonomy, `fusionRank` cross-project scoring (algorithms.ts), 80-row cap with `slice(-80)` eviction, vault mirror. The **read/write asymmetry remains**: read-back exists in exactly one production seam (keyed P6 expansion, above); the P0 reframe prompt, wild classifier, packet's Ranked-memory slot and `injectProven` (knowledge.ts:378) have **no production consumers**; there is **no `lesson` verb family** (no human-gated cross-project promotion) and **no counter-evidence decay driver**; P5's phase summary still says "self-learning loop is roadmap, not yet implemented" (phases.ts:48–49) — stale since capture landed.

### 1.8 Emit / scaffold — what ships to disk
`emit` (CLI) → `emitProject` (headless.ts:1001) → `scaffoldProject` (scaffold.ts, pure + deterministic: same project ⇒ byte-identical files). Per-kind tree: README.md, DEPLOY.md (honest local-only framing, E-27), `.env.example` (PLACEHOLDER values only), package.json + tsconfig (per-kind scripts), **for webapp/game: index.html + vite.config.ts + src/main** (fixes/135 boot shell — `npm run build` really runs in the emitted dir), `src/` modules derived from the spec graph with `generatedSource` hosted verbatim (a keyed brief-faithful module, or the deterministic template), **`tests/oracle.spec.ts` with REAL assertions over the emitted module's exports** (fixes/135 — the E-15 100%-todo era is gone), and `.rapidtool/project.json` (the live export). `emit --check` / `check --dir` adds per-file compile verdicts via `compile-check.server.ts` (`node --check` for JS; the `typescript` devDep's syntactic parse for TS — documented as parse-level, not a cross-file typecheck). Honest boundaries are written into the scaffold itself: the machine-verified core is the P6 module; `src/ui/` is a contract-level shell; deploy templates are recorded artifacts only.

### 1.9 The CLI and UI surfaces
CLI: **30 verbs** today — `create run gate approve reject retry ingest packet export summary vault search crew verify design diagram artifacts doctor harvest swarm prompt bench mine knowledge wild chat deepen emit check diagnose` (30 `case "` arms verified this session; README/README-cli still say 27 — doc drift). Contract: one JSON object on stdout, exit taxonomy **0** executed · **1** could-not-execute · **3** backend not configured (`RT_E_LLM_NOT_CONFIGURED`) · **4** backend runtime failure; failures carry stable `RT_E_*` codes (registry: errors.ts `ERROR_CODE_DOC`); every exit stamps an NDJSON event under `<dir>/.rapidtool/logs/`; `diagnose` reads it back. UI: Home (brief textarea + templates + builds list), Run console (progress rail `{done}/{total} sealed · {pct}%`, HITL dock, gate-log rail, phase records with gate verdict drill-down), packet tab (copy/download), Oracle tab (+ machine-verify visibility per T1.2 wiring), vault/search, design tokens + HTML preview, SVG diagrams, artifacts, memory sidebar, chat tab, runtime telemetry (rt-client installed at `__root.tsx:5,22`). Auth posture: **local-first single-tenant, no login UI** (better-auth latent only, G7 decision).

### 1.10 The honesty contract (the load-bearing asset)
No fabrication (research/code/runner results never invented; `source:"illustrative"` = scaffolding) · keyless floors (no key → deterministic scaffold + honest `RT_E_LLM_NOT_CONFIGURED`, never fake model text) · declare-or-strike P0-04 (claims must match behavior on disk) · RT_E codes on every surfaced failure · advisory-then-enforced gates (decision dated at engine.ts:1498) · append-only ledger with FNV-1a evidence hashes (integrity, not crypto) · purity-tested telemetry that never changes engine behavior. The six real keyed maker journeys confirm this holds under live keys (134 §3; 99: process honesty ≈ 8/10).

### 1.11 The one structural fracture to keep in mind
There are **two artifacts that never meet in-loop**: the isolated machine-verified P6 **module** (what verify runs) and the emitted scaffold **tree** (what emit ships — compiles + its real-oracle tests run, but nothing in the engine executes or repairs the tree). This is fixes/134's S-02 parity gap and the root of the maker 1–2/10 product score: *the generated thing is not yet the run thing*.

## §2 WHAT IS LEFT for standalone use — the ranked delta

- **Gap:** a keyed P6 journey yields ONE brief-faithful module string (`Project.generatedSource`, types.ts, ~60k cap) inside a scaffold whose remaining `src/` files are **typed stubs** (many still `throw TODO(E-15 stub)` — scaffold.ts:558/614/704/713) and a contract-level `src/ui/` shell. No `generatedTree`, no per-file content addresses, no decomposition (134 §4 S-01; 133 #4/#9 remain open in substance; make-1…5 + 99: 0 shipped brief modules, delivery ≈1/10).
- **Why it blocks standalone:** the deliverable a lone user can hold is a verified *core* + stubs — not their app. Every maker criterion M1 fails on the current tree.
- **Concrete change:** S-01/T2 — chunked sequential synthesis (typeSignatures into groups ≤8, sequential pro-tier calls with shared brief + reqTrace), additive `Project.generatedTree?: {path, source, hash}[]`, deterministic assembly into the scaffold layout, `dependencyGraph()` (arch-tools) as a new `p6-arch` probe, per-attempt file versioning. ### D2 — No journey-level iterate-until-pass and no completion gate (a red gate can still sit under a sealed run). **Blocks "set it and trust it".**
- **Gap:** the iterate loop exists only *inside* verify (≤3 iterations, ≤2 synth attempts). - **Why it blocks standalone:** a lone user cannot walk away; a failed synthesis quietly becomes a "sealed" project with a red gate deep in the records. The make-4/5 "red gate + complete coexist" is now surfaced but not prevented.
- **Concrete change:** S-03/T4 — a keyed-P6 journey driver (N bounded produce cycles alternating the recorded repair classes); on budget exhaustion the phase records FAIL with evidence and the completion path **refuses "clean complete"** while a FAIL gate stands (completion gate — make the coexistence a test assertion, 134 T4.2); success path converges the gate + stamps L4. ## §3 The honest "with a DeepSeek key today" answer — a non-technical user's walk-through

**Setup (what you need):** Node 22 installed; this folder (`RapidTool Main`); a DeepSeek API key. The CLI reads `DEEPSEEK_API_KEY` from the environment only (README-cli — it does not auto-load `.env`; export it in the shell: `set -a && . ./.env && set +a` in git-bash, or set it in the terminal profile). The browser app needs the key visible to the `npm run dev` server process the same way (export before starting it). `npm install` once.

**The 40-minute honest journey (CLI, one project):**
1. `node --experimental-strip-types scripts/rapidtool-cli.mjs doctor` → confirms `llm: configured`, `research`, `runner: available`. (30 seconds.)
2. `create --brief "Build me a rental-portfolio tracker: properties, tenants, leases, rent due dates and payment history, with monthly income reports." --name "Rental Ledger" --out rental.json`. Deterministic intake: 13 phases, P0 current. (Instant.)
3. `gate --project rental.json --live` → advances P0–P3 deterministically, and because you're keyed and `--live`, P0/P7-style research phases run **real web search** (keyless DDG/Wikipedia) and attach **"Phase narrative (LLM)"** artifacts + findings rows; artifacts accumulate (scorecard, spec graph, contracts, memory rows, tool plan). The run **parks at P4 (Security — stock HITL)**. Nothing self-approves. (~2–4 min; the phase work is deterministic, the live overlay is the variable.)
4. You read the P4 artifact in the JSON (`export` or `packet`), decide, and `approve --project rental.json` (or `reject --note "…"` with 12+ chars, which parks `blocked` → `retry` → re-run; the note steers the next attempt and is preserved forever).
5. Loop `gate --live` → decide at P5 (HITL) → P6 arrives. **P6 is the moment of truth:** with the key, the engine runs `expandBrief` (flash) then `liveP6Synthesis` (pro) — the brief's type signatures become a **single brief-faithful TypeScript module** (properties/tenants/leases/rent/payments vocabulary — the `p6-brief-fit` probe passes when ≥ half the required brief nouns appear as identifiers). If synthesis refuses (timeout/signature/brief-fit/parse), it retries with backoff, runs repair re-prompts, and if it still fails **the deterministic template stands with an honest `p6.synthesis.refused` log** — you see a red P6 gate, never a fake pass. (~2–6 min; pro-tier synthesis + backoff.)
6. `verify --project rental.json` → DeepSeek writes executable boolean oracle cases **grounded in the brief's nouns and the module's contract signatures** (anti-vacuity — no more "5/5 on a toy"), the bounded local runner executes them, and on failure the module is patched and re-run, ≤3 iterations. Only a real machine-run pass mints `status: "passed"` with an evidence hash. (1–4 min.)
7. Keep going: P7 (live research), P8 (**parks — HITL** — UI/UX contract with screens derived from product surfaces, never one-per-verb), P9 (**parks — HITL**), P10–P12 deterministic (edge/realtime/docs, OpenAPI). Final `gate` seals the run — and if any gate FAILed, the summary honestly says so (`sealedWithFailures: true`, `failedGates: [...]`) instead of a clean bill.
8. `emit --project rental.json --out rental-app/ --check` → writes the scaffold **folder**: README/DEPLOY/.env.example, package.json + tsconfig, `index.html + vite.config.ts + src/main.tsx` (webapp kind — it really builds), `src/` files hosting the **machine-verified module** plus typed stubs for the rest, `tests/oracle.spec.ts` with **real assertions**, `.rapidtool/project.json`, and `--check` prints a per-file compile verdict. In the emitted folder: `npm install && npm test` runs the real oracle tests against the real module.
9. Also yours, free: `packet` (the paste-ready Agent Packet v3 + System JSON), `design --html` (design tokens + a standalone HTML preview), `diagram --kind phases|architecture|flow` (SVGs), `vault` (Obsidian-importable notes) + `search`, `artifacts` index, `summary`, `chat --ask "…"` (a grounded copilot over the project), `swarm` (deterministic advisory critique), `bench` (synthetic estimates), `harvest` (bounded real-repo/license research), `crew` (advisory multi-agent review), `knowledge --store …` (your own cross-project pattern file), `wild --start` (bounded macro-run that parks honestly at every human gate).

**What you actually get (the honest box):** a **governed, auditable, machine-verified single-module core** for the brief's domain, embedded in a **bootable scaffold with real oracle tests**, wrapped in genuinely useful planning/research/design/documentation artifacts — and a decision ledger that proves how it was made. For a **library / CLI / service / data-module** brief, that core + scaffold is close to a real first artifact. For a **webapp** brief you get the verified core + a UI *contract shell* (honestly labeled) — the screens and flows are **not** generated as working UI.

**What you do NOT get (the honest negatives):** the full multi-file product (D1), a run that fixes its own emitted tree until it passes (D2/D3), cross-project memory that makes the next brief smarter (D5), or a machine scorecard proving the run was good (D6). The six real keyed journeys behind this repo (rental portfolio, field-ops, showing booking, flip manager, CRM, Coffeehouse2Home merge) each ended at **product delivery ≈ 1–2/10** with **process honesty ≈ 8–9/10** — and every fix wave since (135's bootable emit + real oracles, compile-check, verify-UI seam, enforcement default, failed-gate census, P8 fix) moved the *seams*, not yet the *substance bar*. A non-technical user should treat today's RapidTool as: **"a rigorous, honest pre-flight + verified-core generator for small modules, and a governed project compiler — not yet the thing that builds my app."** The delta list in §2 is precisely the work between those two sentences. The UI path (browser at `localhost:8080`) is the friendlier surface for the same engine — same phases, same parks, same honesty — but the CLI is where the full 30-verb surface and `emit`/`verify`/`diagnose` live today.
