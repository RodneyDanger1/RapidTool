## 5. The five most important findings (with evidence)

**1 · A3-01 — The "pipeline now" line reports the console's own main-thread jank, not the run.** `src/components/pipeline-rail.tsx:122-183` checks the client telemetry ring *first*. Rendered evidence (`fixtures.png`, `run-after-p0.png`): `RING 16:12:56 sys.longtask Main thread blocked 281ms (Long Tasks API). newest row of the client telemetry ring · 1 row this page session` — shown even after a four-phase run that parked at the P4 approval gate. The single line an operator reads to answer "what is the machine doing?" answers "your UI thread blocked for 281 ms". *(M, S)*

**2 · A3-02 — The stall latch can never clear; the console can show `Stalled` forever.** `setStallLatch` is written on a critical heartbeat (`rt-client.ts:548-562`), persisted (`:352`) and rehydrated (`rt-ring.ts:239-258`), and read by `PipelineRail` (`:440,491-497`). `clearStall` (`rt-client.ts:359-363`) has **0 production callers** — only `rt-client.test.ts:103`. Trigger it once (wild run + a ≥10 s main-thread stall) and the `<Stalled …>` row survives the run and a reload. The companion `requiresHumanResume` invariant is likewise never consumed. *(M, S)*

**3 · A3-03/A3-04/A3-05 — Four fully-built, fully-tested subsystems have zero production wiring.** `plugin.ts` (T5.5 hook registry) imports only from `plugin.test.ts`; `compaction.ts` (T-107.9) only from `compaction.test.ts`; `watchdog.ts`'s decision math only from `watchdog.test.ts` while its doc claims the store/headless drivers use it; and `swarm.ts`'s DAG/loop-back exports are unreachable. The roadmap promises extension points, compaction, freeze-class decisions and a swarm advisory layer that no shipped code path exercises. *(M, M/S each)*

**4 · A3-15 — The factory is steerable but partly opaque from its own console.** A browser operator can see phase/gate/DoD/decision state and can run, approve, reject, retry (verified: Approve at P4 advanced to P5).
