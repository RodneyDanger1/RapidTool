## 1. Findings (file:line + what is wrong/risky)

### F1 — EMIT-DIR vs LEDGER DIVERGENCE IS OBSERVED IN SHIPPED EVAL ARTIFACTS (P0)
`research/eval-out/coffeehouse2home-property-ledger/`:
- `.rapidtool/project.json` declares `generatedTree: [{path: "src/generated.ts",
  hash "3477377620", 38,049 B}]` and `lastTest {label:"tested", evidenceHash
  "1689581842"}` — but **no `src/generated.ts` exists on disk** (`src/generated/`
  is absent) and `src/jobs/track.ts` (38,670 B) is the *non-tree* host file
  (`emitGeneratedHost` header at scaffold.ts:711-733) wrapping `generatedSource`.
- `lastTest.detail` = "tree-run green: compile 12/12 file(s) · 1 spec file(s) pass
  · 16 assertion(s) · entry webapp skip" — the treeRun verdict was computed over
  a file set that contains **none** of the ledger's declared tree row at its
  declared path. `results.json` scored that card M1=1 M2=1 … total 9/9.
- Mechanics: `emitProject` (headless.ts:1018-1044, result type 1001-1009) never cleans the target dir
  (`mkdirSync` + blind `writeFileSync`, no `rm`), and `run-eval.mjs` reuses
  `research/eval-out/<slug>/` across runs and modes (no wipe between keyless and
  keyed legs). The dir is a first-class artifact (headless.ts:1469 "the emitted
  dir is a first-class ARTIFACT; the project JSON is the LEDGER") but the eval
  never re-imports it: `importTreeDir` (headless.ts:1557-1625, hash-checked
  dir→ledger) is **never called** by run-eval.mjs, so a stale or partial disk
  state is scored as if it were the ledger state.
- Canonical-score-source answer: **neither** is canonical today — M1/M3/M4/M5 read
  the in-memory `finalProject` ledger, M2/M6 read the disk; nothing binds them.
  SLSA's model (provenance: record inputs as `externalParameters`, artifacts as
  content digests, run as `invocationId`) is exactly the missing glue
  (cite [W2]).

### F2 — F1 MULTI-FILE EXPANSION IS NOT "IMPORTABLE MODULES"; IT IS A ONE-FILE IIFE DUMP + ORPHAN FRAGMENTS (P0)
- `assembleTreeEntry` (codegen.server.ts:520-543) concatenates every chunk inside
  `(function (module, exports, <prior names…>){…})(module, module.exports, …)`
  — **scope-sharing by wrapper parameters, not ESM imports**. Later chunks call
  earlier exports as bare free identifiers bound only by the wrapper.
- Chunk paths: chunk 0 always `src/generated.ts`, chunk i>0 under
  `src/generated/<slug>.ts` (codegen.server.ts:492-518). The scaffold in tree
  mode pushes every tree file **verbatim** (scaffold.ts:1945-1947) and emits
  `generatedSource` (the assembled entry) **nowhere** — the host branch is
  non-tree only (scaffold.ts:2006-2021). Tree entry resolution prefers the first
  job node's spec-graph path, falling back to `src/generated.ts`, else the first
  sorted file (scaffold.ts:1894-1904).
- Consequences: (a) the oracle spec and every job bridge import **only the entry
  file**, which in a >1-chunk tree is chunk 0 alone — chunks 1..N are emitted but
  never imported, never executed, never cross-checked; treeRun (compile-check:
  walkSpecFiles under `tests/` only, entry smoke = one module) certifies chunk 0 +
  the scaffold oracle, **not the tree**. (b) A chunk i>0 file imported standalone
  is broken at runtime (free identifiers → ReferenceError on call). (c) Real
  observation: the only keyed tree in `eval-out` is **one 38 KB chunk on one row**
  — "splitting" never produced >1 file in any shipped artifact. The 162 §1 claim
  "multi-file expansion … emits a real ~38 KB module" is byte-accurate and is the
  problem: the tree did not expand.
- Risk: M1 (ledger identifier scan over ALL tree rows) can be 1 while M2/M3/M4
  certify only the entry; a red later chunk is invisible to every criterion.

### F3 — THE testsPass ADAPTER EXISTS, IS CONSISTENT, AND IS *DISPLAY-ONLY* — BUT ITS SEMANTICS ARE ASSERTION-COUNT, NOT SPEC-PASS (P2)
- Adapter: `treeRunToEvidence` (run-eval.mjs:235-263) bridges TreeRunOutcome →
  MakerTreeRunEvidence correctly for the shape: `testsPass` = Σ over
  `outcome.tests[].tests.pass`, `testsFail` = Σ `[].tests.fail`
  (TreeSpecVerdict.tests = {pass, fail} *assertion* counts, compile-check.server.ts:252).
- Consumer: m2Runs (maker-score.ts:324-345) reads `tr.testsPass` only in the
  **evidence string** (line 328); the M2 score keys solely on `tr.ok === true`.
  So no score depends on the counts — the "inconsistency" is a hazard, not a bug:
  the name reads as "all tests passed (bool)" while it carries "assertions that
  passed (int)". A green UI-shell run (`entry webapp skip`, 0 spec assertions)
  prints "tests 0 pass / 0 fail" under a green treeRun — misleading on its face
  (observed in the real lastTest: "1 spec file(s) pass · 16 assertion(s)" is only
  in the mint summary; the evidence string for the same run shows 0/0 when no
  specs ran).
- Deeper gap: **nothing cross-checks the treeRun verdict against the ledger's own
  lastTest/evidenceHash**. The journey mints `lastTest` from a *temp-dir* treeRun
  (driveP6Journey seam, headless.ts:1228-1266; mint seam codegen.server.ts:1654-1693)
  and run-eval then treeRuns the *final* dir (run-eval.mjs:417) — two different
  dirs. A red final treeRun gives M2=0 while the journey-minted M4 stays 1.
  `mintTreeRunTested` is honest per-dir, but the eval never verifies the minted
  stamp equals the evidence it scored (same dir, same byte set).

### F4 — NON-DETERMINISM: project.id (randomUUID) + createdAt + log ts LEAK INTO EVERY EMITTED ARTIFACT (P1)
- `emptyProject` (engine.ts:1697-1715): `id: crypto.randomUUID()` (fallback
  `p-${Date.now()}`), `createdAt: Date.now()`. Headless `createProject`
  (headless.ts:96-102) → `emptyProject`. run-eval calls `createProject` per entry
  (run-eval.mjs:343) — so **two keyless runs of the same brief produce different
  packet ids**.
- `MACHINE_STAMP(id)` (scaffold.ts:103-104) is embedded in the header of every
  emitted source file (scaffold.ts:573, 1029), in `package.json`
  `generatedBy` (scaffold.ts:510, 1360), README/DEPLOY surfaces, and the emitted
  `.rapidtool/project.json` (scaffold.ts:1923) carries `createdAt`, `logs[].ts`
  (Date.now, e.g. engine.ts:1724+), and the timestamped decision ledger.
- Net: **same packet ⇒ NOT byte-identical emitted tree** — even in keyless mode
  with no LLM call. Scores are unaffected (scoreMaker reads no id/createdAt/ts),
  but every reproducibility claim about artifacts, any content-address on the
  emitted dir, and the SLSA-style `resolvedDependencies`/digest story (cite [W2])
  breaks at the header line.
- Everything else audited is clean on this axis: evidence hashes are pure
  `fnv1a` over content strings (codegen.server.ts:546-549, 921, 1556; dod.ts:488-511;
  algorithms.ts:1096) with no clock/random input; compile-check walks dirs in
  sorted order (compile-check.server.ts:149, 316); scaffold tree rows sorted by
  path (scaffold.ts:1891); `Math.random` appears only as injectable retry jitter
  in the keyed LLM client (deepseek.server.ts:78-82, 183) — it cannot fire in
  keyless mode and never reaches evidence strings. **Pin list below targets the
  id/createdAt leak as the only artifact-level nondeterminism.**

### F5 — M7 IS STATEFUL: SAME PACKET SCORES DIFFERENTLY BY WALL-CLOCK HISTORY (P1)
- `priorFor` (run-eval.mjs:218-224) takes the **last history row for the slug**
  with **no mode/packet filter**; `history.json` appends every run with an ISO
  timestamp (run-eval.mjs:589-609). Real history: coffeehouse2home-property-ledger
  has 6 rows — keyless (0,0,0) then 5 keyed rows; a later `(1,1,1)` row re-scored
  after an even better row would regress M7 to 0 for an *identical packet*.
  Re-running the corpus on a fresh checkout (empty history) vs a warm box yields
  different M7 scores for the same packet. M7 evidence claims "learning", but the
  comparator is *chronologically last run of the slug*, mixing keyless floors and
  keyed journeys and different briefs that share a filename-slug.
- fix needed: prior = last **same-mode** row whose packet/briefHash matches (or
  freeze the prior into the packet at run start), and exclude M7 from the
  byte-reproducibility gate or record its inputs.

### F6 — DROPPED STATE: corpus `acceptance` and `expectedNouns` ARE LOADED AND NEVER SCORED (P1)
- `loadCorpusEntry` reads `acceptance` (run-eval.mjs:179) and `expectedNouns`
  (run-eval.mjs:177); `scoreMaker` corpus carries `expectedNouns`
  (maker-score.ts:51, wired run-eval.mjs:462) — **no criterion ever reads either**.
  M1 keys off `expectedCapabilities` + kind + brief (maker-score.ts:274-320); no
  criterion reads `acceptance` at all. The corpus's own human-authored pass-bar is
  dead state; M6's `oracleSpecBytes >= 100` (maker-score.ts:454) is a size proxy,
  not the acceptance fixtures. 162 §0's "honest bar" (external human-approved
  fixtures) therefore has **no score wire** yet.

### F7 — DROPPED STATE: scaffold tree-refusal WARNINGS VANISH IN THE EVAL PATH (P1)
- `scaffoldProject` returns `warnings` for refused tree rows (scaffold.ts:2044-2049;
  refusals at 1858-1889). `emitProject` (headless.ts:1018-1044) returns
  `{ok, dir, files, summary, moduleEmbedded}` — **no warnings field** — and
  run-eval's handover evidence (run-eval.mjs:410-415) records emitted/deployMd/
  oracleSpec only. A tree row refused at emit (bad path, duplicate, reserved
  file) stays in the ledger → M1 counts it (treeFilesOf, maker-score.ts:209-221)
  → M1=1 while the file was never written; the refusal is invisible to the card.

### F8 — DROPPED STATE / MISALIGNED EVIDENCE: two treeRuns, one stamp, no binding (P2)
- Covered in F3: journey temp-dir mint vs run-eval final-dir verdict, plus
  `emitResult.warnings`/`moduleEmbedded`/`summary` never read by run-eval
  (run-eval.mjs:395-427). `moduleEmbedded` (does the emitted tree actually contain
  `generatedSource` bytes?) is computed (headless.ts:1041-1042) and discarded —
  it is the cheapest possible "ledger↔disk agreement" probe and nobody consumes it.

### F9 — SCORING-TIME REPRODUCIBILITY GAPS IN THE PERSISTED LEDGER (P2)
- `results.json`/`history.json` embed `generatedAt`/`at` ISO timestamps
  (run-eval.mjs:578, 590) — fine as metadata, but there is **no run-id, no
  packet-content hash, no corpus hash, no code-version hash** on the row, so two
  rows are indistinguishable except by wall-clock time (SLSA `invocationId` +
  `externalParameters` digests, cite [W2]). `entryRow` also persists `coverage`
  and criteria but not the **emitted-dir tree hash set**, so a later re-score of
  history rows cannot detect that the artifact drifted (F1).
- `mean`/`total` math is stable (integer sums); `mean.toFixed(4)` on the card is
  FP-deterministic for identical inputs — no issue found there.

  Maps 1:1 onto 163-B: our packet/corpus/code-version = externalParameters,

- [W3] Reproducible Builds project — definitions: a build is reproducible when

## 3. Ranked plan-patch additions (merge-ready for fixes/162, phase-gated)

### PATCH-A (Phase: eval driver / 163-B land, P0) — canonical score source + dir hygiene
1. `run-eval.mjs` `evaluateEntry`: before scoring, call `importTreeDir(finalProject,
   emitDir)` (headless.ts:1557) and (a) fail loudly / zero M2+M6 when
   `missing.length > 0` (ledger row absent on disk) or `changed.length > 0`
   (disk differs from ledger hash), (b) persist the dir's per-file fnv1a hash set
   onto the entry row (`artifactHashes: {path: hash}`) and the row's
   `runId`/`packetHash`/`corpusHash`/`codeVersion` (fnv1a over corpus frontmatter
   + package.json version + engine file hash).
2. `emitProject`: wipe `dir` (rm -rf contents or emit into `dir/.tmp` + rename)
   before writing, OR add `clean: true` option used by run-eval; propagate
   `scaffoldResult.warnings` + `moduleEmbedded` through `EmitProjectResult` and
   record them on the row (F7/F8).
3. New invariant check in `scoreMaker` input contract: when `handover.emitted`,
   require `treeRun.dir` hashes ⊆ ledger hashes (re-import result passed in as
   `MakerRunEvidence.ledgerDiskAgree: boolean`); M2 evidence string must name the
   check result.
4. Canonical source documented in AGENT_GUIDE/162: **the ledger row + the dir
   re-import are canonical; a card is valid only when ledgerDiskAgree=true.**

### PATCH-B (Phase: 163-B land, P0) — F1 assembly verification + entry truth
1. Tree-mode scaffold: emit the **assembled entry** (`generatedSource`) at the
   entry path so the runnable whole is on disk, OR make the entry a real module
   that imports each chunk file (requires chunk sources to stop being
   import-free: prompt contract change). Until then, add to `treeRun` a
   "whole-tree load" verdict: dynamically import/require **every** emitted tree
   file (not just entry) and mark `run:error` on free-identifier crashes —
   later chunks become executable evidence instead of orphans (F2).
2. Assert in a maker-score/multi-file test: for a 2-chunk tree, the emitted
   per-chunk files are each loadable; add a scaffold test asserting the entry
   path is emitted in tree mode and contains (or imports) all chunk sources.
3. `run-eval.mjs`: when the keyed journey converged with >1 tree row, require
   `treeRun` evidence to show ≥1 executed assertion **per chunk file** before M2=1
   (either per-file specs or the whole-tree load above).

### PATCH-C (Phase: 163-B land, P1) — determinism pins (W3: strip timestamps/ids from outputs)
1. `emptyProject`: accept an optional `{id?, createdAt?}`/`seed` param; headless
   `createProject` and run-eval derive a **deterministic id** = `p-<fnv8hex(brief)>
   [-<runSeq>]` when no id supplied (keyed UI keeps randomUUID; eval/CLI headless
   get packet-stable ids). Keep `createdAt` out of emitted headers.
2. `scaffold.ts` MACHINE_STAMP: emit `packet <stable-id-or-briefhash8>` and stop
   stamping `createdAt`/wall-clock into source headers and package.json
   `generatedBy`; move timestamps to `.rapidtool/project.json` metadata only.
3. Reproducibility gate (new test + optional CI script `scripts/repro-gate.mjs`):
   run the SAME corpus entry keyless twice into two clean `EVAL_OUT_DIR`s; assert
   (a) identical emitted file bytes except `.rapidtool/project.json`'s metadata
   keys (allowlist `createdAt/adr ts/logs ts`), (b) identical criteria scores and
   identical `entryRow` except `at`. Land as a `maker-score`/scripts test so the
   four gates cover it.

### PATCH-D (Phase: 163-B land, P1) — M7 prior determinism (W1/W2 run-id discipline)
1. `priorFor` filters `h.mode === mode` AND same `packetHash`/`briefHash` AND
   same corpus hash; `history.json` rows gain `mode`, `packetHash`, `corpusHash`
   (computed in PATCH-A). Re-score of an old packet then compares like-for-like.
2. When no same-packet prior exists, M7 evidence string must say
   "no prior same-packet run" (score 0) instead of borrowing an unrelated slug
   run. Freeze M7 inputs at run start (snapshot the prior row into the result
   row) so re-derivation is impossible.

### PATCH-E (Phase: later / 162 Phase A alignment, P1) — wire the dropped corpus state
1. `MakerCorpusExpectation` gains `acceptance?: string[]`; `scoreMaker` input
   gains `acceptanceRun?: {verdict: "pass"|"fail"|"not-run"; detail?: string}`
   gathered by the driver from an external harness run (162 §0 fixtures), and a
   new criterion (extend to M10 or fold into M6 evidence) scores it. `expectedNouns`
   either feeds M1's brief-fit vocabulary (merge into `brief` checks) or is
   deleted from the type to stop the dead-state illusion (F6).

### PATCH-F (Phase: 163-B land, P2) — testsPass semantics + mint/verdict binding
1. Rename `MakerTreeRunEvidence.testsPass/testsFail` to
   `assertionsPassed/assertionsFailed` (or document as assertion counts in the
   type + m2 evidence string "N assertion(s) passed / M failed"); keep the
   adapter math. Fix the 0/0-on-skip wording: when `ok && tests.length === 0`,
   print "no spec files executed (entry <kind> <run>)".
2. In run-eval, when `finalProject.lastTest.label === "tested"`, verify the
   minted evidenceHash recomputes from the FINAL dir's treeRun outcome summary
   (`treeRunTestedEvidence` on the final outcome); mismatch ⇒ set M4 evidence to
   "mint/verdict dir mismatch" (score 0) — binds the temp-dir mint to the scored
   dir (F3).

### PATCH-G (Phase: 163-B land, P2) — evidence-hash upgrade note
fnv1a stays for integrity (AGENTS.md §6), but the eval row should additionally
carry a collision-safe digest of the emitted tree bytes (sha256 of the sorted
path→hash manifest) as the artifact id — cheap, no engine change; gives W2's
`ResourceDescriptor.digest` for downstream consumers.
