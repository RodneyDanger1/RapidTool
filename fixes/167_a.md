## Findings

### 167A-1 — LLM-authored code executes with full host-user privileges; the "sandbox" is a lexical denylist + timers (Codex/OpenHands: OS/Docker isolation)
- **WHAT + WHY**: Codex runs model-generated commands under OS-enforced sandboxes — `bwrap` + `seccomp` (Linux), Seatbelt `sandbox-exec` (macOS), a native Windows sandbox; writes are confined to the workspace, `.git`/`.agents`/`.codex` are protected read-only, network is **off by default** (Codex "Agent approvals & security" doc; `docs/sandbox.md`). OpenHands' core promise is "safe interaction with **sandboxed environments for code execution**" — each agent session executes in its own Docker container via `openhands/runtime/impl/docker/docker_runtime.py` (same interface for E2B/Daytona/Modal/remote runtimes). The guarantee that matters: **code the LLM wrote never runs with the harness's own OS credentials**. RapidTool's keyed builds have the LLM author modules that are then executed for tests — today that execution is a `node -e` child of the app process.
- **RapidTool status**: **ABSENT** — the code says so itself:
  - `node-runner.server.ts:4-17` (load-bearing honesty label): "*bounded* execution environment, NOT a security sandbox… the child can touch anything the OS user can… no memory/CPU rlimits… real network denial… Only an OS-level boundary (Docker / WSL2 / Windows Sandbox / AppContainer / VM) contains a determined adversary. **Do not run untrusted third-party code here.**"
  - What exists is bounded-ness, not isolation: wall-clock timeout + `taskkill /T /F` tree-kill, 1 MB output caps, scratch temp cwd ("courtesy, not a jail"), scrubbed child env / `NO_PROXY="*"` (`node-runner.server.ts:8-14,164`); `MAX_BUFFER`/`DEFAULT_TIMEOUT_MS` 30 s (`node-runner.server.ts:66-73`).
  - Template path: `runGenerated` executes via `new Function` in the page/process global, gated by a lexical `FORBIDDEN` regex (`sandbox.ts:34-38,108-111`) — and the file itself notes the worker-isolate executor is deprecated with zero product call sites (`sandbox.ts:115-124`).
  - The product's own P4 gate text asks the operator to "Confirm the implemented execution boundary" and prints `sandboxClaim()` (`engine.ts:745-750`), and `sandboxClaim` only ever claims "Engine-template runner (bounded, engine-authored code only)" or a worker isolate that no longer exists (`sandbox.ts:178-184`). `project.sandbox.ramMb` is *described* (`engine.ts:746`) but never enforced anywhere (node-runner admits no rlimits).
- **WHERE**:
  - `src/lib/node-runner.server.ts` (runner impl — the seam to harden), `src/lib/exec.ts` (client-facing wrapper; already has an injectable `runner` DI seam "for tests only", `exec.ts:23-28`), `src/lib/sandbox.ts` (`sandboxClaim`/`runGenerated`), `src/lib/engine.ts:745-750` (P4 gate copy), `src/lib/store.ts:1310+` `runModuleReal` (UI path that spawns the bounded runner; 165A-8 shows it has no busy latch).
- **HOW (RapidTool-idiomatic, phased)**:
  1. *Refuse-by-default (cheap, do now)*: add an explicit `SandboxMode` on `Project.sandbox` (`types.ts` sandbox type): `"engine-template"` (current, template-only) | `"bounded-host"` (today's node-runner, allowed **only** for engine-authored modules) | `"os-sandbox"` (requires a configured backend). `runModuleReal`/`exec` refuse `ok:false, code:"RT_E_VALIDATION"` when a module is LLM-authored and mode is not `os-sandbox` — mirroring the `runGenerated` refusal message pattern (`sandbox.ts:97-101`). Ship the honesty copy change first: the P4 gate text (`engine.ts:745`) must say "runs with host-user privileges" until a real boundary is configured.
  2. *OS boundary behind a seam (medium cost)*: implement `runner` variants in `exec.ts`'s existing DI shape — a `"docker"` runner (spawn inside a pinned image container, workspace mounted read-only + a scratch volume writable, `--network none`, `--pids-limit`, no host env) and/or a `"wsl"`/`"windows-sandbox"` note for Windows hosts. Keep the honest `sandboxClaim` the single source of truth and drive it from the resolved mode. Lazy-load the backend module only when configured, exactly like the `wild-mode.server.ts` lazy import idiom at `engine.ts:27-28` (server boundary, keeps the client bundle clean).
  3. Do **not** claim more than the honest label: gate the whole feature behind explicit operator opt-in (P4 HITL already exists for exactly this, `phases.ts:42`).
- **TEST**: unit — `runModuleReal` with an LLM-authored module under `bounded-host` returns the refusal code and writes an honest `log` row (mirror `sandbox.test.ts` refusal pins); unit — `sandboxClaim()` output changes when mode flips; integration — docker runner variant: module that writes outside the scratch volume fails, module that binds a socket fails (`--network none`), 30 s `test_no_skip` still passes (keeps `treeRun`/m2 green); existing 1447 suite must stay green because the default mode keeps today's behavior byte-identical.

### 167A-2 — Token/cost usage is parsed then discarded: no run-level ledger, no budget, no hard stop (Codex: `SessionBudgetExceeded`; OpenHands: `accumulated_cost` + THROTTLING)
- **WHAT + WHY**: Codex meters both rollout and per-turn token budgets and turns an exceeded budget into a hard typed error — `record_rollout_budget_usage` returns `Err(CodexErr::SessionBudgetExceeded)` (`session/rollout_budget.rs`), with per-turn `token_budget.rs` and a startup preflight (`config/token_budget_startup.rs`). OpenHands accumulates per-LLM-call cost in `Metrics.accumulated_cost` (`llm/metrics.py:67-74`) and the controller's traffic control pauses the agent at `max_iterations`/`max_budget_per_task`, THROTTLING state, and a human continue doubles the cap (`controller/agent_controller.py:600-660,905+`). RapidTool's wild mode auto-loops up to a **20-step cap** (`store.ts:1088-89`) with live LLM calls per step — today nothing measures or stops total tokens/cost.
- **RapidTool status**: **ABSENT** as a run-level control. Per-call usage IS parsed: `deepseek.server.ts:171` (`usage?: {prompt_tokens…, completion_tokens…}`) and `:427-432` (extracted into the typed result) — then nothing accumulates it. All other "budget" hits are prompt/context/output *token budgets per call* (`codegen.server.ts:110-130`, `deepseek.server.ts:39-51`, `chat.server.ts:324`) or wall-clock (`WILD_STEP_BUDGET_MS`, `rt-events.ts`, `diagnose.ts:145-158`). No `maxBudget`-style field exists on `Project`/run config (`types.ts`).
- **WHERE**: `src/lib/deepseek.server.ts:171,427-432` (usage source), `src/lib/rt-events.ts:161-167` (`llm-call` event kinds — the natural ledger row), `src/lib/runtime-log.server.ts` (append point), `src/lib/store.ts:1067-1090` (wild driver loop — the check site), `src/lib/engine.ts:3468+` `wildStep` (per-step), `src/lib/headless.ts` (CLI runs), `src/lib/types.ts` (config field).
- **HOW**: (a) add `RtEvent` kind `llm.usage` (or extend `llm.ok` rows) carrying `promptTokens`/`completionTokens`; (b) pure accumulator `addUsage(ledger, usage)` + `budgetExceeded(ledger, budget)` with an injectable clock, unit-tested like `jitteredBackoffDelayMs` (`deepseek.server.ts:76-81`); (c) thread a `tokenBudget`/`maxCostUsd` through the wild driver (`store.ts`) and `headless.ts` drive loops; on exceed, **park with a distinct reason + honest log** exactly like the existing step-cap park (`store.ts:1088-89` "budget" vs "cap"), never a silent stop; (d) surface the running ledger in the console strip (read from the ring) so the operator sees spend like OpenHands' frontend metrics. Keep it honest: without a key there are no tokens — ledger stays empty (deterministic runs cost nothing and say so).
- **TEST**: unit — accumulator/budget-exceed pure tests with pinned usage rows; store-level — stub `wildStep` usage to blow a tiny budget → run parks with `stoppedReason:"budget"` + a `log` row, `wildRun.pause` state matches the cap-park shape (`store.ts:1088`); headless e2e (probe-b2 style) — CLI run with `--max-budget` exits non-zero with the machine code, not a silent success.

### 167A-3 — No durable run journal / resume-from-checkpoint; a wild run dies with its driver on reload (OpenHands: EventStream + EventStore + replay)
- **WHAT + WHY**: OpenHands' architecture is the event stream: every action/observation is an event persisted to an EventStore (`openhands/events/stream.py`, `event_store.py`); agent state is *derived* from the stream, so a session can be replayed/resumed (controller `replay.py`). Codex persists thread/session state (`codex-rs/core/src/state/`, `session_prefix.rs`) and resumes with `--continue`. RapidTool's console feed is a capped in-memory ring (`rt-ring.ts:23,138-143` rows + byte caps) — it dies with the tab; the headless NDJSON log (`runtime-log.server.ts`, 5 MB × 4 files) is append-only telemetry for `diagnose`, not a replay substrate; and the code itself states the design limit twice: "no durable checkpoint layer" (`phases.ts:25`) and "Session-break honesty: a live run cannot outlive the driver that drove it" (`engine.ts:1960`, the reload-stop path that 165A-4 mislabels in the UI).
- **RapidTool status**: **PARTIAL**. What exists is *phase-level* durability — the 13-phase state machine + gate records persist on `Project` after every committed gate (`store.ts` persist slice + `db.ts` PGLite/KV), so an interrupted run can be *re-driven* from the last committed gate; and in-session pause/resume for wild runs (`store.ts:991-1032`, `headless.ts:2789-2811 wildResumeRun`). What is missing is a **run-scoped event journal** (one JSONL file per run id) + an idempotent resume verb that replays to the last checkpoint and continues — the difference between "re-drive" and "resume".
- **WHERE**: `src/lib/runtime-log.server.ts` (the fs owner — extend, never the client ring), `src/lib/rt-events.ts` (schema: add `run.checkpoint` rows carrying the committed gate + phase), `src/lib/engine.ts:1960` (reload-stop honesty → make it a checkpoint stop), `src/lib/store.ts` (hydrate path), `src/lib/headless.ts` (new `resume` verb beside `wildResumeRun`), `src/routes/run.$id.tsx` (run screen).
- **HOW**: (a) per-run JSONL journal under the existing `logs/` dir (`runtime-log.server.ts` already owns rotation + torn-line handling — reuse `resolveLogDir`/`appendRtLine`); (b) on every committed gate, append a `run.checkpoint {runId, phase, gateVerdict, seq}` row — content deterministic (gate + evidence hash, no wall-clock in the payload), matching the 158_s1 S1-02 replay-law note; (c) a pure `checkpointAfter(journal)` that returns the last committed gate id (unit-testable); (d) `headless resume <project>`: load project, replay the journal, re-run from `checkpointAfter` — the state machine makes re-running idempotent (deterministic gates); (e) for wild runs, persist the run driver state (`phase`, `epoch`) in the checkpoint so a reload can offer "Resume" instead of the current stop-paragraph (`engine.ts:1960-1963`, the 165A-4/5 surface).
- **TEST**: unit — journal append/rotate/`checkpointAfter` on fixture rows (mirror `runtime-log.server.test.ts`); integration (probe style) — kill a headless run mid-phase after a committed gate, `resume` → first phase re-executes from the checkpoint and the journal shows no duplicate checkpoint; wild e2e — reload mid-wild-run → strip offers Resume from the last checkpoint row; byte-parity test that a run with zero committed gates resumes at P0.

### 167A-4 — No operator-level ask-vs-auto confirmation policy, and OS-spawning actions need no confirmation (Codex: `approval_policy`; OpenHands: `confirmation_mode`)
- **WHAT + WHY**: Codex separates *capability* (sandbox mode) from *confirmation* (`--ask-for-approval on-request | untrusted | never`, per-tool `AskForApproval`, granular policies, `approvals_reviewer = auto_review`, `tools/approvals.rs`); OpenHands flips a `confirmation_mode` that stops the loop at `CmdRun`/`IPython` actions until a human confirms (`agent_controller.py:856-860`, `AWAITING_USER_CONFIRMATION`), backed by the SecurityAnalyzer framework (`security/README.md`, Invariant confirmation). RapidTool's gates are *phase-scheduled* (the pipeline stops at P4/P5/P8/P9 because the phase says so) and wild mode auto-continues everything that is not `forceHuman`. What neither provides is an operator knob for *action-class* confirmation — notably, "Run module (bounded)" spawns a real OS process on a single click with no confirmation and no policy gate (the 165A-8 re-entry/latch gap is the same surface).
- **RapidTool status**: **PRESENT-PARTIAL** — HITL phases + `forceHuman` never machine-cleared: `phases.ts:42,50,74,82` (P4/P5/P8/P9 `hitl: true`), `engine.ts:764` ("forceHuman gates (reframe, failed sandbox) can never be autopilot-approved"), `store.ts:91,1456` `approve(id,{force})`, `store.ts:369` M-09 (autopilot must not approve a phase failing its DoD), `headless.ts:637` (CLI `force` override), console approve dock + override checkbox (165A-3). Wild mode auto-decides non-forceHuman gates (`engine.ts:3105,3468` `wildStep`, "bounded autonomous step"). Missing: (1) a per-project/per-run confirmation *policy* (`ask-all | auto-nonforcehuman | auto-including-runs`); (2) pre-action confirmation for the `runModuleReal`/exec path.
- **WHERE**: `src/lib/types.ts` (Project field `confirmPolicy`), `src/lib/store.ts:1310+` `runModuleReal` + `:1067-1090` driver loop, `src/lib/engine.ts:3468+` `wildStep`, `src/components/console.tsx` (165A-8's button + dock), `src/lib/headless.ts` (CLI flag), `src/lib/phases.ts`.
- **HOW**: (a) add `confirmPolicy?: "ask" | "auto"` on Project (default `"auto"` = today) and a pure `needsConfirm(policy, action)` classifier (unit-tested); (b) `runModuleReal` checks it: under `"ask"` the first OS-spawning run per project opens the existing approve-dock shape (reuse `approve`'s `requestedAt` flow) instead of executing; the dock and the `a` shortcut honor it (fixes the 165A-3 shortcut hole at the same seam); (c) wild driver reads the policy per step and parks with an honest log row when a step needs confirmation it cannot get — mirroring the step-cap park (`store.ts:1088-89`) with reason `"needs-confirm"`; (d) console busy-latch for the module run (165A-8 fix) lands here as the UI half.
- **TEST**: unit — `needsConfirm` table over (policy × action-class); store — under `"ask"`, `runModuleReal` returns pending + a gate row, and `approve` (dock or `a`) is the only path to execution; wild — a step classified needs-confirm parks with `stoppedReason:"needs-confirm"` and no further phase advance; e2e — toggling the policy mid-run changes the next step only (never re-approves a committed gate).

### 167A-5 — No boot-time config validation / fail-fast; a malformed `.env` or config fails late and per-call (Codex: typed ConfigToml + committed JSON Schema; OpenHands: pydantic AppConfig)
- **WHAT + WHY**: OpenHands models all config as pydantic `BaseModel`s — `AppConfig`, `LLMConfig`, `SandboxConfig`, `SecurityConfig` (`core/config/app_config.py`) — so a bad `config.toml` fails at load with a typed error, before any agent runs. Codex derives a committed JSON Schema from its typed `ConfigToml` (config/schema.md), has loader tests, and preflights budgets at startup (`config/token_budget_startup.rs`). RapidTool deliberately supports keyless deterministic operation (honest fallback everywhere — a product strength), but the flip side is that **no config is ever validated up front**: an accidental `DEEPSEEK_API_KEY` typo, a nonsense `sandbox.ramMb`, or a half-edited `.env` surfaces only as per-call `RT_E_LLM_NOT_CONFIGURED`/timeouts mid-run.
- **RapidTool status**: **PARTIAL**. Key read is centralized and honest: `deepseek.server.ts:4,93` ("Reads the key from `process.env.DEEPSEEK_API_KEY` ONLY"), call-time `not-configured` results (`chat.server.ts:303`, `crew.server.ts:1297`), typed `RT_E_LLM_NOT_CONFIGURED` (`errors.ts:24-60`). Dev-only build-consistency check exists (`scripts/check-auth-invariant.mjs` vs `VITE_AUTH_ENABLED`). But there is **no env/config schema and no fail-fast**: zod exists in the dependency stack yet is imported in exactly one `src/` module (`preview-host-bridge.ts`) and never validates env/config; `.env.example` is prose (`DEEPSEEK_API_KEY=sk-...`); and `ramMb`/`timeoutS`/`isolated` claims are never validated against the runner that will execute (`engine.ts:746` prints them; node-runner enforces none).
- **WHERE**: new `src/lib/env-schema.ts` (pure), read once at server bootstrap and in `scripts/with-app-env.mjs`/`gate.sh`; `src/lib/deepseek.server.ts:93` (key accessor); `src/lib/types.ts` sandbox type; `src/lib/io.ts` sanitizer (import-time coercion already the pattern for payloads — extend to config shape).
- **HOW**: (a) a tiny hand-rolled validator in RapidTool style (no new dep, mirroring `errors.ts`): `validateEnv(env): {ok:true} | {ok:false, code:"RT_E_VALIDATION", errors:[...]}` — key **format** checks when present (`sk-…` prefix for DeepSeek, `tvly-…` for Tavily), numeric-range checks for `sandbox.timeoutS`/`ramMb` if ever set, and cross-checks (e.g., `isolated:true` with no OS backend → warn); (b) fail-fast: server bootstrap and `headless` CLI run it once at startup and exit with the machine code + a one-line fix hint (exactly how Codex's loader tests + OpenHands' pydantic errors behave); (c) keep keyless honesty: absence is valid, malformed presence is not; (d) wire the same validator into the import sanitizer so a persisted project with an invalid sandbox shape is repaired with a token (the established `io.ts` drop-with-token pattern from 162 Phase A1).
- **TEST**: unit — `validateEnv` table: absent keys → ok (honest keyless), `DEEPSEEK_API_KEY=typo` → `RT_E_VALIDATION` naming the variable, out-of-range `timeoutS` → error; integration — boot the server with a malformed `.env` → non-zero exit with the code before any route serves; headless — same for the CLI; regression — the existing keyless deterministic test fixtures still boot clean (no false-positive on absence).

### 167A-6 — No circuit breaker / degrade-and-halt after repeated LLM failures inside a run (Codex/OpenHands: bounded retries; RT retries forever per call, then only the step cap stops the loop)
- **WHAT + WHY**: Both competitors bound *call* retries (Codex `responses_retry.rs` max-retries + connection backoff; OpenHands tenacity `stop_after_attempt` + exponential wait, `llm/retry_mixin.py`), and OpenHands' traffic control pauses the *loop* when the run exceeds its iteration budget. RapidTool's retry layer is already best-in-class (full-jitter bounded backoff, injectable seams, `deepseek.server.ts:55-81`; typed `errors.ts` codes) — but there is no run-level trip: if the provider degrades (repeated `RT_E_LLM_TIMEOUT`/`RT_E_LLM_REJECTED`), every wild step retries internally and the outer loop keeps spending wall-clock until the 20-step cap. 155's research already named circuit breaking as the industry degrade pattern ("circuit breaker trips → errors, not plausible answers, plus a monitor alert", [S27 in 155]); `watchdog.ts`/`diagnose.ts` detect, they don't trip.
- **RapidTool status**: **PARTIAL** — retry PRESENT, breaker ABSENT (grep for `circuit` across `src/lib`: no mechanism; only 155's research notes).
- **WHERE**: `src/lib/store.ts:1067-1090` (wild driver), `src/lib/engine.ts:3468+` `wildStep` (per-step classify), `src/lib/errors.ts` (codes), `src/lib/diagnose.ts:145-158` (already computes wild-step stalls — natural breaker readout), `src/lib/runtime-log.server.ts` (trip row).
- **HOW**: (a) pure `tripDecider(failures: {code}[], opts): "open" | "closed"` — e.g., 3 consecutive `RT_E_LLM_*` → open; injectable counters like the jitter seam (`deepseek.server.ts:151-158`); (b) in the wild driver loop, after each `wildStep` failure classify via `errors.ts` and feed the counter; when open, **park with reason `"llm-breaker"`** + an honest log row and a diagnose-hint (reuse the existing park shape `store.ts:1088-89` so the UI strip already knows how to render it); (c) log the trip as an `RtEvent` so `diagnose` shows "breaker open at Pn after 3 consecutive LLM failures" — the monitor alert 155 asked for; (d) reset the counter on any success (half-open on operator resume is the existing resume path, `store.ts:991-1032`).
- **TEST**: unit — `tripDecider` table over failure-code sequences (timeout→timeout→rejected trips at 3; success resets); store-level — stub `wildStep` to fail N times → parks with `stoppedReason:"llm-breaker"` at exactly N and no further calls; diagnose — the breaker row renders in the `diagnose` timeline (mirror existing wild-step-timeout row `diagnose.ts:145-158`).
