## 1. Why a pure module first (and what "deterministic drafter" honestly means here)

A7 oracle rows are prose (`buildTestOracle`: `given:"Authorized operator submits “record” with a
valid property"`, `expect:"200 + persisted entity + checkpoint written"`) and corpus
`expectedCapabilities` are prose too. Prose carries **zero executable literals**, so no
deterministic (no-LLM) function can mint concrete `createProperty({address,owner}) ⇒ {id,history:[]}`
semantics from it without inventing data — which the honesty contract forbids. Per 158_s2 A1 the
concrete literals come from the producer (the LLM-assisted draft stage / the human) as a `typed`
map; the F2 pure core's deterministic job is everything around that: binding, eligibility triage,
kind/source/approval metadata, red cards, the shape gate (A1's deterministic review), and the
approval gate (A2's machine half). Rows/capabilities without a typed entry are **red-carded as
vacuous** — A1's rule ("a case with zero literals — 'returns something ok' — is rejected as
vacuous") is honored by refusing to emit a case that asserts nothing. This keeps the module
deterministic AND honest: same args ⇒ deep-equal draft, every emitted case is a real
given→expect claim.

## 2. Landed surface (src/lib/brief-fixtures.ts — 516 lines, zero deps)

Types: `BriefFixtureCase` { id, requirementId, capability, name, given (plain JSON literal),
expect (typed descriptor), kind: 'pure'|'effect'|'property', source: 'a7'|'capability'|'human',
approval: 'pending'|'approved' } · `BriefFixtureExpect` = shape{value} | throws{messagePattern} |
property{name} (a deterministic check descriptor — never free text, never code) ·
`BriefFixtureTypedDraft` · `DraftBriefFixturesArgs` { oracle, capabilities?, typed? } ·
`BriefFixtureDraft` { cases, redCards } · validation/gate result types.

Functions:
- `draftBriefFixtures(args)` — deterministic drafter. A7 rows in input order → one case per
  typed row (case id **= the oracle row id**, so the E-08 pinning seam works on case ids
  directly); constraint rows (orc-c-* / constraint.* / negative prose) triage kind `effect` with
  a throws expect (typed throws honored; a typed shape on a constraint row is overridden by a
  throws descriptor whose `messagePattern` is derived deterministically from the prose — after
  "violates ", else the constraint name/id, else the job); capability entries → `cap-<n>` cases,
  kind triaged from prose lexicon (property > effect > pure). Controls: engine/control rows
  (`orc-phase`, `graph.*`, job ∈ {graph,workflow,engine,system}) are never fixture targets →
  red card; capability-coverage filter red-cards job rows whose job matches no capability
  (token ∩ len≥3 or substring; advisory when no capability list); malformed/duplicate rows →
  red card. **Every case is born `approval:"pending"`; nothing in the module ever flips it.**
- `validateFixtureCase` / `validateFixtureSet` — A1 deterministic shape gate: id/requirementId/
  capability/name non-empty; kind/source/approval ∈ unions; **given is a plain JSON literal**
  (recursive checker — rejects functions, undefined props, NaN/Infinity, Dates/RegExps/Map/Set,
  class instances, bigint) with **no code strings** in any string leaf; expect is a supported
  descriptor (shape value JSON-literal + code-clean; throws messagePattern = non-empty plain
  substring, no code markers; property name = registry identifier `^[a-z][a-zA-Z0-9_]{0,63}$`,
  never free text); set-level id uniqueness.
- `fixtureApprovalGate(cases)` — A2 machine half: `{ok, total, approved, unapproved[],
  unapprovedIds}`. ok ⇔ ≥1 case AND every case `approved`. Only reads approval; never writes it.
- `approveFixtureCases(cases, ids)` / `approveAllFixtureCases(cases)` — the **only** writers of
  "approved", pure and explicit; documented as human-invoked (the A2 verb/UI). Drafter,
  validator, and gate never call them.
- Helpers: `isPlainJsonLiteral`, `containsCodeString`, `deriveCapabilityKind`,
  `jobCoveredByCapabilities`, `BRIEF_FIXTURE_KINDS/SOURCES/APPROVALS`, `BRIEF_FIXTURE_CONTROL_JOBS`.

## 3. Semantics decisions (recorded for the A3/A2 waves)

1. **Case id = requirement id.** A7-sourced cases carry the row's own id (`orc-1`); capability
   cases `cap-<n>`. `missingOracleCaseIds(draftCaseIds, oracle)` therefore pins drafted rows
   directly (test-verified); the only rows it reports missing are the deliberately excluded
   engine-control rows (orc-phase) — an honest, documented exemption.
2. **`given` is a plain JSON literal** whose exact call shape the A3 emitter owns (single object
   arg, or `{args:[...]}` for multi-arg targets — the runner convention is deferred to A3 per
   158_s2 A3 "store the arg shape in the case so the runner is deterministic").
3. **Kind triage lexicon is fixed + exported for tests**; property-kind capability prose wins
   over effect over pure. The approved property-name registry (A5-iv hidden canary) is not part
   of F2 — the validator format-checks names only.
4. **The approval gate's empty-set arm is `ok:false`**: no cases ⇒ no functional claim (a run
   may not certify a brief it never drafted).
