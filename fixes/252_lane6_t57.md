Behavioural decisions worth naming (all pinned by tests):
- **Record is write-through**: the tape file holds the entry the moment the call returns — recorded
  evidence must never be silently lost (`write-through` test reads the file between calls).
- **First-wins per key**: re-recording the same call never rewrites the recorded envelope (a second
  record pass with a DIFFERENT live answer leaves the tape byte-identical — pinned).
- **Recorded refusals are first-class**: an `ok:false` envelope is recorded and replays as the same
  refusal, with NO provenance stamp (nothing was produced; no model was served).
- **A transport throw propagates untouched and records nothing** (never a swallowed error).
- **Load never repairs**: corrupt JSON / wrong version / key≠request / malformed rows / a provenance
  block T5.4 would drop are all coded refusals — a corrupt tape can never masquerade as an empty one.
- **Collision guard**: lookup by key, then verify the stored canonical request matches the live one;
  a mismatch (a real FNV-1a collision) refuses instead of serving another prompt's answer.

## §1 — T5.4 provenance consumption (fixes/249_lane5_t54.md §"Exact field names")

249 had LANDED its declared names when this lane started, so this consumes the REAL exports, not
placeholders: `type ArtifactProducer` / `type ArtifactProvenance` (compile-time) and
`coerceArtifactProvenance` (**runtime import of `./io.ts`** — the tape loader validates entries with
T5.4's own validator, so a cassette stamp can never be one the serializer would drop).

- Record mints `{ producer: "model", model: <id from the returned envelope>, timestamp: now(), inputHash: key }`.
- Replay mints `{ producer: "replay", model: <id served at record time>, timestamp: now(), inputHash: key }`
  — the vocabulary 249 reserved for this lane ("no writer mints it today").
- `inputHash` = the cassette key = `String(fnv1a(canonical request))` — the repo's FNV-1a convention.
- An `ok:false` envelope mints NO stamp: T5.4's validator *requires* a served model for both
  non-deterministic producers (`io.ts` `coerceArtifactProvenance`), so minting one would be a
  contradiction — pinned by asserting the validator rejects exactly that shape.
- Test evidence: the record stamp and the replay stamp both survive `coerceArtifactProvenance`.

HARD DEPENDENCY NOTE: `cassette.ts` runtime-imports `./io.ts` (W18-L5's uncommitted landing). If that
landing is reverted before commit, this module fails to load — the consumption is deliberate, not
accidental.

## §2 — the coded miss (the anti-fabrication core)

`CASSETTE_MISS_CODE = "RT_E_LLM_REJECTED"` — the registry's existing "the model side refused to serve
this call" code, the **same code the mock provider returns when its fixture queue cannot serve**
(`mock.ts` complete(): queue exhausted → `RT_E_LLM_REJECTED`). `RT_E_LLM_NOT_CONFIGURED` was
deliberately NOT used: its documented agent action is "return the honest not-configured fallback
(deterministic path)", which would let a replay miss ride the keyless floor and fake the replay.

Real miss envelope (from the probe run):

```json
{"ok":false,"reason":"error","code":"RT_E_LLM_REJECTED",
 "error":"cassette miss: no entry for this call — key 2201378038 (model (unset), prompt 14 chars). The cassette NEVER fabricates text: record the call (RAPIDTOOL_CASSETTE_MODE=record) or run live."}
```

Three miss paths, all pinned: (a) key absent on a present tape; (b) no tape file at all (detail says
`no tape file at <path>`); (c) real FNV-1a collision (detail says `FNV-1a collision`, and the test
asserts the other request's answer text is nowhere in the response). Every miss asserts
`!("text" in res)`.

`CASSETTE_MISS_CODE` is a one-line flip if a dedicated `RT_E_CASSETTE_MISS` is ever wanted (that
registration lives in `errors.ts`, outside this lane's box); the detail's stable `cassette miss: `
prefix lets consumers branch today.
