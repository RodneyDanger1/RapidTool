## 0. BOTTOM LINE (read this first)

RapidTool's **emitted product** (scaffold + generated tree) is a deliberately narrow artifact: a TypeScript-only, zero-dependency, pure-function module envelope plus typed stubs, one `tests/oracle.spec.ts`, an inventory README, an anti-deploy DEPLOY.md, and a placeholder `.env.example` (`src/lib/scaffold.ts:1801-2050`). The top-3 open-source prompt-to-software harnesses (OpenHands, MetaGPT, gpt-engineer) each ship **product-level capabilities around that same moment of "code was produced"** that RapidTool has *inside its own engine* but never extends to the thing it emits, or does not have at all:

1. **Extension without forking** — OpenHands `.agents/skills` + SDK agents, MetaGPT role/action architecture, gpt-engineer `preprompts/`+`steps`: users add verbs/roles/prompts as data. RapidTool: 33 verbs in one `case` switch (`scripts/rapidtool-cli.mjs`, `grep -c 'case "'` = 33), fixed 13-phase pipeline (`src/lib/phases.ts`) — **adding a verb or phase is a fork** (169D-1).
2. **Multi-language output** — all three harnesses are language-agnostic or polyglot; RapidTool's emit is TS-only by construction in **both** halves: scaffold toolchain per kind (`scaffold.ts:449-492`) and the synth envelope ("TypeScript-style CommonJS module", `codegen.server.ts:163`) (169D-2).
3. **Real unit tests next to the produced code** — gpt-engineer runs/benchmarks generated projects; RapidTool's runner *executes every emitted `tests/*.spec.ts|*.test.ts`* (`compile-check.server.ts:215,598`) but the emitter **only ever produces one spec file** (`scaffold.ts:188-191, 474, 2009`) (169D-3).

5. **CI/CD + Docker + deploy-config output** — OpenHands ships 17 GitHub workflows incl. `docker.yml` + `helm/` + `vercel.json`; MetaGPT ships `Dockerfile` + `.github` + `.devcontainer`; gpt-engineer ships `docker-compose.yml` + `.github`. 9. **Git hygiene + first-commit integration** — gpt-engineer ships `core/git.py` and a git-controlled UI (README:86); RapidTool's `emitProject` writes files blind (`headless.ts:1018`) with **no `.gitignore`, no `git init`, no commit** — the repo itself isn't git, and an emitted tree's first `git add` would stage `node_modules/` + real `.env` (169D-9).

**Partial/adjacent (kept short, not full findings):** config/env handling — `.env.example` *is* emitted per kind (`scaffold.ts:415-441`) but no emitted module ever reads `process.env` and no config module/loader exists; telemetry-in-produced-app — RapidTool's own runtime telemetry (`rt-events.ts`, `rt-ring.ts`, runtime-log) never reaches emitted apps.
