## F1. `compaction.ts` — the dead `!out.includes(marker)` guard. LANDED

**What it was.** `if (out.length > cap || !out.includes(marker))` — `out` is built as
`` `${head}${marker}${tail}` ``, so `marker` is a substring by construction and the second disjunct can
never be true. Verifier §5 (LOW). The guard's comment also claimed a case it could not detect.

**Fix.** Reduced the condition to the ONE honest, reachable trigger: `if (out.length > cap)`. The
comment now states why (the marker is a substring by construction; and a sliced `out` would truncate
the marker / under-report the elision). Note on the verifier's literal suggestion: `out.length > cap ||
!out.slice(0, cap).includes(marker)` is *also* entailed-dead in its second disjunct — when
`out.length <= cap`, `out.slice(0, cap) === out`, which always contains the marker — so the disjunction
collapses to `out.length > cap`. I landed the collapsed form rather than a second tautology.

**RED/GREEN.** The removal itself has no behavioural RED (a dead disjunct never changed output) — stated
plainly. The `out.length > cap` branch is proven reachable and load-bearing by the existing cap-64..130
sweep, which I strengthened in the same edit:

- RED (round-1 bytes, `probe_clamp2.mjs` + the sweep): cap 64..90 produced a truncated marker stub;
  the sweep test `not ok 6` `# tests 20 / pass 19 / fail 1` (shown in my round-1 log).
- GREEN (now): `compaction.test.ts` 20/20 on Node 22.23.2 AND Node 24.15.0.
- The strengthened pins: the two arms (fully marked / counted head-cut) are mutually exclusive; a
  head-cut carries NO `chars elided by compaction` fragment and equals `text.slice(0, cap)`. A
