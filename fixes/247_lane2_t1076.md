## 2. Design notes (why it is safe)

- **One budget, threaded as a parameter** (no second budget system, no global singleton): `generateCases(source, brief, signatureNames, seeds, pinnedOracleIds, budget?)`; `verifyAndFixServer(…, opts.budget)`. Mirrors the landed `codegen.server.ts` `accountSynthUsage` record-then-signal pattern.
- **Order preserved:** keyless check → input validation → prompt build → budgeted call. With no budget the call is the exact previous `callModel(...)` expression; the only edits inside the seam are the wrapper + the refusal early-returns.
- **Refuse before the wire:** `assertBudgetHeadroom` runs inside the wrapper before `call()`, so an over-cap budget makes **zero** fetch calls (pinned: `mock.calls.length === 0`).
- **Spend kept:** on a crossing, `recordBudgetSpend` mutates the caller's ledger first and then throws; the wrapper catches that and returns the refusal — the ledger keeps the measured totals (pinned: crossing ledger `{promptTokens:10, completionTokens:10, calls:1}` after a refusal; fix-loop test keeps 40 tokens across gen+fix).
- **Mid-loop fix stop:** a budget stop at the fix dispatch exits the loop immediately with `status:"error"`, coded evidence `fix dispatch refused: … RT_E_BUDGET_EXHAUSTED …`, anchored to the failing machine-case ids observed that iteration (`gatedFailureMint`) — the loop never spins on a spent budget.
- **Non-budget errors keep their own classification:** the wrapper rethrows anything that is not `SessionBudgetExceeded` (pinned by `assert.rejects(/boom/)`).
