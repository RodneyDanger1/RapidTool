## What changed (code — rapidtool-cli.mjs)

### 1. Default output resolution moved from CWD to the user's home (g4 F1 patch)

`emit` and `vault` previously defaulted to `./emit/` / `./vault/` resolved against the
shell CWD — a fixed, project-less folder name that landed inside whatever directory the
CLI was launched from (repo root on this machine) and was silently clobberable by any
project. Both now default to a named, per-project folder under the user's home:

- `emit`:  `<os.homedir()>/RapidTool Software/<slug>/`
- `vault`: `<os.homedir()>/RapidTool Software/<slug>/vault` (same parent as the software)

`--out` keeps overriding in both verbs (byte-for-byte unchanged semantics). Windows-safe:
`node:os` `homedir()` + `node:path` `join` — never a hardcoded path.

New helper (module scope, after `readReportSource`):

```js
// Software deliverables (`emit`) and knowledge vaults (`vault`) default to a
// NAMED, per-project folder under the user's home — never a CWD-relative
// ./emit|vault buried in whatever directory the shell happened to be in:
//
//   emit:   <os.homedir()>/RapidTool Software/<slug>/
//   vault:  <os.homedir()>/RapidTool Software/<slug>/vault
//
// `--out` always overrides. <slug> is io.ts slugName (headless re-exports it
// as h.filename): lowercase, spaces/non-alphanumerics -> "-", trimmed, and ""
// -> "project" — the SAME slug the packet/JSON downloads use (io.ts:340), ...
function defaultOutputDir(h, project, ...sub) {
  const slug = h.filename(project.name);
  const target = join(homedir(), "RapidTool Software", slug, ...sub);
  try {
    mkdirSync(target, { recursive: true });
    return target;
  } catch {
    const fallback = resolve(slug, ...sub);
    mkdirSync(fallback, { recursive: true });
    return fallback;
  }
}
```

Before/after at the call sites (anchor `rapidtool-cli.mjs` — re-grepped at edit time):

```js
// BEFORE (emit)                                  // AFTER (emit)
const dir = typeof args.out === "string" ? args.out : "./emit/";
const dir = typeof args.out === "string" ? args.out : defaultOutputDir(h, project);
const target = resolve(dir);
const preExisting = existsSync(target) && readdirSync(target).length > 0;

// BEFORE (vault)                                 // AFTER (vault)

```

Imports added (g4 §2's own recommended import patch, extended):
`import { existsSync, mkdirSync, readdirSync, readFileSync, writeFileSync } from "node:fs";`
+ `import { homedir } from "node:os";`

**Slug source:** `h.filename` = `io.ts slugName` (headless.ts:793-794 re-export) — the
same slugger `create` already used for `<slug>.json`, so emit/vault/create/packet/JSON
downloads all name things identically. slugName semantics: `.trim().toLowerCase()`,
`[^a-z0-9]+ → "-"`, hyphen-trim, 80-char cap, `"" → "project"` — matches the mission's
slug() spec (cap is a safe superset that keeps Windows path lengths legal).

**Writability fallback:** `mkdirSync(recursive)` of the full target is attempted first;
on throw (server/CI, unwritable profile) the default falls back to `<cwd>/<slug>/[vault]`
— an emit never silently dies on a bad homedir. If even CWD is unwritable the error
propagates to the verb's existing catch → clean `{ok:false}` envelope, exit 1.

### 2. mkdir-before-write — verified already correct, no edit needed (headless.ts)

Mission microstep 2 asked to verify the emit path `mkdirSync`s before `writeFileSync`.
`headless.ts emitProject` (NOT in this lane's ownership) already does
`mkdirSync(target, {recursive:true})` (headless.ts:1006) AND `mkdirSync(dirname(full),
{recursive:true})` per file (headless.ts:1010) before `writeFileSync` (1011); `writeVault`
mkdirs recursively at headless.ts:1030 before its writes. Recursive mkdir creates every
parent, so no change was needed or made in `src/`. (Noted for the owning lane: the stale
scaffold summary suffix "— write them to disk with the emit command" at
`src/lib/scaffold.ts:1555` is g4 one-liner #2 and belongs to another M1 lane — left
untouched here.)

### 3. Second emit overwrites cleanly + says so (never a silent merge)

The emit case now snapshots pre-existing content of the resolved target BEFORE writing
(`existsSync(target) && readdirSync(target).length > 0`). On a re-emit the payload gains:

```json
"overwritten": true,
"warning": "Output folder already existed — its files were overwritten in place (writeFileSync replaces whole files; nothing was merged or appended)."
```

`writeFileSync` is unconditional per file (headless.ts:1011) → clean replace, and the
`warning` line makes the overwrite loud instead of silent. Works for `--out` targets too
(dir-agnostic), so agents re-emitting into a scratch tree get the same honesty.

### 4. create default — deliberately UNCHANGED (CWD `<slug>.json`), rationale + docs

Kept CWD-relative (documented in README-cli + CLI USAGE row). Why: the g4 dossier's §2
recommended change targets `emit` only and lists `vault` as an optional consistency
follow-up; it records `create`'s CWD-relative `<slug>.json` (F1) without proposing a move.
The project JSON is an **intermediate, machine-facing control file** that every later
verb consumes via `--project <path>` — chaining `create && gate --project x.json` from
one shell requires it to stay next to that shell (or every `--project` reference in the
quickstart/docs would need the absolute home path). The task's "findable software" goal
is about the DELIVERABLE (emit tree) and the knowledge vault — not the JSON control file.
Moved: software + vault. Stayed: the intermediate file. A rationale comment now marks the
decision at the create call site.
