## 0. BOTTOM LINE (read this first)

- **The loop can already mint a machine approval that *reads* as a human approval.** `approveHitl`
  defaults `decidedBy` to `"human"` (engine.ts:1526), and the CLI `approve` verb — reachable by the same
  agent that drives the wild loop — stamps `decidedBy:"human"` with an unguarded `--force`
  (headless.ts:640-652, rapidtool-cli.mjs:456-479). No TTY/seat evidence separates a human from an agent
  process. In the all-AI factory, `approve --force` on a forceHuman gate **fabricates a human decision
  row**. The ledger is honest only if the caller is honest about who it is.
- **Wild Mode's self-approval policy is WEAKER than the conservative autopilot's, and contradicts the
  product's own words.** Sync autopilot refuses `forceHuman` gates AND the stock HITL phases
  P4/P5/P8/P9 (`canAutopilot` headless.ts:294-307; STOCK_HITL phases.ts:151). The wild loop refuses
  ONLY forceHuman gates (engine.ts:3301-3310) — so the Auto-Review classifier self-approves the P4
  isolation-policy gate, the P8 UI contract and the P9 deploy gate, while dod.ts criteria literally say
  "P4/P5/P8/P9 **HITL approved** — phase record complete" (dod.ts:285,297,418,430) and packet.ts:501 says
  "Do not deploy without HITL on P9". A machine approval **satisfies a criterion that asserts a human
  approved**. The decision ledger row is truthful (decidedBy autopilot, engine.ts:1551); every
  downstream surface that renders the criterion is not.
- **The classifier has no falsifiable check to pass, and its rubber-stamp guard is trivially
  satisfiable.** `isVacuousFeedback` (wild-mode.server.ts:220-239) accepts any approve carrying one
  ≥5-letter non-stopword or a mention of an artifact title the model itself generated (evidence list =
  the titles, wild-mode.server.ts:291-294) — "the interface contract artifact is coherent with the
  brief" passes with zero verification. The DoD verdict is shown to the judge **before** it decides
  (wild-mode.server.ts:123) — an anchor that turns "approve" into an echo. And the judge is
  deepseek-v4-flash (wild-mode.server.ts:33), the same family as the v4-pro producer — a weaker sibling
  grading its stronger sibling.
- **Runaway protection is per-invocation, not per-run; there is no tripwire inside the loop.**
  wildStep itself has no step/token/time budget (engine.ts:3468-3681); "bounded" lives only in each
  driver call (store 20, store.ts:1067; headless 24 clamped 1-48, headless.ts:2558/2707; gate 40,
  headless.ts:479). An agent re-invokes → totals unbounded. Classifier reject → pause is state-free:
  nothing records the rejection on the phase (human-only writers engine.ts:1620-1623, report-intake.ts:386),
  the deterministic floor regenerates byte-identical content (engine.ts:1273), so agent-driven
  resume→review→reject churn burns one LLM call per cycle forever with zero progress and zero counters.
  The Reflexion "rejection history steering" in the review prompt (wild-mode.server.ts:102-114) is a
  dead letter — a wild reject never writes the history it reads.
- **A5's human fixture gate inherits all of the above unless it is an enforced seam, not a prompt
  line.** 162 §3's "never auto-approve a fixture (only the human `fixtures approve` verb may)" is
  discipline; nothing in code stops the run's own driver from invoking that verb. Fix the actor seam
  first (163A-1), then make the fixture gate forceHuman (163A-7).

## 1. Code-grounded findings

### F1 — Fabricating a human decision: the actor seam does not exist (audit Q1/Q5)

- **engine.ts:1526** — `const decidedBy = opts?.decidedBy ?? "human"` in `approveHitl`. Every caller
  that forgets to pass an actor silently records a HUMAN decision.
- **headless.ts:640-652** — CLI `approve(project, {force})` calls `approveHitl(project, { decidedBy:
  "human", force: opts.force })`; **rapidtool-cli.mjs:456-479** `case "approve"` passes `--force`
  through with no interactivity check. A pipe/agent invocation produces a ledger row indistinguishable
  from a person at a terminal. This is the verb A5's future `fixtures approve` will copy unless the
  seam is fixed first.
- **engine.ts:1533-1534** — the forceHuman guard throws only when `decidedBy === "autopilot"`; the CLI
  path never says autopilot, so `--force` on a failed-P6-sandbox / reframe gate is a legal, honest-only-
  by-convention human forgery.
- **dod.ts:285/297/418/430** — P4/P5/P8/P9 criteria read "…**HITL approved** — phase record complete";
  the probes check only `phaseComplete`. In wild mode the machine completes the phase itself
  (engine.ts:3337-3340 approveHitl autopilot), so a self-approval flips a criterion that names a human
  actor. `p8-complete`/`p9-complete` (dod.ts:419,431) are the same shape.
- **packet.ts:501** — "Do not deploy without HITL on P9" is emitted for projects whose P9 gate the wild
  loop may self-approve (F1b). Wild mode is a declared product path (engine.ts:3105 header; store
  console drive store.ts:960+), not a test seam.

### F1b — Wild approval policy < conservative autopilot policy (the asymmetry)

- **phases.ts:151** `STOCK_HITL = [4, 5, 8, 9]`; **headless.ts:294-307** `canAutopilot` refuses
  `forceHuman` **and** stock HITL phases **and** a phase failing its own DoD (M-09) **and** tight
  schedules (tightness ≥ 7.2). Store mirrors it (store.canAutopilot).
- **engine.ts:3301-3310** `wildApproveGate` refuses **only** `forceHuman`. Stock gates are raised in the
  wild execute path by `synthesizePhase` with no forceHuman flag: P4 "Approve isolation policy"
  (engine.ts:738-757 — prompt itself says "Declared-not-implemented … do NOT approve as fact",
  engine.ts:748-756, yet a machine may approve it), P8 "Approve interface contract" (engine.ts:963-970),
  P9 deploy gate (engine.ts:1009+), P5. forceHuman gates today: P0 reframe (engine.ts:626-633) and the
  failed-P6 sandbox (engine.ts:1287-1294) only.
- Consequence: the *autonomous* loop has strictly less approval protection than the *assisted* autopilot
  — backwards for the no-human factory.

### F2 — Classifier falsifiability: nothing to falsify (audit Q3)

- **wild-mode.server.ts:220-239** — `isVacuousFeedback`: one non-stopword ≥5 letters, or a ≥4-char
  mention of a shown artifact title/gate-id, makes an approve "substantive". Evidence list =
  **wild-mode.server.ts:291-294** the titles of artifacts the model itself generated. Feedback naming its
  own artifact passes the "rubber-stamp detector" by construction — there is no check that the feedback
  *refutes anything* (Anthropic's bar is "a fresh model tries to refute the result" [S2]).
- **wild-mode.server.ts:123** — the prompt hands the judge the machine verdict *before* it decides:
  "Machine-checkable DoD verdict: PASS". An approve that follows is at best an echo of the deterministic
  gate, at worst anchor-and-adjust approval bias. The judge is never asked to predict the gate first and
  then reconcile a mismatch.
- **wild-mode.server.ts:33** `WILD_CLASSIFIER_MODEL = "deepseek-v4-flash"` vs producer
  **codegen.server.ts:127** `P6_SYNTH_MODEL = pro`; llm-tasks runs pro; chat runs flash (chat.server.ts:359).
  Same model family judges its own output; judge tier is *weaker* than author tier. LLM-as-judge
  self-preference is quantified (+10% GPT-4 / +25% Claude-v1 self-favoring [155-WF S10]; self-recognition
  correlates with self-preference [S3]). A weaker sibling cannot catch its stronger sibling's subtle
  errors, and "the producer grades itself" is exactly what 155-WF R5(iii) forbids.
- **wild-mode.server.ts:87-133** — the one genuine guard: rejection history is surfaced verbatim with a
  steering line (Manus/Reflexion pattern [S4]) — but see F3d: wild rejects never write that history.

### F3 — Runaway: per-invocation caps only; state-free reject→resume churn (audit Q2)

- **engine.ts:3468-3681** `wildStep` — no step counter, no token/time budget, no progress check; guards
  are active/pause/status only. The "hard iteration cap" promised in the section header
  (engine.ts:3109-3110) is the *caller's* job.
- Driver caps are per-invocation and bypassable by re-invocation: store loop 20 (store.ts:1067);
  headless `wildStartRun`/`wildStartHeadless` default 24 clamped 1-48 (headless.ts:2558, 2707);
  `runUntilGate` default 40 (headless.ts:479). `Project.wildRun` (types.ts; hydration engine.ts:1943-1974)
  carries `startedAt/lastAutoAt/pause/stoppedAt` — **no stepsTotal, no maxSteps, no pausesTotal, no
  rejectCount, no wall-clock tripwire**. Nothing in the persisted state can ever trip.
- Resume is agent-reachable: `wild --resume` (rapidtool-cli.mjs wild case, ~1670-1740 → headless.ts:2791
  `wildResumeRun`) and `startWildRun` doubles as the resume path (store.ts:989-1005 PA-01). Pause is a
  speed bump, not a stop, for an agent that controls the CLI.
- Reject is state-free: wild reject branches only `wildPause` (engine.ts:3397-3405 leave-phase;
  3327-3336 gate) + a log. `rejectionHistory` is appended only by human `rejectHitl` (engine.ts:1620-1623)
  and report-intake (report-intake.ts:386). Deterministic floor re-execution is byte-identical
  (engine.ts:1273-1284, `applyPhaseResult`→`synthesizePhase` deterministic), so
  resume→re-review→reject cycles re-judge identical content forever, one classifier LLM call per cycle,
  zero progress, zero counters, zero state change between reviews.
- Reflexion steering dead-letter: the review prompt's rejection-history block
  (wild-mode.server.ts:102-114) can only fire for human rejections; an autopilot re-approval that
  ignores a *classifier* rejection is never detectable because the rejection is never recorded on the
  phase. (T9's deterministic answer block engine.ts:1302-1308 only engages when `attempt ≥ 1`, which
  requires a rejectionHistory the wild path never writes.)
- Precedent from the field: even a deterministic gate has a bounded override so the loop cannot wedge
  (Claude Code Stop hook: block ≤ 8 consecutive, then end turn [S2]); and "the infinite exploration" is
  a named failure mode that must be scoped up front [S2]. Here there is no tripwire *and* no bounded
  override — the pause is indefinite but resumable by the same actor.

### F4 — Hard-DoD is honest but existence-level; gate self-approval is circular (audit Q1/Q3/Q4)

- Hard-DoD enforcement is real and clean: `hardDodBlockInto` (dod.ts:745-792), wild leave/gate post-checks
  (engine.ts:3408-3421, 3350-3363), store auto-advance parity. But the probes are existence/string checks
  (p12-openapi string-contains dod.ts:454-458; p7 counts dod.ts:397-408; p8/p9 `hasArtifact` +
  phaseComplete dod.ts:414-432) — satisfiable by well-formed content the machine itself wrote. Hard-DoD
  cannot distinguish "empty but well-formed" from real; that is what the A5 fixture harness is for
  (162 PHASE A) — see 163A-7.
- For gate phases P4/P5/P8/P9 the *only* criterion is "HITL approved — phase record complete"
  (dod.ts:285/297/418/430), so the wildApproveGate post-approval runGate (engine.ts:3350-3363) verifies
  the self-approval itself — circular by construction.
- Autonomy-limit disclosure (audit Q4): exclusions exist only in code (forceHuman engine.ts:3301; the
  autopilot predicate headless.ts:294-307) and in a prompt line (162 §3). No run-start artifact or CLI
  response states, machine-readably, what this run may NOT self-approve. 162 PHASE B's provenance stamp
  (B2) is the right carrier but does not exist yet.

### F5 — Self-approval vs the A5 human fixture gate (audit Q5)

- A5 (162:137-155) makes the human-approve act a CLI/store surface: `fixtures approve|reject`. The
  honesty property "only the human may approve fixtures" depends entirely on whoever invokes the CLI
  being human — the exact seam F1 shows is missing today. Copied verbatim, A5 produces a machine-
  callable self-approval for the one gate designed to be the external oracle.
- The wild loop does not run `driveP6Journey` today (applyPhaseResult only), so a P6 fixture gate does
  not fire in wild runs yet — but the keyed P6 upgrade core is explicitly shared "by liveLayer AND the
  wild" (engine.ts:2620-2672), so a future wild+P6-synthesis path can raise the fixture gate on a gate
  `wildApproveGate` would classifier-approve unless the fixture gate is forceHuman.
- 162 C2 already leans on "LLM-as-judge self-enhancement bias (155-WF S10)" for eval-gated promotion;
  the same bias applies one level down to the per-step Auto-Review classifier, which 162 does not
  currently address.

## 2. Ranked plan-patch additions (fold targets into fixes/162)

Ranking: **P0** = prerequisite for the no-human factory's honesty (land before/with PHASE A);
**P1** = same wave as PHASE C (agent loop); **P2** = parallel with PHASE B/D. Each block is

### 163A-1 [P0 — fold into PHASE A, before A5] Actor-honest approval seam (seat evidence)

- What: every approval surface that may record `decidedBy:"human"` must prove an interactive human
  seat. `HitlDecision` gains `seat: "human-tty" | "human-seat" | "agent"`. CLI verbs `approve` (and
  A5's `fixtures approve`) default to `decidedBy:"autopilot", seat:"agent"` when stdin is not a TTY and
  no explicit human-seat credential (`RT_HUMAN_SEAT` env or interactive challenge) is present; a
  non-human seat may never clear a forceHuman gate even with `--force` (extend the engine.ts:1533
  throw to a typed error). Interactive TTY behavior stays byte-identical to today.
- Why: F1. Today an agent driving the CLI can write a human decision row; A5's "only the human `fixtures
  approve` verb may" inherits the hole. Fixing the seam once makes every current and future approval
  verb (A5, wild resume, forceHuman override) honest for free.
- Where: `scripts/rapidtool-cli.mjs` `case "approve"` (:456-479) + new A5 verb; `src/lib/headless.ts`
  `approve` (:640-652); `src/lib/engine.ts` `approveHitl` (:1515-1606) + types (`HitlDecision`);
  `errors.ts` (register `RT_E_HUMAN_SEAT_REQUIRED`).
- How: pure `seatOf(argv, env, stdinIsTty)` helper; engine refuses human-decided approvals when the
  seat is agent; keep the autopilot path untouched (it already declares itself).
- Done ==: `echo | rapidtool approve --force` on a forceHuman P6 gate exits non-zero with
  `RT_E_HUMAN_SEAT_REQUIRED` and appends NO decision row; an interactive `approve` is byte-identical to
  today; a unit test proves a non-tty caller cannot mint `decidedBy:"human"`.
- Bugs: git-bash/Windows TTY detection quirks (use `process.stdout.isTTY` + env override for CI); script
  tests that pipe stdin must pass the seat env explicitly; never weaken the existing autopilot-forceHuman
  throw.

### 163A-2 [P0 — fold into PHASE A] Wild approval policy = conservative autopilot policy (one shared predicate)

- What: extract the autopilot refusal predicate into one pure engine-side function
  `canSelfApprove(project, gate)` = NOT forceHuman AND NOT stock-HITL-outside-scope AND (M-09 DoD floor
  when the phase ran) AND schedule tightness check — used by store, headless autopilot AND
  `wildApproveGate` (engine.ts:3301). A per-project `wildAutonomyScope` (default: stock HITL excluded)
  can opt P8/P9 into machine approval explicitly, and that grant is recorded in the ledger + the
  autonomy-limit artifact (163A-6).
- Why: F1b. Wild Mode today self-approves the security-policy / UI-contract / deploy gates the sync
  autopilot refuses, contradicting "Do not deploy without HITL on P9" (packet.ts:501) and the P4 prompt
  "do NOT approve as fact" (engine.ts:748-756).
- Where: `src/lib/engine.ts` (new pure predicate + wildApproveGate), `src/lib/headless.ts` :294-307 and
  store.canAutopilot refactor to delegate; `types.ts` (autonomy scope field).
- How: replace the inline forceHuman check (engine.ts:3301) with the shared predicate; pause with
  `wild.paused_human` naming "stock HITL — outside autonomy scope" (RT_E_GATE_PENDING).
- Done ==: a wild run hitting a P4/P8/P9 stock gate pauses (no classifier call) unless the project's
  scope grants it; a parity test runs the same gated project through autopilot and wild and asserts the
  same pause class; the grant, when present, appears in the ledger.
- Bugs: wild-step.test.ts tests asserting P8 classifier self-approval must flip to expect a pause (or
  set the scope); keep keyless/floor runs byte-identical (they raise no classifier anyway); scope field
  hydration for legacy projects.

### 163A-3 [P1 — fold into PHASE C] Classifier falsifiability: separate judge, blind DoD, refutation requirement

- What: (a) judge model must differ from producer (configurable `WILD_CLASSIFIER_MODEL`; default
  deepseek-v4-pro once 162 B3 metering makes cost visible — a flash judge over a pro producer is the
  weakest link); (b) the review prompt no longer prints the DoD verdict before the verdict
  (wild-mode.server.ts:123): ask the judge to predict pass/fail from evidence, then reconcile the
  machine gate after — a predict-then-compare mismatch is logged as an echo flag, never silently
  swallowed; (c) an approve is only accepted when feedback contains an explicit refutation attempt that
  failed ("strongest counter-evidence I checked and why it does not hold"), parsed as a required
  `REPUTATION-CHECK:` section — the mechanical form of Anthropic's "fresh model tries to refute"
  [S2] and OpenHands' verify-agent design [S5]; (d) `isVacuousFeedback` (wild-mode.server.ts:220-239)
  tightened so artifact-title echo alone never counts as substance.
- Why: F2 — the only LLM in today's autonomous loop has no falsifiable duty and every guard is
  satisfiable by self-referential prose; the same bias 162 C2 names for eval-gated promotion applies
  per-step.
- Where: `src/lib/wild-mode.server.ts` (WILD_SYSTEM :69-76, buildWildReviewPrompt :87-133,
  createWildClassifier :245-308), `src/lib/engine.ts` resolveWildReview (:3232-3281).
- How: additive prompt sections + parser changes; engine treats missing refutation section as
  `{ ok:false, reason:"error" }` (same honesty class as the existing short-feedback error).
- Done ==: adversarial unit tests — an approve whose feedback names only artifact titles is an honest
  error (today it passes); the advance prompt contains no pre-printed gate verdict; judge-model const ≠
  producer-model const; a predict/gate mismatch emits a `wild.echo` warn row.
- Bugs: prompt byte-parity pins in wild-mode tests; cost/latency of a pro judge per step (bind to 162 B3
  metering + M8 budget); over-strict parsing must degrade to honest error, never to a guessed approve.

### 163A-4 [P1 — fold into PHASE C] Runaway tripwire: total-run budget + progress tripwire inside wildRun state

- What: extend `Project.wildRun` with `stepsTotal` (default 0, capped at a configurable
  `maxStepsTotal`, default 200), `pausesTotal` (cap 3 per run), `rejectsTotal`, and a no-progress trip:
  when a leave/gate review would re-judge a phase whose recorded `gate.evidenceHash` is unchanged from
  the previous review, wildStep parks with `wild.tripwire_no_progress` (new event + code) instead of
  calling the classifier again. Resume after a tripwire requires either a state change (new
  evidenceHash) or a human seat (163A-1). Optional wall-clock tripwire via an injectable clock
  (`opts.now`), default 2h.
- Why: F3 — per-invocation caps are bypassed by re-invocation; reject→resume churn is unbounded,
  counterless and state-free; the tripwire must live in the persisted run so no driver can re-arm it.
- Where: `types.ts` wildRun; hydration defaults engine.ts:1943-1974; wildStep head (:3527+);
  wildLeavePhase/wildApproveGate reject branches; headless `wildResumeRun` (:2791-2814) + store resume
  path (store.ts:989-1005) + CLI wild verbs (rapidtool-cli.mjs ~1670-1740).
- How: pure `tripwireState(project)` helper; counters incremented in wildPatch; resume refuses when a
  tripwire is set and no state change and no human seat.
- Done ==: a driver re-invoking `wild --start`/`--resume` cannot exceed the total budget or the
  no-progress bound; identical-content re-review after a reject emits `wild.tripwire_no_progress` and
  makes zero classifier calls; ledger rows exist for every trip; legacy persisted runs hydrate with
  default budgets.
- Bugs: a legit 13-phase run needs ~26-40 steps (execute + review + gate approvals) — budget 200 is
  generous but must be per-project configurable; determinism/byte-parity of hydration; tests need the
  injectable clock; don't double-count steps on noop iterations (mirror runUntilGate's honest step rule,
  headless.ts:489-497).

### 163A-5 [P1 — fold into PHASE C] Reject→repair must be a real Reflexion loop: record the rejection, bound the attempts

- What: wild classifier rejects append to the phase record's `rejectionHistory` with
  `{ note, at, source: "autopilot" }` (currently human-only writers, engine.ts:1620-1623) so the review
  prompt's steering (wild-mode.server.ts:102-114) engages and T9's answer block (engine.ts:1302-1308)
  can fire on a genuine re-execution; add `maxRejectsPerPhase` (default 3): the 4th reject parks
  terminal (`wild.reject_terminal`, human seat required), and a re-execution that cannot change the
  evidence (deterministic floor, no keyed repair path) is refused as no-progress by 163A-4 rather than
  re-reviewed.
- Why: F3/F2 — Reflexion steering is dead-letter today (a wild reject never writes the history the
  prompt reads); deterministic re-runs can never satisfy a reject, so an unbounded repair fantasy is
  replaced by an honest bounded one: record → repair (keyed) or park (floor).
- Where: engine.ts wildLeavePhase reject (:3397-3405) + wildApproveGate reject (:3327-3336);
  applyPhaseResult attempt plumbing (:1280-1308) already reads rejectionHistory — no change needed
  there.
- How: shared `recordWildRejection(p, phase, note)`; reject verdicts write history THEN pause; attempts
  counted from history length.
- Done ==: after a wild reject the phase record carries `rejectionHistory[0].source === "autopilot"`;
  the 4th reject parks terminal with RT_E_GATE_PENDING; a keyed re-execution after reject shows the
  rejection note in the next review context and the T9 answer block in the artifact.
- Bugs: byte-parity for keyless runs (no rejects → no history → no delta); avoid double-recording with
  the existing `wild.reject` log row; lesson/memory rows must not duplicate per retry (content-addressed
  ids already dedupe).

### 163A-6 [P2 — fold into PHASE A/B] Honest approval semantics + autonomy-limit disclosure

- What: (a) dod criteria "P4/P5/P8/P9 **HITL approved** — phase record complete" (dod.ts:285/297/418/430)
  become "gate approved (decision row exists; human or in-scope autopilot)" with a probe that requires
  an actual `decisions` row for the phase naming its actor — the criterion can no longer be satisfied by
  a completion with no decision; (b) packet.ts:501's deploy line is qualified ("…without a human-approved
  P9 gate or an explicit recorded autonomy grant"); (c) every wild run start stamps a machine-readable
  "Autonomy limits" docs artifact + ledger row listing exactly what this run may not self-approve:
  forceHuman gates, stock HITL outside the recorded scope (163A-2), A5 fixtures, blocked/rejected
  phases, classifier-unconfigured gates.
- Why: F1/F4, audit Q4 — the "HITL approved" surface is the semantic fabrication; the factory needs an
  honest, machine-readable autonomy-limit disclosure before the first autonomous step.
- Where: `src/lib/dod.ts` criteria/probes; `src/lib/packet.ts` :501 and the P9 narrative;
  headless `wildStartRun` (:2727+) + store.startWildRun (:1011+) stamping; `types.ts`.
- How: additive probe change with a legacy tolerance (see Bugs); disclosure block rendered by a pure
  `autonomyLimits(project)` helper shared by start paths and the console B7 pane.
- Done ==: a keyed wild run emits the autonomy-limit artifact before its first step; the packet of a
  machine-approved P9 contains no unqualified human-approval claim; the dod probe fails on a phase whose
  record is complete but whose decisions ledger has no row.
- Bugs: legacy projects whose phases are complete with the old "HITL approved" string and no decision
  row — tolerance rule: if the project predates the change (no autonomy field) and the phase record is
  complete, keep pass but stamp an advisory "legacy approval semantics" note; tests pinning criterion
  strings (dod.test.ts, fixture JSON) must be updated in the same change; probe must read decisions,
  never re-derive from artifacts (162's no-second-driftable-probe rule).

### 163A-7 [P2 — fold into PHASE A, with A5] Reconcile self-approval with the human fixture gate

- What: the A5 fixture gate is forceHuman by construction: `fixtures approve|reject` is human-seat-only
  (163A-1), the fixture `approval:"approved"` flip is the only writer, and dod's `p6-verified`
  (dod.ts:337-355) keys on approved fixtures. `canSelfApprove` (163A-2) returns false for any P6 state
  carrying pending fixtures, so the wild loop parks human (RT_E_GATE_PENDING) at the one gate that must
  stay external — exactly the 162 §3 "never auto-approve a fixture" line made mechanical.
- Why: F5 — the external oracle is the keystone of 162 PHASE A; if the machine can approve its own
  fixtures, the oracle is the producer and 162's whole honest bar (162:14-30) collapses.
- Where: A5 additions (rapidtool-cli.mjs fixtures verb, store `approveAcceptanceFixtures`,
  brief-fixtures.ts emit guard `fixtureOk`, dod.ts p6-verified), engine.ts wildApproveGate via the
  shared predicate.
- How: fixture gate raise sites set `forceHuman: true` (mirroring engine.ts:626-633); predicate order:
