1. **T's D5 gates any flip on next-run evidence** (fixes/154_direction.md §3 D5): "on the next keyed run read the attempt journal + refusal notes BEFORE tuning further; if the notes say 'reasoning only (N chars…)' or refusals persist at 32k, the fix is to disable thinking for json envelopes … rather than to keep raising budgets." 3. **W's honest negative + Mechanism B/D**: no vendor doc states an explicit thinking×json_object conflict for v4; DeepSeek's own JSON-mode guide vendor-acknowledges "the API may occasionally return empty content" with *prompt mitigation* as the suggested lever [S1], and SkillClaw #70 [S11] shows proxies/relays can produce byte-identical `content:""` + `finish_reason:"length"` symptoms on direct-working calls. A thinking-off flip fixes neither B nor D; the discriminator (finish_reason length vs stop + reasoning chars + direct-call repro) is exactly what the diagnostics F3 just pinned now capture.
