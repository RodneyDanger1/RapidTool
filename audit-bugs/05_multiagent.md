## 1. Bug register

### M-01 — P7 competitor rows are bulk-promoted to `source:"cited"` with zero per-row evidence; the UI hides the label entirely — P1 (honesty contract) `[follow-up]`
- **file:line:** `src/lib/engine.ts:1309` (`if (real.cited) competitors = done.competitors.map((c) => ({ ...c, source: "cited" as const }))`), duplicated at `src/lib/headless.ts:174`. The rows themselves are hardcoded template objects — `marketFor` at `engine.ts:41-68` (comment at `:66`: "Deterministic template rows — never present as live research (B-23)") — and their `strength`/`gap` prose is authored, not derived from the research items.
- **Verified:** at P7, `synthesizePhase` (case 7, `engine.ts:528-552`) writes artifact **"Competitive analysis matrix"** whose body **explicitly warns** "Illustrative competitor templates (source: illustrative — NOT live research)" (`engine.ts:539`), while the same phase sets `project.competitors` (the field DoD counts and the console renders) to `source:"cited"` whenever **any** ≥1 research item returned — even though the research items (fetched at `engine.ts:1250-1258`) are never matched to rows. So the packet/JSON sidecar carries rows labeled verified whose text is fabricated template prose; a research finding about, say, ServiceTitan would promote *all* rows (Cursor, v0, Housecall Pro…) to "cited". `fixes/07_llm_integration.md:18` shows the promotion-by-real-findings behavior was *deliberate* — the bug is that promotion never validates row content, which contradicts the field's own comment at `types.ts:63-64` ("`cited` reserved for real research phases").
- **Worse, the label is invisible:** the scorecard competitor table (`console.tsx:1570-1591`) renders name/class/gap only — `c.source` is never displayed (`console.tsx:1581-1587`), so an operator cannot tell a verified row from a template row even in the UI that shows the table.
- **Why it matters:** the honesty contract is RapidTool's core differentiator (`AGENT_GUIDE.md:9-13`). A downstream agent that reads `project.competitors` from the exported JSON (or parses the DoD-visible data) inherits invented "cited" intelligence. DoD P7 passes on the template alone: `p7-competitors` only counts rows (`dod.ts:128-131`) and `p7-research` only checks a `research` artifact exists (`dod.ts:133-136`) — which the deterministic template matrix artifact (`engine.ts:534`, kind `"research"`) satisfies with **zero** live research.
- **PROPOSED FIX:** (1) never mutate the source of template rows — instead add a separate `project.research` corpus of real findings (title/url/content per item) and render *that* as the P7 evidence, keeping `competitors` labeled `illustrative`; or (2) map each promoted row to the exact findings that support it (per-row `evidence: url[]`), promoting only rows with support. (3) Show a `source`/evidence column in the scorecard table (`console.tsx:1570-1591`). (4) Tighten DoD: `p7-research` should require a *cited* research artifact (or ≥1 finding with URL) and `p7-competitors` should count cited rows when live research is configured.

### M-02 — UI research only ever fires when the **LLM** key is set; the green "research · free search" chip is thus a lie — P2 (wiring) `[NEW]`
- **file:line:** `src/lib/store.ts:395` (`const configured = get().llmStatus.configured;`) and `:406` — the store gates the **entire** async engine (research + narrative) on `llmStatus.configured` via `advanceOnceAsync → runReadyAsync → synthesizeAsync` (`store.ts:265-296`, `243-262`, and the `if (configured)` at `:226-241`). But `llmStatus.configured` means *DeepSeek key present* (`llm.ts:37-42` → `deepseek.server.ts:59-61`), while the research sub-path inside `runPhaseAsync` is **keyless-capable**: `fetchResearch` calls `research()` unconditionally (`engine.ts:1250-1258`), which falls back to free DuckDuckGo/SearXNG/Wikipedia when Tavily is unset (`research.ts:29-38` → `websearch.server.ts:300-357`).
- **Verified:** `researchStatus()` reports `configured: true` on any live server even with no key at all (`research.ts:40-47`, label `"free search"`); the console renders that as a green chip `research · free search` (`console.tsx:827-831`, tone `ok` at `:829`). Net effect: a Tavily-only or keyless deployment shows "research ready" but every P0/P7/P11 run silently takes the deterministic path, because `runPhaseAsync` is never invoked (`store.ts:240`). The headless driver has no such gate (`headless.ts:110-118` runs research whenever `live:true`), so the two drivers disagree on when research happens.
- **Why it matters:** the headline "live research" upgrade (`AGENT_GUIDE.md:78-79`) is unreachable from the UI without the *unrelated* DeepSeek key; users configure Tavily, see a green chip, and get illustrative artifacts with no warning.
- **PROPOSED FIX:** split the gate — `synthesizeAsync(project, phase, { llm, research })` where `research = researchStatus.configured` (server side always true for the keyless path when reachable); call `runPhaseAsync` when *either* is configured (it already degrades per-subsystem: `engine.ts:1244-1284`). At minimum, make the chip reflect the actual gate (`store.ts:395`), i.e. "research only when LLM key set".

### M-03 — Real P6 execution is a manual side-channel that never updates `lastTest`, the DoD, or the gate — P2 (verification loop) `[NEW]`
- **file:line:** `runModuleReal` (`store.ts:452-488`) appends a "Real module run (bounded)" `docs` artifact + `runner.real` log only (`store.ts:473-480`); it never touches `lastTest`, `generatedSource`, `hitl`, or phase status. `runP6Real` (`engine.ts:1358-1373`) returns `{ok:true, result}` for **every** runner outcome except `not-configured` (`engine.ts:1366-1369`) — its `ok` means "runner ran", not "module passed" — so a real-run failure is only visible in one doc artifact. The UI exposes it as an optional button (`console.tsx:970-979` → `onRunModule` at `:613-627`).
- **Meanwhile the DoD and the packet keep reporting the *template self-test*:** DoD `p6-test` probes `p.lastTest.ok` (`dod.ts:111-114`); the packet prints `P6 sandbox (last run): …` from `lastTest` (`packet.ts:191`); `lastTest` is only ever set by `runGenerated`'s bounded template runner in `synthesizePhase` case 6 (`engine.ts:471-481`, runner at `sandbox.ts:71-97` with the shape gate `:81-83` that **rejects non-template source**). Two verifiers exist and never converge: the template self-test (which the DoD trusts) and the real bounded run (which nothing trusts).
- **Why it matters:** review/03 §2.2 already named the "sandbox-pass = code-exists illusion". Code-level: even the *real* runner executes only the engine-authored template module (`runP6Real` runs `project.generatedSource`, `engine.ts:1361-1364`, which is `buildPhase6Module` output, `sandbox.ts:119-155`) — never agent-written code — so neither verifier says anything about the actual build. There is no path where an agent's real output is executed and its result feeds a gate.
- **PROPOSED FIX:** make `runP6Real` converge into the gate: on real-run completion, update `lastTest = {ok: exitCode===0, detail: stdout/stderr head}` (store/engine seam at `store.ts:452-488`), re-run DoD `p6-test`, and open a `forceHuman` HITL on failure — mirroring the template path (`engine.ts:482-524`). Add an agent-facing "run my tests" primitive (see `research/multiagent/02` E1).

### M-04 — No executable oracle: A7 rows are prose, and nothing in the product can run a test against built code — P2 (core gap) `[NEW]`
- **file:line:** `buildTestOracle` emits `{id,name,given,expect}` string rows only (`algorithms.ts:438-463`); the spec graph's `tests` node is a *target file description* ("Acceptance tests from the oracle", `algorithms.ts:365-371`), not a generator; the packet renders them as bullet prose (`packet.ts:181-182`). No module imports `runSandboxed` (`sandbox.ts:242-324` — verified by grep: only `sandbox.test.ts` exercises it) and `runGenerated` refuses non-template source (`sandbox.ts:81-83`). The only "test" executions in the entire repo are (a) the P6 template self-test (`engine.ts:471-481`) and (b) the optional manual real-run of that same template (M-03). Agent-returned test evidence is free text in report artifacts (`report-intake.ts:20-26` — schema has no test field).
- **Verified:** `grep -rn "runSandboxed" src/ --include=*.ts` → matches only `sandbox.ts` itself and `sandbox.test.ts`. `grep -rn "oracle" src/lib/*.ts` → oracle is produced (`algorithms.ts`), embedded in the packet (`packet.ts:181-182`), shown in the console Oracle tab (`console.tsx:1342-1353`), and counted as HITL-dock "evidence" (`console.tsx:88-97`) — never executed anywhere.
- **Why it matters:** the entire "tested code" claim (P6 title "Code Generation, Testing & Deployment", `phases.ts:54-59`) rests on a canned module test. There is no fail-to-pass (test written before code) mechanism, no test-runner command for agent output, no result type — the exact loop industry guidance centers on (Anthropic verification-driven dev; TDD-Bench F→PF tests; see `research/multiagent/02` §B).
- **PROPOSED FIX:** see `research/multiagent/02` E1 (executable oracle + F2P harness over `exec.ts`/`node-runner.server.ts` + a `TestResult` schema threaded into `lastTest`/DoD). Minimum viable: a `runAgentTests(project, {command, cwd})` server seam and an `OracleTest`-to-runnable-template emitter.

### M-05 — Agent report intake is self-declared and phase-unchecked: "complete" carries zero evidence, wrong-phase reports are accepted, and a "blocked" report's note is half-wired — P2 `[NEW]`
- **file:line:** `AgentReport` shape (`report-intake.ts:20-26`) has `status/summary/artifacts/files` only — no `tests_run`, no `evidence`, no per-file contract mapping. `validateReport` checks phase ∈ 0..12 (`:46-49`) but **not** that `phase` equals the current edge; `applyReport` (`:103-148`) never re-runs DoD or touches `gate`/phase status (by design — store owns advancement, comment `:13-16`), so a report claiming `status:"complete"` with zero files, zero artifacts, and no test output is accepted and recorded (`store.ts:493-501`, `console.tsx:629-646`).
- **Blocked-report half-wiring:** a `blocked` report writes only `rejectionNote` (`report-intake.ts:138-140`) and never appends `rejectionHistory` (which only `rejectHitl` does, `engine.ts:973`). Consequence: regeneration attempt stays 0 (`engine.ts:767` `attempt = rec?.rejectionHistory?.length ?? 0`), so (a) text phases never get the visible "Rejection response" block (guarded by `attempt >= 1`, `engine.ts:789`) and (b) the packet's loop metadata — `rejection_loop` in System JSON (`packet.ts:43-46`) and the `## Rejection loop` section (`packet.ts:196-201`) — stays silent even though the operator pasted a rejection-quality note. P6 does consume `rejectionNote` for its variant (`engine.ts:469-470`) but with attempt 0 the variant flip is hash-only, so two different blocked notes can produce identical output.
- **Why it matters:** this is the "close the loop" surface (`AGENT_GUIDE.md:64-74`); as built, the loop trusts the agent's self-report and gives the human no machine-checked signal.
- **PROPOSED FIX:** (1) extend `AgentReport` with optional `tests_run: {command, pass, evidence}[]` and `phase` must equal `project.currentPhase` (else validate-error). (2) On `status:"complete"` where the phase DoD probes reference test evidence, surface a `warn` log when no tests_run is supplied. (3) Make `applyReport` for `blocked` also append a `rejectionHistory` entry (or introduce a separate "blocked" history that `unlockRetry` converts) so attempt counting and loop metadata stay truthful.

### M-06 — Research grounding ages out of the agent packet — P3 (grounding lifecycle) `[NEW]`
- **file:line:** the packet embeds at most the **last 8** non-packet artifacts at **900 chars** each (`packet.ts:80-87`) and hard-truncates the whole document at 14k chars with a visible marker (`packet.ts:242-244`). Live research findings are ordinary `research` artifacts (`engine.ts:1302-1304`, `headless.ts:149-156`) — so by P8+, when the agent actually writes code, the P0/P7 citations (title + URL + content) have almost certainly slid out of the slice (each phase adds ≥1 artifact; `applyPhaseResult` keeps prior-phase artifacts, `engine.ts:815-818`). The `Project` type has **no** dedicated research corpus field (`types.ts:193-232`) — research exists only as artifact bodies, so citations are structurally evictable.
- **Verified:** export JSON retains full artifacts (`io.ts:25-27`), so nothing is lost on disk — only the paste-ready packet (the artifact the guide tells the agent to consume, `AGENT_GUIDE.md:22-25,37-39`) loses the sources exactly when the build begins.
- **PROPOSED FIX:** persist research separately (`project.research: {query, provider, items[{title,url,content}]}[]`, appended by `runPhaseAsync`/`liveLayer`) and have the packet emit a compact `## Research sources (live)` block of URLs + one-line summaries regardless of the artifact cap. Fold into E3 (`research/multiagent/02`).

### M-07 — LLM narratives are stored as engine-looking artifacts with no "unverified" marker, and can be pure invention when research is empty — P3 (honesty surface) `[NEW]`
- **file:line:** when no research items return, the narrative prompt explicitly invites the model to "reason from the brief and lattice only" (`engine.ts:1271`); the result is stored as artifact **"Phase narrative (LLM)"** (`engine.ts:1306` for research phases; `:1319` kind `docs` for every other phase) with **no** unverified footer — unlike agent reports, which carry `> external report — unverified by engine` (`report-intake.ts:37`) — and no provenance hash of the source items used.
- **Verified:** the grounded-vs-ungrounded distinction exists only inside the prompt (`engine.ts:1265-1271`); nothing records which case occurred. The narrative artifacts then flow into the packet's artifact window (`packet.ts:80-87`) and the console artifact pane (`console.tsx:1739-1754`) indistinguishable from deterministic content except by title.
- **Why it matters:** a second agent consuming the packet mid-build can quote invented "phase narrative" claims (library names, constraints, market facts) as if they were grounded — the exact hallucination vector this product exists to prevent.
- **PROPOSED FIX:** append an honesty footer to every LLM narrative artifact ("generated prose — not grounded in fetched sources" when `items.length === 0`; "grounded in N fetched sources (see research artifacts)" otherwise), and record `{grounded: boolean, sources: url[]}` in the artifact body or a companion log line.

### M-08 — No agent-memory write-back: "memory" and "Self-Learning" are engine-only fiction — P3 `[NEW]`
- **file:line:** memory rows are created **only** inside the engine — `synthesizePhase` per-phase rows (`engine.ts:237-247` etc.), `bootstrapMemory` (`algorithms.ts:532-556`), override/reject rows (`engine.ts:922-932`, `1005-1014`) — and the list is capped/deduped at 80 (`engine.ts:819`). `applyReport` (`report-intake.ts:142-147`) writes artifacts/logs but **no memory row**; `ingestReport` (`store.ts:493-501`) likewise. The packet's "## Ranked memory (A2 FusionRank)" section (`packet.ts:203-206`) therefore never contains a lesson learned from any prior agent build — yet P5 is titled "Validation, HITL & **Self-Learning**" (`phases.ts:47-51`) and P2 promises "Durable checkpoints, hierarchical memory… cross-encoder re-rank" (`phases.ts:24-27`, artifact text `engine.ts:354-365`) which are descriptive, not implemented loops.
- **Why it matters:** cross-run learning (the "memory" selling point and the reason memory appears in the packet at all) is dead — the only writes are deterministic boilerplate. An approved agent report is the natural memory candidate and is dropped on the floor.
- **PROPOSED FIX:** on `applyReport` with `status:"complete"`, append one semantic memory row `{text: summary truncated, score: 0.7}` and one episodic row per artifact; cap via the existing dedupe/slice (`engine.ts:819`). Fold into E4 (`research/multiagent/02`).

### M-09 — DoD gates are advisory *and* recorded post-hoc, so autopilot can approve work that fails its own exit criteria — P3 (enforcement gap) `[NEW]`
- **file:line:** `canAutopilot` (`store.ts:126-132`; mirrored `headless.ts:203-208`) checks only `forceHuman`, stock-HITL membership, and tightness — never the phase's DoD probes. Gates are recorded **after** a phase is already `complete`: `recordGate` requires `rec.status === "complete"` (`store.ts:85`), i.e. it *reports* rather than *checks*; `runGate`'s other callers are `recordGateInline` on approval (`engine.ts:847-868, 957`) and the handoff builder (`handoff.ts:28`). Nothing anywhere consults `runGate(...).pass` to block a transition or an approval (grep: `runGate(` appears at `engine.ts:850`, `store.ts:86`, `handoff.ts:28` only).
- **Verified:** the advisory posture is explicit and intentional (`dod.ts:1-14` header; `AGENT_GUIDE.md:13`), and for a *human* operator that is a defensible product choice — but the autopilot path exists (`store.ts:147-148, 206-208, 278-279`) and is precisely where machine enforcement matters most: an autopilot that approves P9 with a recorded-but-ignored `gate.passed:false` produces a "CI/CD complete" phase whose DoD artifact is self-contradictory.
- **PROPOSED FIX:** leave human gates advisory, but in `canAutopilot` require `runGate(project, hitl.phase).pass` (or the just-synthesized phase's criteria) before an autopilot approval; log `autopilot.gate_denied` when unmet. See E4 (`research/multiagent/02`).

### M-10 — Live-research layer is duplicated engine↔headless and has already drifted — P3 (maintainability/consistency) `[NEW]`
- **file:line:** `headless.liveLayer` (`headless.ts:101-177`) reimplements `engine.fetchResearch` + the `runPhaseAsync` layering (`engine.ts:1241-1284, 1293-1350`): duplicated query builder (`headless.ts:89-93` vs `engine.ts:1225-1229`), duplicated competitor relabel (`headless.ts:174` vs `engine.ts:1309` — the M-01 bug exists in **both** copies), duplicated artifact construction (`headless.ts:149-168` vs `engine.ts:1302-1308`), and duplicated narrative prompt (`headless.ts:135-137` vs `engine.ts:1272-1274`).
- **Why it matters:** M-01 and any future research fix must be applied twice or the drivers silently disagree (they already disagree on gating — see M-02, where only the headless path runs keyless research).
- **PROPOSED FIX:** export the research layering from `engine.ts` (e.g. `liveLayer(project, phase)` built on `fetchResearch`) and have `headless.liveLayer` call it; delete the headless copy. Headless-only concern: `headless.ts` runs under bare Node with no server functions, so `engine.ts`'s `research()`/`complete()` imports (TanStack server fns, `llm.ts:25-35`) must stay injectable — thread a `liveBackend` object through `runPhase` (`headless.ts:182-194`) instead of importing `.server` modules directly (`headless.ts:111-112, 126`).

### M-11 — Packet/DoD terminology calls the template self-test a "sandbox" — P4 (wording drift, agent-facing) `[NEW]`
- **file:line:** `packet.ts:191` renders `P6 sandbox (last run): pass|FAIL` and DoD criterion `p6-test` is "Last **sandbox** test run passed" (`dod.ts:111-113`) — but the executor is `runGenerated`, whose own honesty label is "Engine-template runner (bounded, engine-authored code only)" (`sandbox.ts:166`, `sandboxClaim` `:158-167`) and whose sandbox claim is also what the packet's `Execution:` line prints (`packet.ts:188`). No `runSandboxed` worker execution exists in any product flow (M-04).
- **Why it matters:** a consuming agent that sees "P6 sandbox: pass" and "Execution: engine-template runner" in the same document must reconcile the contradiction; the DoD name actively strengthens the review/03 "sandbox-pass = code-exists illusion" failure mode.
- **PROPOSED FIX:** rename the agent-facing strings to "P6 template self-test" in `packet.ts:191` and `dod.ts:111-113` (and the `p6-test` id), reserving "sandbox" for actual `runSandboxed` executions.

### M-12 — `interpretFeedback` (LLM) and the deterministic rejection-response block can steer in different directions; guidance lands while the project is `blocked` with no dock — P4 `[NEW]`
- **file:line:** `rejectAsync` (`store.ts:611-642`) appends a "Rejection guidance (LLM)" `docs` artifact (`:631`) after `reject` has set status `blocked` (`engine.ts:993`) with `hitl: null`; the guidance is only surfaced as an artifact in the artifacts tab. Meanwhile the deterministic engine appends its own keyword-matched "Rejection response" deltas on regeneration (`engine.ts:787-795` via `rejectionResponseBlock` `:167-171`). Both steer; nothing reconciles them, and the LLM guidance may even suggest what the deterministic delta ignores.
- **PROPOSED FIX:** P4-level note for now — either render guidance in the blocked-state UI (HITL dock is null when blocked, `console.tsx:1611-1613`) or tag guidance artifacts so the next handoff/packet can cite "LLM guidance vs. deterministic deltas" explicitly.

## 2. What this register means for the fix wave

The P1/P2 set (M-01..M-05) are all on the **agent-facing correctness loop**: honest sourcing (M-01), research actually firing (M-02), real execution converging with gates (M-03), an executable oracle (M-04), and evidence-carrying report intake (M-05). None require new external services — each is a wiring/schema change over the existing honest runner (`node-runner.server.ts`), server-fn boundaries (`llm.ts`/`research.ts`), DoD registry (`dod.ts`), and report envelope (`report-intake.ts`). Ranked enhancement proposals built on this register live in `research/multiagent/02_capability_audit.md` §C.
